# 战斗特效分层调整方案（2026-10-23）

状态：已按本方案实施，并完成身体状态、真实地面遮挡及喷火拆分的后台 GPU 复核。当前规则见[层级核对清单](combat_effect_layers_20261023.md)，测试范围与限制见[实施记录](combat_effect_layer_validation_20261023.md)。下文保留设计依据，表中的“当前”指迁移前数值，“建议”已成为最终有效 Z，不是旧 `set_effect_layer()` 的参数。

## 推荐规则

1. 地面痕迹、范围底色在草上、角色下；危险预警高于普通地面装饰，但不盖住角色身体。
2. 持续身体状态覆盖所属怪物，随所属怪物一起参与脚底排序。前方玩家或怪物应能遮住后方怪物及其火焰、冰壳。
3. 小型快速攻击和短暂命中反馈优先保证可见，可放在身体前景；大型持续效果拆分背景体积与前景亮边，避免长时间遮住操作主体。
4. 信息图标、数字与身体状态分开。身体状态不应因为与图标共用节点而被整体抬到全局前景。

同层“覆盖所属身体”的实现依赖角色组内部绘制顺序，不是把节点重新设为 0 就结束：角色及其局部状态共同参与外层 Y 排序，组内部不单独 Y 排序，先画背面装饰，再画 Sprite，最后画正面状态。同组的图集辅助节点不得再跳到绝对前景。玩家与另一只怪物从前后穿行时必须验证实际遮挡。

## 具体代码改法

### 1. 先建立明确的层级入口

在 `scripts/effects/combat_render_world.gd` 中增加具名的最终层级常量与接口，例如地面、预警、身体后侧、快速攻击、光束、命中、反应、信息。现有 `set_effect_layer()` 暂留给地面及未迁移路径；新增接口直接设置最终 Z，避免把建议值 +28 传进旧函数后实际得到 -100。

角色局部状态使用另一条入口：设置相对 Z 0，并挂入所属角色的局部状态组；不能使用绝对层级接口模拟“只高于所属怪物”。

### 2. 身体状态与火焰批次

- `enemy_status_visual.gd`：将当前同时承载图标和冰壳的 +25 根拆分为身体状态组与 +64 图标组。脚底霜花继续使用绝对地面层。保留身体锚点、状态时间与当前图集。
- `pixel_fire_visual.gd`：为 `setup_status()` 增加角色局部绘制模式，使用一个局部 MultiMeshInstance2D（单火舌实例），继续使用现有 `INSTANCE_CUSTOM`、共享材质和时钟。该实例不再提交到 FlameClock 的全场合并批次，以免重复绘制；只更新时间、局部姿态和配色。地块火与飞行火种仍可保留批次路径，火种改到快速攻击层。
- `enemy_super_armor_visual.gd`：描边进入角色局部组，文字进入信息层。`lightning_status_visual.gd`、`debt_target_marker.gd` 的头顶提示归到信息层。
- `player_controller.gd`、`revive_angel_wings.gd`：翅膀进入玩家参与排序的视觉组，在身体之前画，维持复活动画行为。

局部状态节点会增加绘制提交数，这是保留角色间正确遮挡的成本。应复用所有素材与时钟，只为有状态的怪物启用绘制，并用密集燃烧场景测量；不能声称改成局部节点后仍只有原来的全场单批次。

### 3. 冻结、解冻、蒸汽与导电

- `element_reaction_visual.gd::spawn()`：用反应类型显式选择层级，冻结/解冻 +28、蒸汽 +16、冰面扩散/湿润传播保留地面。导电如有目标则进入其局部状态组。
- `reaction_block_visual.gd::draw_thaw()`：删除绘制时调用旧 `set_effect_layer(canvas, 83)` 的行为。层级在创建/切换阶段确定，绘制函数只绘图，否则生成阶段设好的前景值会被覆盖。
- `element_reaction_resolver.gd`：提供导电局部状态所需的所属目标；保持现有反应、伤害、状态与音频路径。`enemy_controller.gd` 的解冻时序不变。

### 4. 混合效果必须按可见部分拆分

- `mobility_atlas_effect.gd`：地圈、锚点、尘土保持地面；拖尾 -4；离开/到达/返回的短时亮部 +24；霰弹命中 +24。保留键盘/鼠标施法和原始动画时长。
- `directed_weapon_runtime.gd`、各投射物/武器脚本：小型弹道与攻击主体 +8；派生武器的地面子节点继续绝对地面层。等离子球为持续实体，需使用独立视觉代理覆盖通用投射物的默认策略。
- `light_sword_effect.gd`、`electric_spark_effect.gd`、`lightning_particle_effect.gd`：空中剑体、雷电主体与地面范围分别设层；不能提升整个父节点后让默认相对子节点一起升高。
- `black_hole_effect.gd`：现有球体和两组漩涡移入按落地点排序的视觉组，内部保持前后顺序；吸引与伤害逻辑留在原逻辑对象。
- `copper_lamp_flame.gd`、`underworld_wolf_flame.gd` 及对应 Shader：加入互补的背景/前景绘制选择，检查同一部分不被重复叠加；小范围手炮喷焰可归短时前景反馈。
- `reaction_block_visual.gd`、`enchantment_block_vfx.gd`、手雷与武器块状绘制：短暂爆心归前景，地面冲击波归地面。若 PNG 或 Shader 把两者烘在一起，先分离可见部分再改层级，不能只移动整个节点。
- `elite_rusher.gd`：独立预警节点；`echo_bat.gd`、`underworld_wolf.gd` 和玩家指示器统一预警层。保留预警尺寸和持续时间。

### 5. 共享粒子按用途拆批次

`particle_world.gd` 目前只有一个统一 Z 的绘制批次，不能整体提高。建议在粒子 profile 中增加渲染用途（地面、拖尾、命中），渲染按用途建立少量批次；`particle_event.gd` 仅在需要逐事件覆盖时透传枚举值。地面碎屑留低层，快速弹道拖尾归 +8，命中火花归 +24。

沿用一个模拟池、原有粒子总预算、随机数调用与生成时序，只改变渲染分组，避免把每层扩成一个完整模拟池。粒子落地也不能仅凭寿命切层，只有已有实际地面阶段的数据才能触发；纯装饰短粒子可按所属用途保持到消失。

## 实施与验收顺序

1. 身上燃烧、冰壳局部排序、冻结/解冻前景及图标拆分。先解决已经明确的状态显示问题。
2. 快速弹道、闪电、光辉剑、闪现与命中反馈；同步共享粒子分组。
3. 大面积喷火、黑洞持续实体、敌人预警统一及相关视觉拆分。

每批先执行 Godot headless 编译和对应运行验证，再通过私有桌面截图检查：草簇遮挡、单怪状态覆盖、两怪/玩家前后交错、冻结转解冻、密集燃烧与雷火、技能预警叠加。截图期间不抢焦点。数值断言之外必须检查实际不透明像素，尤其角色局部同层排序。

已更新 `combat_effect_depth_test.gd` 的旧“所有攻击都低于怪物”断言，新增 `combat_layer_semantics_test.gd` 覆盖局部状态遮挡、角色交错及喷火互补，新增 `combat_layer_visual_review.gd` 复核正式素材。状态/冰水/火焰相关测试同步调整。导电沿用现有 `follow` 目标，无需改动反应结算器；手雷爆炸图集经查看只有爆点与碎片，落点标记和地面投影在独立节点绘制。性能记录区分 CPU 提交耗时与完整帧时间，不能用前者替代后者。
