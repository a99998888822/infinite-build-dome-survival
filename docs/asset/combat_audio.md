# 战斗音效第一版

当前使用 23 类声音、23 个 WAV 文件，约 0.93 MB，每类只保留一个正式音效。音频由程序原创合成，不使用外部采样。源文件统一为 48 kHz、16-bit PCM、单声道、无循环，峰值保留 5 dB 余量，首尾淡入淡出。Godot 导入采用项目默认压缩设置。

根据试听反馈，原来差异过小的 12 个变体及其导入文件已移至项目外 `D:/project/useless/resources/combat-audio-review/archive/variants_v1/`。保留的 `_01.wav` 与已确认版本逐字节一致，运行时继续使用原有的小幅音高随机变化；蓄能音高固定，以保持阶段时序。

## 原有缺口

- 木质弓箭（历史 ID 为 `weapon_void_blade`）的 `hit_sfx` 指向不存在的 OGG；电浆炮也使用这个缺失路径。
- 基础附魔仅闪电、电火花接入声音；其他附魔、联动缺少专用反馈。
- 电火花原先在命中时立即播放雷声，实际落雷约在 0.5 秒后。
- 原附魔音效仅做同帧去重，缺少跨帧冷却；通用音效池轮转会覆盖尚在播放的声音。

原版 `lighting_1.wav`、`lighting_2.wav`、`thunder_1.wav` 保留在 `assets/audio/sfx/effects/`，当前战斗改用 `assets/audio/sfx/combat/`。

| 用途 | 音色 | 播放位置 |

| 电浆接触，1 个 | 低频电流与短促灼击 | 每批接触伤害一次，不按敌人数叠加 |

| 火焰、爆炸、水、冰、风，各 1 个 | 引燃、短爆破、泼溅、结晶、切风 | 引燃／引爆／生成接触特效；持续伤害不重复播放 |

分裂、穿透、连锁强化继续使用武器和元素的命中反馈，不另加一层重复提示声。雷火引爆只播放组合音，不再叠加普通爆炸声。

## 同次命中的联动声音替换

普通附魔与联动按一次命中收集后决定播放内容。联动发生时，取消参与反应的普通附魔音，保留联动音，武器命中声额外降低 5 dB。没有发生联动的普通命中保持原音量；未参与联动的其他附魔继续播放。原 WAV 文件不变。

| 联动 | 取消的同次命中音效 |
| --- | --- |
| 蒸汽 | 水流、火焰 |
| 冻结 | 水流、寒冰 |
| 神圣火焰 | 光辉剑、火焰 |
| 暗焰 | 黑洞、火焰 |
| 光暗湮灭 | 光辉剑、黑洞 |
| 导电 | 水流、闪电、普通落雷 |
| 雷火引爆 | 火焰、闪电、普通落雷、普通爆炸 |
| 湿润扩散 | 风刃、水流 |
| 霜线推进 | 风刃、寒冰 |
| 光冰反射 | 光辉剑、水流、寒冰，以及同次触发的冻结前奏 |

不同投射物的命中分别处理，即使发生在同一帧也不会相互取消声音。同一次范围命中会合并重复反馈；电浆每批接触伤害使用一个声音批次。若同次命中实际发生多个独立联动，仍可保留各联动反馈，继续受全局冷却和声部上限控制。

首段连锁、黑洞启动及引爆保留来源关联。后续连锁跳跃和电火花落雷按新阶段处理：蓄能照常播放，湿润目标受到落雷时用导电音替代普通落雷音；不会删除半秒前已经发生的水流声。雷火和暗焰的火种晚些落地时，仍沿用原命中的替换决定，避免重新补播普通火声。

播放选择最多等待一个渲染帧，以收齐同次命中的延迟回调；伤害、状态和特效执行不等待音频。联动音因冷却被省略时，不恢复已被替换的基础音。暂停会清空尚未播放的请求。

规则表在 `scripts/audio/combat_audio_impact.gd`，收集与播放在 `autoloads/audio_manager.gd`。最多暂存 256 个命中批次，维持原有声音并发上限。

## 实战混音

- `CombatSFX` 独立总线送入原 `SFX` 总线，继续使用设置页的音效音量。
- 12 个独立战斗声部，不占用 UI 音效池；保留 4 个声部给命中、落地与主要反应。
- 60 ms 内最多启动 3 个普通细节声与 3 个重要反馈声。每类另有 65–550 ms 冷却和 1–3 个声部限制。
- 满载时丢弃多余请求，不抢占已播放声部、不积压待播放队列。
- 战斗总线压缩器控制密集叠加，限制器上限 -2 dB。此上限不代表 BGM 与所有总线相加后的主输出上限。
- 战斗暂停后停止短音尾巴，关闭面板后不回放旧声音；UI 音频仍按原逻辑播放。
- 每类使用同一文件，播放时保留小幅音高浮动，使用独立随机数生成器，不影响玩法随机数。

## 文件维护与试听

- WAV：`assets/audio/sfx/combat/`。
- 声音配方、音量、冷却、变体数：`scripts/tools/build_combat_audio.py` 中的 `SPECS` 和合成函数。
- 自动生成的 Godot 目录：`scripts/audio/combat_sound_library.gd`，通过预加载确保导出包含音频。
- 播放入口与混音限制：`autoloads/audio_manager.gd`。
- 调整音色时直接编辑 WAV 也可生效；重新运行生成器会覆盖本音效包的 WAV，手动修改的版本请先另存。

生成全部素材与离线试听页：

```powershell
python scripts/tools/build_combat_audio.py --review-dir D:/project/useless/resources/combat-audio-review
```

试听页为 `combat_audio_review.html`，音频全部内嵌，双击即可使用，不依赖本地 HTTP 服务。包含 23 个正式素材、3 个原版电音、蓄能落雷组合及连续交战合成示意，每类只展示一个播放器。单项使用素材原始音量；组合使用游戏配置增益，不含 BGM，也不是实机录音或等响度盲测。

## 验证

- `scenes/tests/combat_audio_test.tscn`：单素材导入、去重、音高浮动、总线、声部上限、暂停、真实落雷／落剑时序、电浆伤害独立于声音冷却、元素反应派发。
- `scenes/tests/combat_audio_reaction_test.tscn`：真实投射物命中、跨目标隔离、参与元素替换、武器降音量、延迟引爆／火种、连锁、蓄能落雷分阶段、暂停丢弃及伤害即时性。
- `scenes/tests/element_reaction_test.tscn` 和 `scenes/tests/pixel_combat_effect_test.tscn`：既有元素逻辑与像素效果回归。
- Bootstrap 中两处旧断言改为检查当前音频资源和未知资源回退，不再要求武器声音缺失或硬编码旧 OGG 文件名。

首轮验证结果：音频 33 项、元素联动 57 项、像素效果 26 项全部通过；编辑器导入无脚本错误，Bootstrap 数据自检通过，主场景可启动。部分测试和主场景退出时仍有资源释放告警。

精简后复验：音频 34 项检查通过；23 个正式文件均与保留前哈希一致。离线页的 23 类声音各有一个播放器，连同旧版对比和组合示意共 28 段内嵌音频，均可解析为有效 WAV。

联动声音替换复验：新增 27 项联动音频检查、34 项原有音频检查、57 项元素逻辑检查、26 项像素效果检查，共 144 项通过；Bootstrap 自检通过。23 个 WAV 哈希保持不变。本次调整的是实战播放选择和武器音量，单项素材试听的声音保持原样。

本版已获用户确认，作为当前正式战斗音效使用，旧版电音保留。已检查 PCM 数据、峰值、首尾和运行时触发。后续更值得补的是玩家受击／濒死、敌人死亡、精英攻击预警，再考虑环境循环与战斗配乐的动态避让。
