# 战斗音效

战斗音效包当前启用 23 类声音，保留 25 个 WAV 文件；寒冰与冻结已按用户决定停播，原件用于存档对照。音频由程序原创合成，不使用外部采样。源文件统一为 48 kHz、16-bit PCM、单声道、无循环，多数素材峰值保留 5 dB 余量；已确认的电火花母版保留原峰值，约 -4.43 dBFS。首尾淡入淡出，Godot 导入采用项目默认压缩设置。

第一版精简时，原来差异过小的 12 个变体及其导入文件已移至项目外 `D:/project/useless/resources/combat-audio-review/archive/variants_v1/`。2026-09-23 重制了电火花、落雷蓄能、落雷、导电、雷火引爆五个素材，新增两种落雷联动音；其余 18 个战斗素材与重制前逐字节一致。运行时保留小幅音高随机变化；蓄能音高固定，以保持阶段时序。

## 原有缺口

- 木质弓箭（历史 ID 为 `weapon_void_blade`）的 `hit_sfx` 指向不存在的 OGG；电浆炮也使用这个缺失路径。
- 基础附魔仅电火花、落雷接入声音；其他附魔、联动缺少专用反馈。
- 落雷原先在命中时立即播放雷声，实际落雷约在 0.5 秒后。
- 原附魔音效仅做同帧去重，缺少跨帧冷却；通用音效池轮转会覆盖尚在播放的声音。

原版 `lighting_1.wav`、`lighting_2.wav`、`thunder_1.wav` 保留在 `assets/audio/sfx/effects/`，当前战斗改用 `assets/audio/sfx/combat/`。

| 电火花，1 个 | 0.28 秒“原味提亮”，保留 C 的五段断续撕裂与颗粒，仅轻提亮 | 实际连锁击中；75 ms 冷却，最多 3 个声部 |
| 落雷的蓄能、雷击，各 1 个 | 0.48 秒渐强电流；1.72 秒近处雷击、低频冲击与滚雷尾音 | 蓄能启动；0.5 秒预警结束后真正落雷各自触发 |
| 落雷导电、落雷雷火，各 1 个 | 保留雷鸣主体，分别加入导电爆裂、火焰爆燃 | 落雷命中打湿／燃烧目标时播放组合音 |

| 寒冰、冻结 | 已停播；共用寒冰音效的坤舆秘仪书命中也无声 | 状态、伤害与特效照常生效 |
| 光辉剑，1 个 | 低中频撞击与厚重落地 | 剑体实际落地 |
| 黑洞，1 个 | 空腔、低频收缩、轻微颤动 | 黑洞开始吸附；无长循环 |
| 蒸汽、解冻、神圣火焰、暗焰、光暗湮灭、导电、雷火引爆、湿润扩散、霜线推进、光冰反射，各 1 个 | 分别对应反应特征；光冰反射为魔幻晶莹泛音 | 对应反应发生时 |

分裂、穿透、连锁强化继续使用武器和元素的命中反馈，不另加一层重复提示声。雷火引爆只播放组合音，不再叠加普通爆炸声。

## 同次命中的联动声音替换

普通附魔与联动按一次命中收集后决定播放内容。联动发生时，取消参与反应的普通附魔音，保留联动音，武器命中声额外降低 5 dB。没有发生联动的普通命中保持原音量；未参与联动的其他附魔继续播放。

| 联动 | 取消的同次命中音效 |
| --- | --- |
| 蒸汽 | 水流、火焰 |
| 冻结 | 水流、寒冰 |
| 神圣火焰 | 光辉剑、火焰 |
| 暗焰 | 黑洞、火焰 |
| 光暗湮灭 | 光辉剑、黑洞 |
| 导电 | 水流、电火花、普通落雷 |
| 雷火引爆 | 火焰、电火花、普通落雷、普通爆炸 |
| 湿润扩散 | 风刃、水流 |
| 霜线推进 | 风刃、寒冰 |
| 光冰反射 | 光辉剑、水流、寒冰，以及同次触发的冻结前奏 |

不同投射物的命中分别处理，即使发生在同一帧也不会相互取消声音。同一次范围命中会合并重复反馈；电浆每批接触伤害使用一个声音批次。若同次命中实际发生多个独立联动，仍可保留各联动反馈，继续受全局冷却和声部上限控制。

首段连锁、黑洞启动及引爆保留来源关联。后续连锁跳跃和落雷的雷击按新阶段处理：蓄能照常播放，湿润目标受到落雷时用导电音替代普通落雷音；不会删除半秒前已经发生的水流声。雷火和暗焰的火种晚些落地时，仍沿用原命中的替换决定，避免重新补播普通火声。

落雷阶段由 `CombatAudioImpact` 保存来源，导电与雷火分别选择 `reaction_conduct_strike`、`reaction_thunder_fire_strike`，避免宏大的落雷突然变成短促电弧。同一落雷同时命中打湿和燃烧目标时，统一使用雷火轰鸣，所有目标的伤害与状态反应仍正常结算。普通电火花继续使用短促的导电／雷火组合音。

播放选择最多等待一个渲染帧，以收齐同次命中的延迟回调；伤害、状态和特效执行不等待音频。联动音因冷却被省略时，不恢复已被替换的基础音。暂停会清空尚未播放的请求。

规则表在 `scripts/audio/combat_audio_impact.gd`，收集与播放在 `autoloads/audio_manager.gd`。最多暂存 256 个命中批次，维持原有声音并发上限。

## 实战混音

- BGM 播放增益为 +6 dB；音乐 100% 约等于调整前的 50%，设置滑条仍控制各自总线。
- 普通落雷及两种落雷联动增益统一为 -14 dB，较此前降低 9 dB；保留雷击与滚雷素材。电火花增益为 -10 dB，配合更密集的放电音色控制峰值。
- `CombatSFX` 独立总线送入原 `SFX` 总线，继续使用设置页的音效音量。
- 12 个独立战斗声部，不占用 UI 音效池；保留 4 个声部给命中、落地与主要反应。
- 60 ms 内最多启动 3 个普通细节声与 3 个重要反馈声。每类另有 65–550 ms 冷却和 1–3 个声部限制。
- 普通落雷与两种落雷联动共用 `thunder_landing` 声部组：260 ms 冷却、最多 3 个声部，不能通过切换联动类型绕过限制。已播放的尾音自然结束。
- 满载时丢弃多余请求，不抢占已播放声部、不积压待播放队列。
- 战斗总线压缩器控制密集叠加，限制器上限 -2 dB。此上限不代表 BGM 与所有总线相加后的主输出上限。
- 战斗暂停后停止短音尾巴，关闭面板后不回放旧声音；UI 音频仍按原逻辑播放。
- 每类使用同一文件，播放时保留小幅音高浮动，使用独立随机数生成器，不影响玩法随机数。

## 2026-09-23 电音重制审计

主要问题在素材和联动选音：旧电火花仅 0.23 秒，主要由少量噪声脉冲和下滑正弦组成；旧落雷仅 0.49 秒，共用电弧与普通爆炸的主体配方，缺少滚雷。落雷的旧 RMS 为 -19.16 dBFS，叠加游戏增益后约 -28.16 dBFS；重制后素材 RMS 为 -15.38 dBFS，游戏增益从 -9 改为 -5 dB。新版本通过宽频雷击、低频湍流和衰减混响建立冲击与余响。

全目录核查包含重制前 33 个 WAV 和 2 个 BGM OGG。另发现以下既有音频问题：

- `AudioManager` 中 8 个通用 UI／结息音效路径，以及经验拾取、波次结束两个路径，共 10 个 OGG 文件缺失，调用会静默返回。银行存取款的 `bank_%s.wav` 是格式化路径，实际两份 WAV 均存在，不计为缺失。
- BGM 运行时固定增加 12 dB。战斗曲源文件平均 -31.9、峰值 -14.8 dBFS；菜单曲平均 -29.9、峰值 -12.1 dBFS。满音量时菜单曲峰值接近 -0.1 dBFS，留给 UI 叠加的余量很小。战斗限幅器只作用于 `CombatSFX`，并不保护 BGM 和 UI 相加后的主输出。这是后续整体混音需要单独解决的问题。
- 原版 `lighting_1/2.wav` 与 `thunder_1.wav` 仍在资源目录，但当前电附魔实际使用 `sfx/combat/` 内的素材；只修改原版文件不会改变现有附魔声音。

试听页用于判断音色方向；文件指标和自动测试用于检查削波、格式、触发时机、联动路由与并发，不能代替主观听感评估。

本次验证：25 个正式 WAV 均为 48 kHz、16-bit 单声道，首尾采样为零、素材峰值为 -5 dBFS；两个离线试听页的全部内嵌 WAV 校验通过。Godot 音频测试 39 项、联动音频测试 29 项全部通过，Bootstrap 自检通过。完成新素材导入后的编辑器复验无脚本错误，仅有本机 Android build-tools 缺失提示；Bootstrap 的重复购买警告是对应拒绝购买测试的预期输出。验证日志位于上述重制目录。
