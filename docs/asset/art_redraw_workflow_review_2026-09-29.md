# 高清重绘 → Picxel 像素化：工作流评估

日期：2026-09-29。本文为流程建议，不代表已生成、转换或批准任何新素材。

## 结论

“豆包 / Nano Banana 生成高清稿 → 用户审阅 → Picxel 后处理 → 用户审阅 → 正式替换”是合理的生产流程，符合本项目外部图片后处理技能的分工。

需要补充两点：**生成前确定目标显示规格；第二次审阅同时包含像素成品和游戏内预接入效果。** 第一批先用少量代表素材跑通全过程，再批量生成。否则高清阶段认可的细节可能无法落到目标网格，而单张像素图合格也不代表同屏效果一致。

## 参考图应该怎样使用

`artifacts/reference/` 不是一套已经统一的画风，里面同时有写实游戏截图、概念场景、漫画插画、密集线描和动漫角色。应给参考分配用途，而不是对每种资产都混合使用所有参考。

## 高清稿的合格条件

高清表示轮廓和结构有足够采样精度，不表示细节越多越好。适合后处理的稿件应具有：

- **少量清楚的大形状。** 去掉颜色仍能从剪影认出物件；轮廓完整，不裁断帽尖、武器尖或肢体。
- **可分离的明暗组。** 每种主要材质可先按约 3～4 档明暗设计；暗色主体之间仍保留足够亮度差。暗黑氛围不能仅靠整体压暗。
- **概括的细节。** 褶皱、金属高光、石材裂痕以少量块面表达；减少织物纹理、密集排线、细小铆钉和碎噪点。
- **稳定的识别特征。** 每个资产明确最重要的 2～3 个特征，目标尺寸无法容纳的特征在高清阶段就要简化或适度夸张。
- **一致的美术约束。** 同组采用同一主参考、比例、视角规则、轮廓处理、材质色阶和光源方向。换模型时仍使用已确认样板校准。
- **可用的背景。** 角色/道具优先真实透明背景；模型无法输出可靠 alpha 时，使用与主体色不同的均匀纯色底再抠图。绘制出来的棋盘格不是真透明。

无需要求高清稿先做假像素、马赛克或模糊像素边。先得到适合缩小的硬边概括插画，最终像素网格交给后处理控制。

可以用以下尺度关系检查细节是否可靠：主体高清宽 800px、目标可见宽 50px，相当于缩小 16 倍；原图 8px 宽的链条只剩约 0.5 个目标像素，无法可靠保留。应在原图加粗/简化，或制作目标小尺寸的专用结构，而不是依靠锐化恢复。

## 建议生产步骤

### 1. 先确定交付规格

每项资产记录：用途、高清构图、目标逻辑画布、可见主体尺寸、最终显示尺寸、锚点、可用色板和是否需要动画/平铺/九宫格。

同一物件可有战斗精灵、UI 小图标和展示大图三种版本；它们可以共享设计，但不能假定一张图任意缩放都合格。项目当前世界和 UI 还存在窗口级非整数放大，素材工作必须与显示规格一起规划。

### 2. 先做一组代表小样

建议首批选择一个玩家、一个怪物、一个细长武器 icon、一个遗物，以及属性栏/理财共用的面板组件；必要时加一块石材场景件。选择这些对象能同时暴露比例、轮廓、材质、细线和 UI 风格的问题。

每个小样跑完“高清 → 像素 → 游戏内预览”。用户认可的结果成为后续参照。批量生产时，不只附原始风格参考，也附这组已确认的高清稿和像素成品。

### 3. 生成高清稿并进行第一次审阅

审阅重点：造型、姿势、比例、构图、光源、主体完整性、同批一致性与缩略剪影。建议在高清稿旁附目标尺寸的快速缩略示意，仅用于检查可读性，不作为最终像素交付。

豆包和 Nano Banana 都可以作为高清输入来源；本次没有对两者做生成对比，不据此判断谁的效果更好。一个批次尽量固定已验证的模型/模式、参考图与描述，避免将来源差异交给后处理解决。

### 4. 使用项目外部图片技能处理

按 `.agents/skills/picxel-external-images/SKILL.md`：保留高清原图 → 抠图与特征标注 → 限色和网格化 → 对照检查 → 局部像素修整 → 导出审阅 PNG。

本地算法可以处理尺寸、颜色、透明度和网格，局部修整可以恢复眼口、轮廓和细线。解剖错误、错误透视、缺失肢体和根本性的造型变化应回到高清阶段修正。技能的 `anchor` 是检查约定，不是让算法理解语义的命令。

### 5. 第二次审阅合并像素图与游戏内效果

同一次审阅提供：原始像素尺寸、4 倍最近邻放大、亮/暗背景对照，以及临时接入真实场景的截图。必要时附动画循环。

临时预接入使用独立副本或审阅场景。检查实际大小、与旧/新资产的同屏关系、角色脚底、图标槽位、按钮状态、字体、窗口缩放和暗处辨识度。这样保留原流程的两次人工审阅，不必把每个机械步骤都变成新的审批。

### 6. 确认后替换正式资源

核对引用、图集裁切、帧序、锚点、缩放、过滤与导入设置；不要只替换 PNG 而保留不适合新图的旧参数。保留高清输入、确认版本和可编辑像素稿，按项目规范完成 Godot 检查。

## 当前 Picxel 流程的实际边界

1. **标准输出是 32/64/128 的方形网格，每张最多 16 色。** 此处是当前项目入口的约束，不代表像素艺术只能使用这些尺寸或色数。整幅横向背景、长条 UI 框不适合直接套这个入口，需要拆件再组装，或先扩展矩形/分层处理能力。保留原始宽高比，不把宽背景拉成方图。
2. **动画需要固定几何基准。** 当前流程默认逐图按可见主体适配；若对每帧独立裁切和缩放，可能出现角色忽大忽小和脚底漂移。动画必须统一画布、缩放、脚底/握持锚点和色板，并审阅连续播放。高清动画也不能仅依赖逐帧重新描述同一个角色。
3. **色板应按资产家族管理。** 同一角色的各帧、同一套 UI 的组件使用一致色板；不同家族共享总体色彩方向，但不必把整个项目强制塞进同一组 16 色。当前工具需填写完整数值色板才能锁定，文字写“暗绿、旧金”不足以保证同批锁色。
4. **硬透明适合角色与道具，柔光/雾效另行设计。** 当前输出 alpha 为 0/255；软光晕会被改变。光照、阴影、雾和发光特效适合拆成独立层或由引擎控制。
5. **UI 框按组件设计。** 角、边、可平铺底纹与装饰分离；正文、数字和功能按钮文字由 Godot 绘制。AI 可以设计框的外观，但九宫格边距与平铺接缝仍需确定性整理。
6. **小图标需要以目标尺寸为准重组。** 128px 成品通过，不代表缩成 32px 仍通过。细长武器、链条和空心饰品尤其需要专用小图版本。

## 高清生成描述模板

> 生成【主体】，用于【战斗角色 / 物品图标 / 场景件 / UI 装饰】。沿用附图中的【比例、视角、轮廓方式、材质与配色】。整体为暗色幻想插画，清晰完整剪影，大面积概括色块，深色外轮廓，硬边分组阴影，少量有明确形状的高光。主要保留【特征 1、2、3】。后续会缩小到【目标可见尺寸】，细小结构应简化并适度加粗。采用【指定光源】与【指定色彩方向】。背景为【真实透明 / 指定均匀纯色】，主体完整，留白符合模板。减少密集排线、微小表面纹理、碎噪点、柔焦与复杂光晕，不在图中绘制界面正文。

这只是通用骨架。角色增加锚点和动作要求；图标增加缩略剪影要求；UI 增加平铺与边角要求；场景增加层级和镜头要求。最终提示词应引用确认样板，而不能仅使用“克苏鲁 + 暗黑地牢 + 高清”几个风格词。
