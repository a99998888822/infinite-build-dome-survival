# 玩家与角色模块素材生成 Checklist

本文档用于记录“玩家与角色模块”在设计阶段需要准备的图片素材、生成提示词、目标规格、放置路径与当前状态。当前阶段只要求满足 MVP 流程：角色选择页面 → 营地 → 开始战斗 → 局内玩家移动。所有提示词均为中文单提示词，可直接复制到 Ludo.ai 或类似 AI 素材工具中使用。

## 1. 统一美术规范

| 项目 | 约定 |
|---|---|
| 画风 | 清新、干净、轻微可爱、克苏鲁轻幻想、像素风但不要低像素粗糙感 |
| 氛围 | 可以是黄昏、夜晚、昏暗穹顶氛围，但不要肮脏、噪点、腐烂、过度恐怖 |
| 角色比例 | 简单小人，头身比偏可爱，轮廓清晰，装备不要复杂 |
| 像素精度 | 中高精度像素风，建议单帧角色有效像素感接近 64x64 或更高 |
| 背景要求 | 精灵图必须透明背景；角色选择立绘可透明或纯净浅色背景 |
| 朝向规则 | 只制作向右；向左由 Godot 水平翻转；暂不制作向上、向下动画 |
| 动画规则 | 先生成向右单帧，再基于单帧生成向右行走帧表 |
| 裁剪规则 | 动画帧表必须等宽等高网格，建议 6 帧 x 1 行，每帧 256x256，整图 1536x256，透明背景 |
| 锚点规则 | 每帧角色脚底位置一致，角色居中略偏下，避免走路时上下跳动过大 |
| 文件格式 | PNG，优先透明背景，禁止 JPG 用于正式游戏素材 |

## 5. Godot 导入与裁剪约定

1. 正式动画帧表必须是透明 PNG。
2. 每个动画使用单独 spritesheet，不混放多个动作。
3. 行走动画使用 `6 帧 x 1 行`，每帧 `256x256`。
4. 待机动画使用 `4 帧 x 1 行`，每帧 `256x256`。
5. Godot 中使用 `AnimatedSprite2D` 或 `SpriteFrames` 时，按固定网格导入。
6. 玩家向左移动时不需要独立图片，直接对显示节点设置水平翻转。
7. 若后续缩小实际显示尺寸，应在 Godot 中统一缩放，不要让每张源图尺寸不同。

| 未存在 | 还没有生成或未放入目标路径 |
| 已存在 | 文件已放入目标路径，等待 Godot 导入验证 |
| 已接入 | 已在 Godot 场景或脚本中使用 |
| 可暂空 | 非 MVP 必需，可以后续补 |
| 需重出 | 已有图片但规格不适合工程使用，建议重新生成 |
