# 遗物批量白底图集流程

前三批共24件遗物已安装。前两批通过用户像素审阅，第三批按本轮“像素化并替换”直接授权完成，见[第三批记录](14_relics_sheet_03_installation.md)。当前执行[第四批12件](batches/relics_sheet_04/README.md)，4列×3行，一张画风参考，不提供基础图。

按用户最新要求，遗物可由“一次一件”改为“一次生成一张多物件白底高清图集”。模型返回的通常是一张图片，后处理再拆成多个独立PNG；是否支持一次返回多个独立文件取决于豆包当前界面，不能依赖提示词保证。

第一批生成配方保留在[原目录](batches/relics_sheet_01/README.md)。第二批沿用3×2白底图集形式，但不再上传第一批道具母稿或旧图标，以项目画风图与文字设计简报生成新造型。

前两轮采用3列×2行。第三轮增加至4列×3行，优先3072×2304或平台最高可用分辨率。生成后下载原始文件，逐项核对数量、身份与位置；每件独立拆分，个别失败只补做该项。豆包一次12件与Picxel每批最多20个输入是不同约束。

1. Codex整理一张画风参考、位置→资源ID清单和原创设计提示词；旧图标只供内部核对，不上传给豆包。提示词也不复述旧图的具体布局。
2. 用户在豆包新开对话生成白底图集，下载原文件并审阅新造型。只借用参考图的绘画语言，物件身份由文字定义。
3. Codex核对实际数量、身份与位置，再记录逐件裁切坐标；模型错位时按物件识别修正映射，不盲按等分格切断物件。保留原图，失败项单独重做。
4. 逐件抠图，保留浅色材质和高光，检查内部孔洞、残留白边、断开的装饰件和完整轮廓。
5. 每件独立从高清图转为32×32像素稿，最多16色、硬透明、无抖色；批内采用协调的材质色，不把整张图集量化后再切分。
6. 默认用户审阅原尺寸、放大与深浅背景总览后接入；已明确授权像素化后直接替换时，助手检查、备份并安装，执行后台实机验证。

批量更容易统一光源、色彩和线条，也减少重复操作；物件数量、身份串换、格间重叠和每件有效分辨率需要人工核对。纯白背景是利于抠图的输入条件，不等于已经带透明通道。后处理流程沿用[05](05_picxel_commands.md)，只增加“先拆高清图集”这一步。
