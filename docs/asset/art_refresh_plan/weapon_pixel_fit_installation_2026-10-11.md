# 武器图标按屏幕像素显示 · 正式接入

2026-10-11：按用户确认，将实机试验有效的尺寸匹配方案接入正式游戏。正常启动即可使用，不依赖试验绘制层、Python 或 `artifacts/` 目录。

## 正式行为

| 界面 | 最低物理尺寸（长边） | 布局处理 |
| --- | --- | --- |
| 选人初始武器 | 26px | 保留裁切比例，为武器行预留空间 |
| ESC 武器栏 | 32px | 根据实际图标行增高栏体，同时下移并缩短遗物面板，保留原底部位置 |
| 理财购买 | 32px | 由图标框预留尺寸；切回遗物卡片时恢复原布局 |
| 理财附魔武器栏 | 32px | 保留横向滚动、选中、悬停、拖放和文字排版 |
| 理财附魔详情小图 | 26px | 随图标尺寸调整详情行 |

按窗口实际输出尺寸，选择最接近的既有图集版本，按其原生像素显示；需要超过母版大小时使用整数倍放大。裁切的选人图标按可见裁切尺寸选择版本。控件为整数定位预留每侧一个物理像素的余量，避免第二次非整数缩放。

全局 `canvas_items` / `expand` 配置不变，遗物和其他未启用的图标继续使用原有行为。此次没有重新绘制 PNG；炉灯提手等小图素材本身的缺口仍需独立美术修整。

## 实现

- `scripts/ui/weapon_pixel_texture.gd` 包装真实 Texture2D 的绘制，在原控件的 CanvasItem 内调整目标矩形，沿用原生滚动裁切、透明度、主题状态和显示顺序。
- 根据 Godot 的控件局部位置取整和逐层 CanvasItem 变换取整，计算最终屏幕像素位置。
- `scripts/ui/item_icon_art.gd` 保留原图集缓存和素材身份，按界面启用武器尺寸下限。窗口、布局和祖先位置变化触发更新；静止图标不逐帧轮询或重绘。
- 复用控件切回遗物、空图标或未适配图像时恢复布局约束。包装纹理使用弱引用持有控件。
- `WeaponStrip` 通知 ESC 实际行高变化，避免小窗口底部裁切以及遗物面板挤到日志按钮。

## 验证

- Godot 4.7.2：图标原有回归 22 项、物理尺寸与复用回归 81 项、附魔界面回归 16 项、冷却反馈回归 29 项，共 148 项通过。
- 编辑器 headless 导入、主场景 headless 运行，以及 48 个真实界面状态的 headless 检查通过。
- GPU 在独立 Windows 桌面完成 48 张截图；实际引擎桌面核验一致，`foreground_samples=0`。
- 覆盖 640×360，以及七档正式预设：1024×576、1152×648、1280×720、1366×768、1600×900、1920×1080、2560×1440。
- 比较 160 个图标样本，共 97,471 个不透明像素；与选定源纹理逐像素一致，没有因再次缩放丢失像素。验证允许每颜色通道最多 2 的数值差。
- 640×360 附魔横向滚动栏左端第三把武器的纹理矩形触及滚动裁切边界；被裁区域是透明留白，其全部不透明像素同样通过核对。滚动容器继续保留正常裁切行为。
- 测试选图遍历全部 15 张武器状态图（含回收状态）及其裁切版本；截图使用 9 种代表性武器。
- 已检查 UTF-8 和文本异常字符，保持已有文件换行约定。新增 UID 均由 Godot 生成。
