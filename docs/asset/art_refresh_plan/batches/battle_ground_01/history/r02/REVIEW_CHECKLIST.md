# battle_ground_01 · r02审阅标准

## 高清稿先看这六项

| 检查 | 可接受 | 需要回到高清阶段修正 |
|---|---|---|
| 输出类型 | G01–G05满幅不透明，G06–G08分离白底物体 | 地表画成岛、盆景、场景、图集或带透明缺口 |
| 照明 | 每个局部有简洁体积明暗，整图无单向亮度变化 | 左上整片发亮、右下黑角、斜光、长投影 |
| 重复特征 | 草簇／破口有变化，密度均衡、无主角 | 中央石堆、巨大草团、强记忆点、大坑或斜条纹 |
| 视角与尺度 | 地表正交俯视，G04/G05同砖尺度和错缝方向 | 近大远小、透视收缩、平台侧面、两图砖大小悬殊 |
| 可缩小性 | 128px预览仍有清楚草簇和砖形 | 细草针、砂粒、破碎噪点成为主要内容 |
| 原文件 | 最高原生尺寸，真实文件格式；无额外排版 | 仅低分辨率聊天截图、插值冒充高清、画入文字／水印 |

平台自动添加的标识未必能靠提示词消除，应优先下载可用原文件。含标识的预览先登记，不能直接当作平铺成品。当前收到的G01为384×384 RGB预览，有可见右下标识；问题详情单独留档。

高清阶段先做原图的3×3重复预览、灰度／缩小检查，判断整体亮度趋势和显眼重复物。这里的缩小图只是检查，不代表已经执行Picxel。轻微局部边缘不匹配可以留到像素阶段；全幅斜光或场景构图不应留到最后处理。

## 像素母材质与边界

- 采用项目外部图片流程：G01–G05候选128×128、不透明；灌木独立128×128、真实透明。记录源文件、参数、修整和导出尺寸。
- 分别查看原尺寸、最近邻放大、2×2与3×3重复。检查水平／垂直接缝与四块交点；边缘可衔接不代表重复图案不可见。
- 通过循环偏移把四边接缝移到中间检查；修整保持整体颜色和块面，不能靠模糊、拉伸边缘、渐变遮盖。不会强行要求相邻两列像素完全相同，而是检查视觉连续。
- 保留同材质、相同边缘约束的内部变化版本；所有会相邻的变体组合也要检查。G02与G01属于密度不同的材质，不当成随便交替的同款变体。
- G04/G05统一砖网格与平均尺度；存在局部明暗方向时，不随意旋转／镜像纹理来凑变体，避免砖列或光照转向。
- 母纹理Alpha为255，或RGB无Alpha。透明遮罩另存为硬边网格，精灵Alpha主要为0／255；实际图像有Alpha通道不代表内容必须透明。
- 地表混合检查草→泥、草→砖、泥→砖以及G04→G05，包含直边、内角、外角、窄条、三材质交点。遮罩缩放不能产生模糊灰边。
- G05缺砖处泥土默认保留。只有需要局部露出下层时才绘制对应形状，不能用全局颜色阈值抠除泥土、阴影或黑色轮廓。
- 灌木逐件检查白边、漏抠、细枝断裂与留白，透明处在亮暗背景都干净；不把白底投影一起带入游戏。

## 候选战场实机

- 中央、外围都形成完整地貌；无黑色空洞、128方格轮流换材质、明显重复石堆或条纹。
- 跨越正／负坐标和区块接缝，持续移动后返回，地面／装饰布局一致；只在出生区出现一次中央广场。
- 材质在世界坐标固定，镜头滚动时不游动、不随地平线拉伸；附近区块加载、远处回收，无节点持续增长。
- 草／泥／石／水查询与实际画面一致，水纹和湿脚步仅在适用区域出现，不借用贴图透明度判断地表类型。
- 黄昏、夜晚分别检查底色、天幕、CRT／暗角与装饰乘色的共同结果；不靠把整图压黑表现夜间。
- 两玩家、小怪、Boss、预警和掉落在所有地表都清楚，灌木不遮住关键动作；不改变既有碰撞和刷怪规则。
- 检查1280×720与640×360、暂停恢复、退出回收。修改运行逻辑后先headless；GPU实机使用独立Windows桌面，验证foreground_samples=0。

以上为后续验收要求，不表示新地面已通过检查。`audit/background_capture.*`是旧场景基线，不作为r02新场景通过的证据。
