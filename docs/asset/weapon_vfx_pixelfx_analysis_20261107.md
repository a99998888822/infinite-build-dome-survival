# 武器攻击特效分析：以赤铜炉灯为基准

2026-11-07。范围是当前工作区的 16 把武器，包括配置中 `release_locked` 的武器。本文是美术与实现分析，不修改正式特效、数值或伤害时序。当前目录含既有未提交修改，因此这里描述的是工作区状态，不是某个已提交版本。

评审入口：[武器专项对比页](../../artifacts/reviews/weapon-vfx-analysis/index.html)。逐项结论保存在同目录 `analysis.json`；页面将当前真实施放片段、pixelfx 候选动画及适配建议并排显示。建议列为文字方案，尚未制作改造后的成品动画。

## 核心判断

可以参考，而且不需要推倒当前实现。当前项目已经具备块状图集、像素对齐、独立视觉运行时和前后分层，主要应改善色块组织、攻击瞬间的明暗主次、尾迹形状与消散节奏。pixelfx 的优势是把攻击拆成可读的阶段；其全部粒子、光晕、烟雾和演出长度不适合直接搬入密集战斗。

赤铜炉灯的品质应被理解为共同美术标准，各种元素仍保留自己的色彩与身份。重锤应有重量，短刀应快，电浆应有带电球体的连续感。

## 炉灯为什么成立

依据 `scripts/effects/copper_lamp_flame.gd` 和对应 shader：

- 用连贯密度场形成火焰主体，宽尺度噪声占 72%，细尺度噪声占 28%。细节服从轮廓，画面不会完全分解成散点。
- 在局部世界坐标上按 2 像素量化，再换算地面投影，轮廓形成稳定阶梯。视觉时间量化为 18Hz；这不表示游戏逻辑也降到 18Hz。
- 四档暖色依密度和距喷口位置分布，最亮部分集中在根部，外缘较暗，能够读出能量流向。
- 只有 5 个脱离主体的余烬候选，粒子负责延伸动势，主体负责表达攻击。
- 喷口偏移、锥角和径向裁剪与攻击几何对应。前后火焰拆分减少主体和角色相互遮挡的问题。

这套标准不等于必须共用炉灯 shader，也不等于所有武器强制使用相同帧率。快速刀锋可保留更高视觉采样率。

## 优化顺序

| 顺序 | 武器 | 借鉴来源 | 首要改进 |
| --- | --- | --- | --- |
| P1 | 电浆炮 | `projectiles/plasma-shot`、`explosions/plasma-explosion` | 球核、弧光、接地亮点建立主次；接触脉冲不重复完整爆炸 |
| P1 | 裂地战锤 | `melee/hammer-smash`、`impacts/ground-slam` | 首次落地集中爆点；后续 5 节点按真实节奏推进低矮裂尘 |
| P1 | 营地短刀 | `melee/dagger-flurry`、`melee/sword-slash` | 保留现有逐步揭示，用头厚尾薄、前亮后暗提升方向感 |
| P1 | 铸铁榴弹炮 | `explosions/grenade` | 块状爆焰的膨胀与冷却；减少遮挡目标的残留 |
| P2 | 守夜长枪、流星摆锤、异化触手 | `thrust`、`spear-sweep`、`whip-crack` | 强化刃尖、锤头、触手尖端的运动重点 |
| P2 | 坤舆秘仪书、突进短刃、巨型手持火炮、斩马刀 | 符印、刀锋、枪口焰类 | 区分持续提示与瞬时攻击；检查像素网格和层级 |
| P3 | 木质弓箭、食利者钱袋、移星秘典 | 箭矢、符文、魔法弹类 | 小范围整理高光、短尾迹及出发/到达关系 |
| 保留 | 赤铜炉灯、刚焰炉 | `fire-breath`、`fire-ring` 仅作节奏参照 | 保持已确认的大色块及元素身份 |

这里的 P1 是美术收益与评估顺序，不是已验证的程序缺陷等级。长枪、摆锤和斩马刀已有明确方向和分层，不能仅因不同于炉灯就判定为错误。

## 已发现的具体实现差异

1. `weapon_block_vfx.gd` 已统一使用图集辅助绘制，榴弹、书、触手、战锤、长枪分别有 12/10/8/8/7 帧。应先改进这些素材的形状和帧间变化，再决定是否需要新 shader。
2. `aligned_atlas.gd` 默认网格为 3 屏幕像素，其他调用可覆盖；炉灯为 2 世界像素，斩马刀使用 `FRAGCOORD` 的 2 屏幕像素。存在采样基准差异，但不能直接全局替换。应以实际战斗镜头的 1×、1.5×、2× 比较轮廓、颗粒和缩放后尺寸。
3. 短刀已有随刃口进度揭示月牙的逻辑，并非缺少扫击动画。优化应保留该机制，不将整片月牙提前点亮。
4. 电浆炮已有世界空间固定的接地点和双闪周期。应保存这些稳定性设计，参考膨胀壳时也不能让放电端点每帧漂移。
5. 战锤地裂节点间隔 100ms；触手命中与回收有独立时序。参考动画只能重映射视觉阶段，不能把参考的蓄力或回收复制成新的伤害时段。
6. 刚焰炉已使用与炉灯一致的世界像素思路，并有正式审阅记录。当前最合适的行动是保留，先用它判断其他效果是否过亮、过细或过于碎片化。
7. `weapon_void_blade` 的显示名实际上是木质弓箭，分析和后续任务不能按内部 ID 误当刀类武器。

## 适配原则与性能边界

- 每次攻击先确定一个主形：球、弧、直刺、冲击团或符印；亮核、外缘和碎屑都服从主形。建议从 3–5 档主要颜色开始，这不是对现有素材颜色数量的统计或硬性上限。
- 保留当前地面、主体、前景和信息层的分工，尤其不因参考图好看就把全部效果放到怪物前景。
- 闪光与尘屑按攻击或真实命中节点组织；持续伤害不应每 tick 创建完整复杂动画。伤害 tick 与视觉脉冲可以分离，但不能吞掉真实玩法事件。
- 高频命中优先复用预加载图集、现有批次和缓存，避免为每个目标、每一层装饰增加独立节点。参考 JS 粒子模拟不作为新战斗运行时移植。
- 当前 `docs/hammer_plasma_performance_20261107.md` 已记录密集接触 CPU 峰值仍偏高。这里没有新增 GPU 性能结论；录制帧率也不能作为实战帧率基准。
- 参考动画只用于美术比较，时长和尺度来自 pixelfx 自身，与游戏攻击参数不同。不得据此扩大碰撞、延长控制或增加伤害。
- 如未来直接携带 pixelfx 的代码或资源，保留其 MIT LICENSE 及 NOTICE 中的上游归属。本页不使用其受独立条款约束的 Patch Pixel 字体。

## 下一步的可验证工作

建议先制作电浆炮、战锤、短刀各一个隔离候选，与当前真实施放和炉灯并排；只有完成对应评审后，才进入正式替换。这符合仓库 AGENTS.md 的先对比、再改造要求。

正式落地时检查：单次攻击的接触帧与范围；五级多投/分裂下的画面；至少一种附魔组合；暂停与清理；怪群中的遮挡；相同夹具下 CPU/GPU 帧时间。现阶段的真实施放录制只有静止高血量目标和无附魔基础武器，不替代这些回归检查，也不覆盖移星秘典的返回操作或所有升级分支。

## 本轮验证记录

Godot 4.7.1 已完成 headless 编辑器加载与录制夹具运行。首轮夹具对刚焰炉调用手动施放，按正式规则被拒绝；这是夹具使用方式错误。随后改用正式 `auto_attack()` 单独补录，补录退出码为 0。其余 15 把均成功施放并记录到目标伤害。刚焰炉补录观察到正常火圈，但该片段没有伤害事件，只证明外观入口可运行；没有将其计为命中回归通过。原始记录和补录记录分开保留，汇总见评审目录 `capture-summary.json`。

两轮 GPU 录制分别验证了实际引擎所在的私有桌面，均为 `foreground_samples=0`。参考页使用裁剪后的当前实录与独立导出的 18 个 pixelfx 动画；没有新增正式美术或玩法修改。
