# 水流 R02 / 黑洞 R03 / 落雷 R01 正式接入

已按用户最终选择替换正式视觉，保留原伤害、控制、预警和元素反应。改动未提交。

水流使用 R02 的无浪沿波纹，按当前实际范围缩放；黑洞使用 R03 的原色球体与穿过表面的短光粒，球体视觉已经缩为 0.8 倍，不再二次缩放，也不缩小原伤害/拉拽范围。落雷使用 R01 主干、额外分叉与粗火花；保留当前黄色预警和 0.5s 等待。地面纵横比沿用当前透视，雷柱高度与地面扩散分别缩放。

## 运行方式

美术离线生成八张 PNG 图集，运行时选择区域播放，纹理全局共享。水流和黑洞不再实时计算水面 shader 或逐光粒轨迹；落雷正式入口不再构造雷道网格。连锁闪电仍然动态生成，以支持任意敌人位置。预警、命中敌人的反馈、伤害与控制继续原逻辑。

素材使用 nearest、无 mipmap、无损导入，整段固定裁剪窗口和落点。按 RGBA8 像素计算共约 **7.90 MiB**，不是 PNG 文件体积或实测驱动显存；实例增加不会复制纹理，但会增加绘制和透明混合开销。加载遮罩下会预热所有八个非空片段。

默认黑洞保持 0.85s 原片段，延长控制时长时播放独立的 2s 稳定吸入循环，最后接消散段；默认画面不变，长时长衔接可能出现粒子相位切换。雷柱保留主闪 0.16s、暗间隔 0.04s、回闪 0.16s 的精确时钟，图集美术 18fps；火花可持续至 0.55s，不随雷柱提前销毁。高密度预算可关闭地面电弧和火花，保留主闪读图。默认落雷使用同一组已审阅路径，因此重复施法的形状更一致。

旧视觉消耗的水流一次随机抽样、落雷主闪和回闪路径抽样次数均保留，避免改变后续战斗随机序列。素材生成和计时不触发第二次伤害。

## 验证

- Godot 4.7.1 headless editor 导入/脚本检查通过。
- 水流范围/冰图集 29 项、终点范围 179 项、落雷控制 291 项、雷道兼容 109 项、元素反应 69 项、附魔叠加 313 项、加载预热/取消 92 项通过。
- 新增预制播放检查 17 项通过。实际 GPU 采样中，水流、黑洞各 16 个默认帧与离线源逐像素一致（合计 32/32）。落雷分层后按精确双闪时钟播放，采样量化和独立回闪起点造成少量帧间差异。
- 真实战斗场景深度 51 项通过：草地不遮住地面特效，地面特效不盖住不透明敌人；加入正式预制落雷分层。角色/前景层语义 37 项通过。
- GPU 运行均通过私有 Windows desktop helper，`foreground_samples=0`，未切换输入桌面。
- 主场景 headless 启动可进入 game root；强制 `--quit-after 120` 时报告 4 个 ObjectDB 和 2 个资源仍在使用。受控测试退出未报告相同问题，尚未把主场景强制退出的清理提示定位到本次修改。

测试中发现预热用例仍硬编码旧火焰层号 43，已改为当前 `ATTACK_Z - EFFECT_BASE_Z`，并补充八个图集预热断言。

## 本机视觉性能对照

同一 480×360 GPU 视口、相同数量/位置/采样时钟，关闭 VSync 和帧率上限，8 帧预热、90 帧采样，模拟每三个渲染帧更新一次 18fps 美术。比较已选程序化原型与正式图集播放；不含伤害、敌人、碰撞、音频、黄色预警，不能当作整场战斗 FPS 或移动设备结论。测量是 CPU 等待完整渲染帧的墙钟时间，不是 GPU timestamp。

| 100 个实例 | 原型帧中位数 | 预制帧中位数 | 原型 P95 | 预制 P95 |
| --- | ---: | ---: | ---: | ---: |
| 水流 | 0.900ms | 0.417ms | 1.854ms | 1.044ms |
| 黑洞 | 3.067ms | 0.405ms | 27.993ms | 0.912ms |
| 落雷 | 6.029ms | 1.331ms | 22.878ms | 3.129ms |

预制显著减少本机这组视觉负载的开销；伤害查询、元素反应、节点提交和大量透明重叠仍会消耗性能。没有为本次引入复杂对象池或 MultiMesh 批处理，避免破坏现有 Y 排序。手机实机压测仍需后续完成。
