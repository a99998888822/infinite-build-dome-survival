# V3 火焰接入与后续性能优化方案

日期：2026-10-04。状态：V3 外观已接入正式代码；下列性能优化为待实施方案。

后续进展：状态视觉、火焰数据缓存和局部怪物查询优化已接入；草簇合批试作因移动性能与遮挡问题未采用。新数据与验证见 [状态、火焰缓存与草簇合批审阅](runtime_cache_and_grass_review.md)。下文保留本计划制定时的测量与目标。

## 已接入范围

- 普通燃烧状态：每只小怪一个原版窄火舌，2px 网格。
- 地面火场：中间一个中宽火舌，左右各一个窄火舌，3px 网格。
- 飞散火种：沿用 V3 的单个窄火苗，运动、落点与合并规则不变。
- 四阶暖色、原版尖细轮廓、错相摆动、少量着色器火星保持 V3 审阅结果。
- 火焰通过共享材质、噪声纹理、时钟和最多三个 MultiMesh 图层批次绘制。
- 移除普通火场的五层 CPU 粒子发射器、普通燃烧脚下粒子和火种粒子拖尾，保留点火音效与场景照明。
- 燃烧伤害、持续时间、作用范围、风扩散、火场数量上限、圣焰和暗焰逻辑保持不变。

正式实现：`scripts/effects/pixel_fire_visual.gd`、`shaders/effects/pixel_fire.gdshader`，以及 `fire_patch.gd`、`fire_seed.gd`、`enemy_status_visual.gd` 的接入。生产运行不依赖 `preview/`、对照版本参数或计时器。

| 小怪状态视觉 | 0.572 | 每帧状态查询、火苗创建/复用、其他状态图标 |

| 开关 | 整帧耗时 | 绘制调用数 | 战斗子视口渲染 CPU |
| --- | ---: | ---: | ---: |
| 完整画面 | 11.08ms | 1543 | 6.49ms |
| 火焰改为纯色矩形 | 11.19ms | 1543 | 6.36ms |
| 不绘制火焰，仍更新实例 | 9.79ms | 1540 | 6.50ms |
| 不绘制、不更新火焰 | 9.27ms | 1540 | 6.49ms |

| 隐藏地面背景，保留角色、怪物和火焰 | 6.50ms | 494 | 2.14ms |

草丛在本次排查中影响最明显。隐藏草丛节省的约 4.13ms 是诊断开关的差值，不是保留全部草丛后必然能获得的收益。关闭火焰约节省 1.81ms，同样不能当成精确的 GPU 用时。

当前 Compatibility/ANGLE 后端的视口 GPU 计时返回 0，不能解读为没有 GPU 消耗，也不能据此将全部差值归因于着色器或驱动。将火焰替换为纯色未显示收益，所以不优先削减噪声、颜色和火苗造型。像素网格与 18fps 动画步进没有降低实际逐帧着色频率。

上述为历史审阅样本；30 怪 V1/V3 的 FPS 为 81.5/75.4，本次外观接入不能称为性能提升。后续每项优化都需要在当前正式版本重新建立基准。

## 实施顺序

### 0. 建立可复现的正式基准

复用火焰实战测试场景，固定分辨率、怪物种类、随机种子、初始站位与玩家运动路线。分别测试 30、120、300 怪，以及此前满级木质弓箭、额外 +3 投射物、分裂与闪电链的压力组合。额外保留无附魔对照，以区分场景成本和法术成本。

每组预热至少 10 秒，采样 30 秒，运行至少 5 轮并交替先后顺序。记录平均 FPS、P50/P95/P99 帧时间、实际绘制调用、节点数、火舌数、CPU 粒子数和关键 CPU 范围。性能采样期间不录屏；外观录制另跑。GPU 自动测试继续使用私有桌面，不影响用户当前窗口。对后台程序占用和渲染后端作记录，不把跨环境结果直接比较。

除固定画面外，还要覆盖持续移动穿越地图分块、首次释放法术和密集战斗，观察分块生成、首次材质加载及实例扩容带来的长帧。

### 1. 草丛绘制合批——最高优先级

**现状。** `meadow_battle_backdrop.gd` 已使用共享图集、共享材质和按分块生成的布局，没有每株草的独立脚本；但每簇草仍是一个 Sprite2D，参与 `RootDepthSort` 的 Y 排序。本机实测隐藏草丛减少了 1022 次绘制调用。只重复“共享图集”不会解决现有问题。

**实现方向。** 保留 256px 地图分块、已有草丛生成位置、密度、尺寸、颜色和图集区域；将静态草簇合成 ArrayMesh 或 MultiMesh。通过顶点颜色/实例数据传入原先的地面混色和根部参数，避免每簇创建独立材质。只在分块生成、淘汰或布局变化时重建静态数据。

**遮挡处理。** 不能把整屏草丛合成一个固定 Y 值的批次。先验证按根部 Y 行合批的保守版本，再比较 8px/16px 深度带。角色、石块等遮挡对象附近需要拆分前后批次或保留精确排序，避免人物走过草丛时整片草突然翻到前面。现有玩家视觉挂在背景排序节点下，重构时必须保留挂接、坐标偏移和退出恢复。

**验收。** 草丛位置、密度、色彩和接触阴影保持原样；角色与石块前后遮挡、地平线过渡不出错。先以同一快照总绘制调用下降至少 50% 作为工程目标，再看实战 P95/P99 是否稳定改善。该目标待验证，不承诺固定 FPS 收益。若粗深度带有可见跳层，采用精确行批次。

### 2. 状态视觉改为变化时更新——次优先级

**现状。** `enemy_status_visual.gd` 已避免无状态时重复重建图形，但依然逐帧查询多个字符串状态。120 怪这部分约 0.572ms/帧。

**实现方向。** 为视觉状态引入位掩码或版本号；在 `apply_burning`、`clear_burning`、状态过期、圣焰/暗焰切换等入口统一通知视觉。普通火苗只在进入/退出燃烧时创建和释放，持续刷新只更新必要参数。湿润、冻结等有动画的图标保留原有视觉刷新频率；不要把持续伤害的物理更新频率一起降低。

**风险与验收。** 排查直接修改状态字段的路径，包括受击消耗光状态、死亡、复活和重新初始化。验证普通火焰↔圣焰/暗焰、燃烧刷新、状态同时存在、暂停及退出后不留残影。目标是明显减少状态查询和空转处理；伤害次数、持续时间和状态反应必须完全一致。

### 3. 火焰实例数据缓存——较低风险的局部优化

**现状。** 火焰已经只有三个绘制批次。约 0.377ms/帧的 CPU 更新中，提交约 0.044ms，大部分在遍历、字典取值、矩阵计算和缓冲区写入。

**实现方向。** 按图层维护连续实例槽位和缓存数据；尺寸、颜色、相位仅在变化时重写。地面火场在位置/范围未变时复用数据，移动小怪和火种继续按显示帧率更新位置。减少每层重新扫描全部来源的次数，并用计时确认 PackedFloat32Array 的写时复制没有造成新的整块拷贝。

可加入带余量的视口裁剪，只省略看不到的火焰实例；火场碰撞、燃烧伤害和状态持续时间仍正常推进。退出视野再进入不能重置火焰相位或丢失效果。

**验收。** 保持 V3 的三火舌/单火舌数量、2px/3px 网格、颜色和相位；高速移动时火苗跟脚，暂停时冻结，切场景后资源释放。先以实例更新 CPU 比基准下降 30% 为测量目标；不要通过每秒只更新 18 次位置制造拖影。

### 4. 再评估怪物处理与火焰渲染路径

怪物物理处理约 2ms/帧，但正式代码已包含属性缓存和接触碰撞的包围盒提前排除。先测剩余热点，再考虑更精细的查询缓存、接触候选筛选和伤害数字复用；不能通过降低移动碰撞频率或改变燃烧结算次数获得表面收益。

火焰噪声简化、颜色削减、预烘焙动画图集与切换渲染后端都放在后面。纯色开关没有改善当前快照，先做图集会有视觉一致性和内存成本，却未必解决主因。若前述优化后火焰仍占主要耗时，再单独评估紧凑网格减少透明区域、预烘焙帧与动态着色器的对照；切换后端也要作为独立实验，不能只为取得 GPU 计时就改变正式配置。

## 交付方式

每阶段单独保留基准、数据、实机录像与可回退改动。先做草丛合批试作并审阅遮挡效果，再落正式；随后逐项做状态视觉和火焰数据缓存。只有连续多轮收益超过运行波动、P95/P99 没有倒退且外观/玩法验收通过，才标记该阶段优化完成。

本次仅将用户确认的 V3 火焰接入正式资源，未实施上述背景或性能重构。
