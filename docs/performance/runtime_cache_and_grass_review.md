- `enemy_status_visual.gd`：只在版本变化时重新计算视觉状态、创建/移除普通火苗。动画时钟持续推进，其他状态图标沿用原有 12fps 重绘节奏。
- `pixel_fire_visual.gd`：缓存实例槽位、图层、扩容代次、几何版本、变换与颜色；静止实例复用数据，移动实例继续逐帧更新变换。隐藏、重现、槽位压缩和缓冲扩容均会正确失效缓存。
- `runtime_visual_cache_test.gd/.tscn`：23 项回归检查。

保留正式 V3 外观：小怪一个窄火舌，火场一个中宽火舌加左右两个窄火舌。着色器、噪声、颜色、火星和动画速率未修改。曾尝试节流时间参数，但 CPU 与 shader 在浮点边界处出现动画帧差异，未采用该项。

## 是否只绘制玩家视野内草簇

可行，但已有实现会按镜头加载 256px 分块，Godot 也会裁掉屏幕外 Sprite2D。额外隐藏视野外草簇时，保留了 64px 余量，固定场景截图逐像素一致，绘制调用仍为 1271 次。冻结同一场景、正序与逆序各测一次，FPS 为原版 120.2/122.1、隐藏版 129.4/132.4。这说明可能减少 CPU 可见节点处理，不能解释成屏幕外草簇原本都在 GPU 上绘制。

本次只做对照，没有将逐帧扫描所有草簇的实验代码接入正式工程。后续应按镜头范围和分块增量管理可见性。

## 草簇合批试作：未采用

合批把多簇草的原始图集矩形、UV 和颜色装入少量 ArrayMesh；共享原材质。草簇密度、位置和资产不变，但动态前后遮挡需要单独处理。

第一版按 8px 深度带合批，在角色、石块处拆分，固定场景绘制调用从 1271 降到 336。两轮冻结场景 FPS 从 120.2/122.1 到 216.5/218.4。加载 4553 簇草，视野加余量内 1413，使用 107 个批次。固定截图仅有少量像素不超过 1/255 的色值变化。

实战出现反效果：玩家移动时反复拆分与重建网格，三轮平均约 31.0 FPS。第二版复用了静态深度带，仅更新角色所在深度带，但加载范围改变时仍重建过多数据，单轮 49.6 FPS、P99 149.78ms。两版都低于原版，不接入正式工程。

第二版还完成 120 组同状态配对截图，手动同步移动玩家与顶层 Camera2D，跨过 21 次加载分块范围变化。布局签名始终一致；119 帧最大色值差不超过 1，另 1 帧有 20 个像素出现超过 1 的差异，位于角色脚边草的遮挡。故不能声称画面完全等价。动图以 20fps 回放同一冻结战斗快照，HUD 中的 FPS 已冻结，不能用于性能判断。

试作保留原草簇节点用于切换对照；因此也未实现最终的节点内存削减。

后续方向：按地图分块增量生成/回收网格，复用未变化的缓存；将静态草数据与角色附近精确排序解耦。先解决遮挡差异、分块长帧，再考虑正式替换。

## 性能数据与边界

实战配置：同机、1152×648、120 只高生命移动小怪、正式虚空猎刃 + 火焰附魔，角色自动绕行；关闭垂直同步与帧率上限。每轮预热 5 秒、采样 12 秒，期间不录屏。原版/正式缓存候选/第一版合批各 3 轮交替运行；第二版合批仅 1 轮排错样本。固定初始随机种子与路线不代表两次实时战斗逐帧完全相同。

| 版本 | 各轮平均 FPS | P95 中位数 | P99 中位数 | 平均绘制调用 |
| --- | --- | ---: | ---: | ---: |
| 原版 | 61.0 / 59.4 / 59.5 | 20.40ms | 46.55ms | 1623 |
| 正式缓存候选 | 61.6 / 56.4 / 60.9 | 19.74ms | 47.72ms | 1623 |
| 第一版草簇合批 | 32.1 / 29.7 / 31.2 | 49.47ms | 77.76ms | 656 |
| 第二版静态缓存合批 | 49.6 | 26.39ms | 149.78ms | 644 |

原版与正式缓存候选三轮平均 FPS 分别为 59.96 / 59.64，总体持平，不能宣称整局 FPS 提升。这是短样本工程排查，没有完成上一份计划提出的 5 轮 × 30 秒、多规模和多附魔完整基准。

性能对照使用任务开始时的独立项目快照。工作期间正式目录另有怪物素材、武器配置等并行改动，未覆盖这些文件，也未将其混入前后性能对照；接入后的正式目录另行完成下述功能验证。

另做同步 CPU 工作量测试：120 只普通燃烧怪、24 个三火舌火场；每组 300 次，6 组取组均值中位数。

| 局部调用 | 之前 | 之后 |
| --- | ---: | ---: |
| 120 怪状态视觉更新 | 0.403ms | 0.075ms |
| 静止火焰实例整理 | 0.206ms | 0.142ms |
| 120 怪火焰移动时实例整理 | 0.228ms | 0.241ms |

状态视觉约减少 81%，静态火焰整理减少 31%；移动火焰约增加 6%，缓存检查本身有成本。该测试不包含怪物状态计时等物理逻辑，也不是整帧 CPU/GPU 计时。火焰缓存主要对静态火场有效。
