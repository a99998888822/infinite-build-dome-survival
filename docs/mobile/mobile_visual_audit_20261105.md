# 移动端页面检查（2026-11-05）

结论：当前项目已有移动端适配，核心流程大多能显示，但还不能认为所有页面正常。天赋节点遮挡、利息回执重叠，以及设置和结算内容区的触屏拖动问题需要优先处理。

本次只检查并记录，没有修改生产 UI。检查基于当前工作区（分支 `feat/mobile-adaptation`，HEAD `1a6f524`），包含工作区原有的未提交修改。

## 检查范围与证据

- Godot 4.7.1，开启 `--mobile-ui`，中文界面，UI 缩放 1.45。
- 横屏 1920×1080（16:9）和 2400×1080（20:9），每种比例 41 个页面状态，共 82 张实际 GPU 截图。
- 使用项目真实页面和临时数据，覆盖多件装备、8 个附魔、出售确认、贷款、快捷附魔、挑战与三种结算状态。
- 同时检查控件边界，并注入触屏事件测试部分内容区拖动。截图中的滚动到底状态有一部分由脚本设置滚动值，不能用来证明手指拖动正常。
- GPU 检查通过私有 Windows 桌面执行，四次最终捕获均确认引擎处于指定桌面，`foreground_samples=0`，退出码均为 0。

[逐页截图对照图库](../../tmp/mobile_audit_review/index.html) · [问题截图拼图](../../tmp/mobile_audit_review/issues.jpg)

这里的“基本正常”指本次分辨率下未看到明显遮挡、溢出，关键按钮在屏幕内，不代表已经完成全部交互验收。此次为桌面引擎模拟，未覆盖 Android/iOS 真机、刘海安全区、系统软键盘、实际屏幕尺寸与英文界面；竖屏也不在此次结论内。

## 优先处理的问题

### 1. 天赋树被右侧汇总面板遮住

[16:9 截图](../../tmp/mobile_pages_final_16x9/04_talents.png) · [20:9 截图](../../tmp/mobile_pages_final_20x9/04_talents.png)

右侧面板保持约 503 个逻辑像素宽，但树的摆放没有为它留出独立区域。在 16:9 下，“遗物幸运”“掉落率”等节点落在汇总面板后方，另一些节点只露出一部分；20:9 仍有最右节点被挡。顶部“天赋点”与重置按钮也相挤。

定位：`scripts/ui/camp_blueprint_ui_controller.gd:232` 的 `_layout_content()`，面板尺寸在第 240 行，树位置在第 261 行。该页输入逻辑目前主要是鼠标滚轮和鼠标拖动，尚需为手机提供明确的触屏平移、缩放操作与提示。

建议先为树和汇总面板划分不重叠区域，或在手机上将汇总改成按需展开的面板，再验证节点是否可点。

### 2. 设置和结算的内容区手指拖动未产生滚动

注入一段向上移动 150 个逻辑像素的 `ScreenTouch` / `ScreenDrag` 手势，结果如下：

| 内容区 | 16:9 可滚动距离 / 手势后位置 | 20:9 可滚动距离 / 手势后位置 |
| --- | --- | --- |
| 主菜单常规设置 | 287.5 / 0 | 279.2 / 0 |
| 属性抽屉（对照） | 492 / 150 | 492 / 150 |
| 结算主内容区 | 107.2 / 0 | 107.2 / 0 |

证据：[16:9 手势记录](../../tmp/mobile_pages_final_16x9/gestures.json)、[20:9 手势记录](../../tmp/mobile_pages_final_20x9/gestures.json)。附魔外层容器没有纵向溢出，因此其滚动位置为 0 不计为失败。

设置和结算下方确有内容需要滚动查看。当前测试说明“在所测内容位置拖动不生效”，不能据此断言所有滚动方式都不可用；滚动条拖动仍需另行核验。

定位：`scripts/ui/game_settings_panel.gd:85`、`scripts/ui/run_settlement_panel.gd:73`。需要排查控件对子触屏事件的拦截及滚动转发，并在内容文字、空白区、按钮附近分别测试，不能仅根据容器类型推断原因。

### 3. 利息回执出现文字重叠与超框

[16:9 截图](../../tmp/mobile_pages_final_16x9/21_interest_receipt.png) · [20:9 截图](../../tmp/mobile_pages_final_20x9/21_interest_receipt.png)

大金额与“实际到账”重叠，两种比例均可见。16:9 的“第 1 波 · 利息结算”标题还被最小文字宽度撑到回执边框外。

定位：`scripts/ui/interest_arrival_presentation.gd:180` 的 `arrange()`，尤其第 201–206 行。非紧凑模式金额使用 67 号字体，控件实际最小高度约 68；说明文字相对金额起点只下移 52，形成约 16 个逻辑像素的控件重叠。标题实测宽 315，而该布局预留宽约 292。

建议让金额、说明按实际文字高度顺序排版，并让回执根据可用区域选择紧凑布局。

### 4. 银行对话气泡遮住商品区

[16:9 入场截图](../../tmp/mobile_pages_final_16x9/21_interest_receipt.png) · [20:9 入场截图](../../tmp/mobile_pages_final_20x9/21_interest_receipt.png)

移动模式隐藏银行肖像后，对话气泡仍占据购买标签附近、第一张商品图标上方的区域，造成短暂遮挡。它在入场动画前约 5.2 秒出现，之后会自行消失；`22_goblin_trade` 是快进至 20 秒的状态，因此该张截图已没有气泡。此项属于入场演出期间的布局问题，不是商品持续无法访问。

定位：`scripts/ui/finance_popup.gd:630` 的 `_layout()`（第 658 行附近隐藏头部），以及 `scripts/ui/goblin_trade_presentation.gd:134` 的 `arrange()`。建议在移动布局为气泡保留独立区域，或调整它的显示时机。

## 其余适配缺口

- **设置及操作提示仍偏桌面。** 战斗设置包含右键移动、WASD、数字键与鼠标左右键等配置；暂停页也仍出现 ESC 等提示。布局装得下，但对手机玩家不够清楚。定位：`scripts/ui/game_settings_panel.gd:247`、`:394`，以及 `scripts/ui/esc_overlay.gd` 的底部提示。
- **奖励卡片及点击目标偏小。** [升级奖励](../../tmp/mobile_pages_final_16x9/19_upgrade_rewards.png)、[遗物奖励](../../tmp/mobile_pages_final_16x9/20_relic_rewards.png) 在空余面积较大的面板中仍预留四列、两行槽位。小布局文字为 9–10 逻辑像素，选择按钮约 109×20 逻辑像素，在当前 1080 高截图中约 158×29 像素。应增加字号、点击高度并按实际卡片数量排版；实际物理大小仍需真机确认。定位：`scripts/ui/shop_popup.gd:23`、`:515`，`scripts/ui/reward_option.gd:210`。
- **附魔库存窄屏依赖横向滚动。** [银行附魔](../../tmp/mobile_pages_final_16x9/25_enchantment.png)、[快捷附魔](../../tmp/mobile_extra_16x9/38_quick_enchantment.png) 在多件附魔时右侧卡片被裁切。已有横向滚动条，内容并非完全无法访问；建议手机减少列数，降低纵横同时滚动的操作成本。定位：`scripts/ui/enchantment_workbench.gd:105`，代码明确保留六列。

## 验证结果与限制

- 移动配置自测：17 项检查，0 失败（`tmp/mobile_audit_profile_test.log`）。
- 移动银行自测：16 项检查，0 失败（`tmp/mobile_audit_bank_test.log`）。
- 四次最终 GPU 运行未出现 Parse / Compile / SCRIPT ERROR，已指定的关键控件均通过可见且在屏幕内的几何检查。几何检查不能识别所有兄弟控件遮挡，所以仍以实际截图为依据。
- 运行出现 `_fit_world_viewport` 在父 `SubViewportContainer.stretch=true` 时设置子视口尺寸的警告（`scripts/core/game_root.gd:178`）。本次未确认它造成画面变形，应作为单独运行警告处理。
- 截图数据使用临时会话；库存、天赋解锁与结算数据由检查脚本构造，目的是覆盖页面状态，不代表用户存档。

原始资料位于 `tmp/mobile_pages_final_16x9/`、`tmp/mobile_pages_final_20x9/`、`tmp/mobile_extra_16x9/`、`tmp/mobile_extra_20x9/`。每个目录包含 PNG 与 `geometry.json`；主检查目录另有 `gestures.json`。`tmp/` 被 Git 忽略，分享本报告时需一并打包截图。

复查脚本：`tmp/mobile_pages_audit.gd/.tscn` 与 `tmp/mobile_pages_extra.gd/.tscn`。通过 `scripts/tools/run_godot_background.py` 启动，参数包括 `--mobile-ui --transient-session --window=1920x1080 --capture-dir=<绝对目录>`；20:9 改为 `--window=2400x1080`。正常使用项目时不需要这些检查脚本。
