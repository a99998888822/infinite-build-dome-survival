# 密集伤害受击反馈合并优化

日期：2026-10-19。延续 [伤害次数来源与结算优化判断](damage_settlement_fanout_20261019.md)，本轮实现其中优先级最高的受击表现优化。

**同等 21,804 次伤害的 CPU 压测耗时降低 19.7%；固定反射负载的整帧平均耗时降低 7.2%。完整附魔组合仍存在 192 ms 长帧，尚未达到稳定 60 FPS。** 两组百分比分别来自独立实验，不能相加，也不能套用到历史 675 ms 峰值。

## 实现与行为边界

上一轮已经跳过同帧相同姿态的重复 `_sync()`，但每次命中仍进入 `pulse()`，读取 Sprite 偏移、世界变换和材质。大量命中集中到少量怪物时，这些检查仍被执行数万次。

本轮在 `EnemyController._show_hit_visual()` 入口合并重复工作：首次命中立即启动闪白和抖动，标记该怪物待同步；同一 idle 批次内的后续命中走简短判断；通过共享延迟队列，在渲染前按最终动画变换补一次姿态同步。普通的连续 100 次命中因此只调用一次 `pulse()`，随后补一次 `_sync()`。

队列按 idle 批次收尾；一个绘制帧可能包含多个物理步骤或队列批次，因此不承诺严格“每帧只同步一次”。命中之间发生材质替换、视觉停用或重置时，会重新启动反馈。补同步不会重新计时，也不会覆盖最后一次伤害之后安装的材质；晚于霸体描边处理的命中会同步描边位置。初始化、视觉重置和退出会取消旧标记，队列跳过已释放或待删除的怪物。

正式伤害公式、逐次扣血、光状态消费、伤害通知顺序、随机数消费、死亡处理和打击停顿规则保持原样。没有减少真实命中数，也没有将多次伤害相加后一次结算。

涉及正式代码：

- `scripts/enemies/enemy_controller.gd`：入口快速判断、首次即时反馈和批次收尾。
- `scripts/effects/enemy_hit_visual_queue.gd`：共享延迟同步队列。
- `scripts/effects/enemy_hit_visual.gd`：重置时取消怪物的待同步标记。

## 同等伤害量 CPU 压测

96 个真实怪物，连续提交 21,804 次攻击，按 ABBA BAAB 顺序运行 8 轮，前后各 4 轮；A 为本轮之前的受击实现。每轮均为 **21,804 次命中、763,140 点伤害**，伤害通知顺序校验值、最终生命值、受击姿态、下一次随机数和跳字数量完全一致。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 平均 CPU 耗时，包含队列收尾 | 570.277 ms | 458.043 ms |
| 其中队列收尾耗时 | 0.007 ms | 0.775 ms |
| 各轮总耗时 | 571.549 / 591.496 / 531.824 / 586.237 ms | 467.224 / 465.228 / 457.794 / 441.925 ms |

平均降低 **19.68%**。计时包含真实扣血、跳字、受击表现、测量及通知校验回调，是同步突发的 CPU 压测，**不是日常完整战斗帧，也不能直接与历史伤害回调的 216.477 ms 比较**。延迟同步的时间已算入总成本，没有把工作移出计时区间。

## 固定反射负载的真实渲染对照

Godot 4.7.2，1920×1080，Intel Arc / ANGLE D3D11；96 个静止真实怪物、1,280 束反射、60 个固定模拟步骤。两侧使用相同的当前反射实现和真实加载预热，只切换受击实现；关闭打击停顿。8 轮采用 ABBA BAAB，前后各采样 240 帧。

每轮均为 **76,800 次命中、2,688,000 点伤害、顺序校验值 1426651616**；最终生命值、逐步存活反射数与命中数、视觉等级数量一致。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 平均整帧 | 44.534 ms | 41.321 ms |
| P95 | 72.941 ms | 71.795 ms |
| P99 | 94.963 ms | 78.310 ms |
| 最大帧 | 358.208 ms | 79.905 ms |
| 超过 33.33 ms | 165 / 240 | 152 / 240 |
| 超过 50 ms | 99 / 240 | 85 / 240 |
| 超过 100 ms | 2 / 240 | 0 / 240 |
| 平均伤害回调耗时 | 7.751 ms | 6.286 ms |

平均整帧降低 **7.21%**，伤害回调降低 **18.90%**，P95 仅降低 **1.57%**。各轮整帧表现仍有波动，并非每轮优化后都更快；整帧平均差异也受到优化前首轮长帧影响。

优化前的 358.208 ms 峰值中，渲染前区间为 83.077 ms、渲染阶段区间为 275.225 ms，不能把全部峰值差额归因于受击逻辑。此轮优化后没有采样到超过 100 ms 的帧，只说明这次固定负载的结果，不能证明低频尖峰已彻底消失。

## 完整组合与剩余长帧

另用正式等离子球 + 水 + 冰 + 光剑组合运行 12 秒，保留打击停顿，记录到 2 次施法、82,819 次命中。872 个采样帧中有 575 帧处于打击停顿，反射数量快照最高 2,570 束；12 帧超过 100 ms，最大 **192.367 ms**。

峰值帧有 5,278 次扣血，伤害回调累计 25.487 ms，背景回调 1.152 ms、怪物回调 6.203 ms。这些是局部测量，不能将各类监视器读数简单相加或相减来分摊整帧；本次没有启用逐束反射计时，`reflection_ms = 0` 不代表反射没有成本。

本次实际生成量和历史 4,681 束反射、675.099 ms 峰值不同，**不计算这两个峰值之间的优化百分比**。后续应继续定位数千反射实例的更新、批量范围命中、节点创建与回收，以及伤害通知和跳字准入中的重复工作。草簇和怪物回调在本次峰值的测量区间较小，不能据此把所有场景中的地形或怪物逻辑排除。

像素测试经过真实敌人的扣血入口，比较旧实现与新实现；6 个场景的裁剪像素完全一致，覆盖晚时序命中、旋转缩放、材质前后替换、手动重置、精英仅抖动和霸体对齐。伤害死亡当帧、首次即时反馈、初始化取消、删除清理也有独立验证。

试验中曾将补同步放到 `RenderingServer.frame_pre_draw`，发现它晚于 Sprite2D 的画布重绘提交：内存姿态正确，画面仍可能晚一帧。该原型被像素测试检出并修正；最终使用延迟 idle 队列，38 项渲染检查通过。报告目录保留的早期失败日志不是最终实现的测试结果。

最终编辑器 headless 检查没有解析或编译错误，仅有现有 Android build-tools 目录提示；上述回归错误日志为空。所有本轮最终 GPU 检查均在私有 Windows 桌面运行，实际桌面与指定桌面一致，`foreground_samples = 0`，退出码为 0。

补充 Bootstrap 120 帧 headless 检查：退出码 0，数据自检通过，验证错误与验证警告计数均为 0。stderr 有重复购买武器及负载超限的两条拒绝操作警告，来自自检主动验证失败分支；本次没有出现资源残留退出报错。详见 `artifacts/reports/hit_pose_final_bootstrap.log` 与对应 `_errors.log`。
