# 局外营地与成长模块详细设计方案

本文档定义“局外营地与成长模块”的数据结构、界面流程、建筑升级逻辑、局外成长接口和存档联动方式。它只负责“战斗结束后回到营地、在营地里做成长决策、把成长结果带回下一局”，不负责战斗中的实时逻辑，也不负责自由摆放、生产链、居民管理或资源采集。

营地表现采用最简双态显示：仅对“需要解锁的建筑”使用废墟 / 正式建筑双态；初始自带建筑直接显示正式建筑，不需要废墟图。营地场景本身可以由草地、河流、树木、石头、花草等分层素材拼成，不要求单张大底图。

## 1. 模块目标

1. 提供一个固定的局外营地入口，承接角色选择页和战斗开始页之间的流程。
2. 提供建筑等级与建筑升级选项两套成长路径。
3. 提供武器、遗物、召唤、伤害、防御、掉落等方向的局外成长入口。
4. 提供存档读写接口，把营地成长稳定保存到本地。
5. 为后续新增建筑、新增成长项、新增解锁门槛保留扩展口。
6. 支持同一营地场景中按建筑解锁状态切换“废墟/建筑”两种表现。

## 2. 模块边界

### 2.1 本模块负责

1. 营地主界面与建筑入口。
2. 建筑等级状态读取与保存。
3. 建筑等级效果的结算与注入。
4. 建筑升级选项的展示、购买、等级上限和花费结算。
5. 局外解锁状态管理。
6. 战斗结算后资源回流到营地。

### 2.2 本模块不负责

1. 战斗中的敌人 AI。
2. 武器自动攻击。
3. 遗物战斗期效果的具体计算。
4. 经验球、金币、掉落物的场景表现。
5. 营地自由建造、拖拽摆放、路径经营。
6. 角色技能树的独立树状养成。

## 3. 核心流程

### 3.1 主流程

推荐主流程保持为：`角色选择页面 -> 营地 -> 开始战斗`。

### 3.2 战斗结束后的回流流程

1. 战斗模块发出结算结果。
2. 营地模块接收局内货币、解锁项、掉落项和统计数据。
3. 营地模块更新存档中的建筑等级、升级项等级和解锁状态。
4. 玩家进入营地查看本次可升级内容。
5. 玩家确认后点击开始战斗，携带新的成长结果进入下一局。

### 3.3 战斗开始前的出战流程

1. 读取当前选中的角色。
2. 读取营地建筑提供的永久解锁与全局加成。
3. 读取已购买的建筑升级项。
4. 生成本局初始武器、初始遗物可见池和起始参数。
5. 进入战斗场景。

## 4. 营地数据模型

### 4.1 存档中的营地状态

建议营地存档至少包含以下字段：

| 字段 | 说明 |
| ---- | ---- |
| `building_levels` | 建筑当前等级，key 为建筑 ID |
| `upgrade_levels` | 升级选项当前等级，key 为升级项 ID |
| `unlocks` | 已解锁的武器库、遗物库、特殊槽位、模式等 |
| `records` | 局外纪录，例如最高波次、通关次数、击杀数 |
| `camp_currency` | 局外营地可用货币 |
| `selected_character_id` | 当前角色选择 |
| `selected_start_weapons` | 开局武器选择结果 |

### 4.2 营地运行时状态

建议运行时只维护三类状态：

1. 当前正在显示的建筑 ID。
2. 当前建筑下可购买的升级项列表。
3. 当前营地资源余额和解锁状态快照。

### 4.3 配置文件依赖

本模块直接依赖：

1. `data_config/camp_buildings.json`
2. `data_config/weapons.json`
3. `data_config/relics.json`
4. `data_config/characters.json`
5. `data_config/bonds.json`
6. `data_config/waves.json`
7. `data_config/drop_tables.json`

## 5. 设计原则

1. 固定营地，不做自由摆放。
2. 建筑等级与升级选项分开管理。
3. 新增成长内容优先走配置，不优先改代码。
4. 成长效果统一转成 `Modifier` 或解锁标记，不在 UI 层直接改数值。
5. 营地模块只负责“能看见、能买、能存、能恢复”，不直接耦合局内具体战斗表现。

## 6. 建筑系统

### 6.0 表现规则

1. 需要解锁的建筑只维护两种显示资源：废墟素材和正式建筑素材。
2. 未解锁时显示废墟素材。
3. 解锁后显示正式建筑素材。
4. 初始自带建筑只维护正式建筑素材，不需要废墟图。
5. 之后如果有建筑升级，也只在正式建筑素材基础上继续扩展，不改变这套切换规则。

当前营地共 8 个建筑，分为两类：

### 6.1 建筑等级型

这类建筑的主要作用是“建筑本身升级后直接生效”。

1. `camp_armory_workshop` 军械工坊
   - 初始自带。
   - 作用：武器图鉴解锁、武器基础强化。
   - 1 级：解锁基础近战武器。
   - 2 级：解锁远程武器库，全局伤害加成。
   - 3 级：解锁稀有武器，全局攻击速度提升。
   - 4 级：解锁特殊武器槽。
   - 5 级：解锁传说武器图纸，全局冷却缩减提升。

2. `camp_relic_archive` 遗物档案馆
   - 初始自带。
   - 作用：遗物图鉴解锁、遗物套装预览。
   - 1 级：解锁全部普通遗物库。
   - 2 级：解锁全部稀有遗物。
   - 3 级：解锁全部史诗遗物。
   - 4 级：虚空侵蚀阶段，解锁虚空遗物。
   - 5 级：解锁全部传说遗物。

### 6.2 升级选项型

这类建筑主要负责“解锁一批可购买升级项”，本身升级后通常不会直接给大量数值，而是开放新的成长入口。

3. `camp_blade_arena` 利刃演武场
   - 近战专属营地建筑。
   - 解锁近战伤害、通用伤害、攻速、冷却缩减、暴击率、暴击伤害升级项。

4. `camp_farstar_range` 远星射靶台
   - 远程专属营地建筑。
   - 解锁远程伤害、投射物数量、穿透次数、范围、攻击范围、冷却相关升级项。
   - 说明：攻击范围只使用 `area_size` 这一项，不再额外维护其它范围字段。

5. `camp_kin_nursery` 眷族培育栏
   - 召唤体系强化建筑。
   - 解锁眷族伤害、召唤相关成长项。
   - 作为召唤流的局外入口。

6. `camp_mutation_laboratory` 畸变研究所
   - DOT 持续伤害体系强化建筑。
   - 解锁范围倍率、持续时间、减速效果、控制强度、腐化类词条。
   - 作为异常/控制/持续伤害方向的局外入口。

7. `camp_dome_shelter` 穹顶庇护所
   - 生存防御类平衡建筑。
   - 解锁最大生命、每秒回血、护盾值、护甲值、移动速度升级项。
   - 用于补足脆皮流和前期开荒容错。

8. `camp_council_hall` 议事大厅
   - 通用成长与套装强化建筑。
   - 解锁拾取范围、经验获取倍率、掉落率倍率、幸运、局内/结算货币获取倍率、理财、利率等升级项。
   - 用于提升整体经济与局外收益。

## 7. 建筑数据结构

### 7.1 建筑基础字段

建议 `camp_buildings.json` 中每个建筑至少包含：

| 字段 | 说明 |
| ---- | ---- |
| `id` | 建筑唯一 ID |
| `name` | 建筑显示名 |
| `initial_unlocked` | 是否初始自带 |
| `type` | 建筑类型，例如 `human`、`mixed`、`void` |
| `role` | 建筑核心定位 |
| `description` | 建筑描述 |
| `unlock_condition` | 建筑解锁条件，可选 |
| `levels` | 建筑等级效果 |
| `upgrade_options` | 建筑开放的升级选项 |

### 7.2 建筑等级效果

`levels` 适用于“建筑本体升级”。支持三种效果：

1. `unlock`：解锁武器库、遗物库、特殊槽位、系统权限等。
2. `stat/value`：直接提供全局属性加成。
3. `stage`：标记阶段状态，例如虚空侵蚀阶段。

### 7.3 升级选项

`upgrade_options` 适用于“可重复购买的局外成长项”。建议字段：

| 字段 | 说明 |
| ---- | ---- |
| `id` | 升级项 ID |
| `name` | 升级项显示名 |
| `stat` | 对应属性 ID |
| `currency` | 消耗货币类型 |
| `cost` | 每级固定花费 |
| `max_level` | 最大购买等级 |
| `value_per_level` | 每级增量 |

规则：

1. 每级花费固定。
2. 达到 `max_level` 后不再可买。
3. 玩家当前等级只记录在存档，不写死在配置里。
4. 只允许使用 `StatDefinitions` 中已存在的属性 ID。

## 8. 局外成长接口

### 8.1 属性类成长

由建筑升级项直接提供，统一转成 `Modifier` 或百分比修正。

### 8.2 解锁类成长

用于开放武器池、遗物池、特殊槽位、图鉴、难度层、后续营地功能。

### 8.3 经济类成长

用于提升局内/结算货币获取、经验收益、掉落收益和理财收益。

### 8.4 选择类成长

用于扩大可选武器、遗物、开局道具、免费升级次数等决策空间。

## 9. 存档与恢复

### 9.1 保存时机

1. 战斗结算后。
2. 营地建筑升级购买后。
3. 解锁状态变化后。
4. 进入战斗前重新整理出战配置后。

### 9.2 恢复时机

1. 游戏启动时。
2. 进入营地时。
3. 进入战斗前重新读取当前局外状态。

### 9.3 恢复内容

1. 建筑等级。
2. 升级项等级。
3. 已解锁武器、遗物和槽位。
4. 营地货币余额。
5. 结算纪录。

## 10. 与其他模块的接口

### 10.1 与玩家与角色模块

1. 营地决定出战角色和出战初始武器。
2. 营地提供角色外部成长修正。
3. 角色选择页只负责选角色，营地负责把成长结果组装成战斗初始状态。

### 10.2 与局内武器模块

1. 军械工坊决定武器池开放范围。
2. 升级项影响武器关键属性，但不直接写死到武器配置。

### 10.3 与局内遗物与羁绊模块

1. 遗物档案馆决定遗物池开放范围。
2. 套装、羁绊和遗物搜集结果都要回流到营地存档。

### 10.4 与敌人与波次模块

1. 波次结算结果进入营地。
2. 局内金币、经验、掉落统计都由营地接收并展示。

## 11. MVP 范围

MVP 阶段建议只做：

1. 固定营地主界面。
2. 8 个建筑的静态展示。
3. 建筑等级读取与显示。
4. 升级选项列表展示。
5. 购买升级项和保存存档。
6. 从营地进入战斗的出战数据组装。

暂不做：

1. 自由建造。
2. 居民经营。
3. 资源采集链。
4. 复杂交互动画。
5. 多页面经营大地图。

## 12. 扩展原则

1. 新建筑优先加配置，不优先改流程代码。
2. 新升级项只要对应 stat 已存在，就能直接接入。
3. 新增存档字段必须可兼容旧版本。
4. 新增建筑效果优先通过 `ModifierStack` 结算。
5. 营地功能永远保持“局外入口”定位，不向战斗内侵蚀复杂逻辑。

## 13. 结项判断

本模块可视为完成的条件：

1. 能从角色选择页进入营地。
2. 能从营地开始战斗。
3. 能读取并保存建筑等级与升级项等级。
4. 能展示并购买建筑升级项。
5. 能把成长结果稳定带入下一局。
