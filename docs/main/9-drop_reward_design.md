# 掉落与奖励模块详细设计方案

本文档定义局内掉落、经验球、金币结算、升级候选、商店候选与最终战斗结算输出。它只负责“敌人死亡后掉什么、波次结束后怎么收、升级或商店时给什么选项、死亡或通关后给多少局外货币”，不负责敌人 AI、武器命中、UI 排版和存档落盘。

## 1. 模块目标

1. 建立统一的掉落与奖励入口。
2. 支持敌人死亡后按掉落表生成经验球与其他奖励。
3. 支持波次结束后统一吸取、结算和清场。
4. 支持免费奖励与商店候选池生成。
5. 为波次流程提供局内奖励快照。
6. 为死亡或通关提供最终局外结算结果。

## 2. 模块边界

### 2.1 本模块负责

1. 掉落表读取与校验。
2. 经验球、金币和临时奖励的生成。
3. 敌人死亡后的掉落请求分发。
4. 波次结束后的统一收集与结算。
5. 免费奖励入口与付费商店入口的候选池生成。
6. 奖励结算快照输出。

### 2.2 本模块不负责

1. 敌人移动、追踪、受击和死亡判定。
2. 玩家移动、战斗表现和动画。
3. 武器伤害计算与索敌实现。
4. UI 节点布局与视觉效果。
5. 存档落盘与营地建筑升级规则。

## 3. 设计原则

1. 配置驱动：掉落与奖励都必须能从 `data_config/*.json` 读取。
2. 结果优先：本模块返回的是奖励结果和候选池，不直接决定 UI 长相。
3. 候选池复用：免费奖励入口与付费商店入口共用同一套池子规则。
4. 类型分离：掉落、升级奖励、商店候选池分开定义，避免互相缠绕。
5. MVP 优先：先做经验球、金币、三类共享奖励，再扩展稀有奖励。

## 4. 数据结构

### 4.1 `drop_tables.json` 最小字段

```json
{
  "id": "drop_basic_enemy",
  "display_name": "普通敌人掉落",
  "enabled": true,
  "tags": ["enemy", "normal"],
  "entries": [
    {
      "type": "exp_orb",
      "chance_percent": 100,
      "amount": 4
    }
  ]
}
```

### 4.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | String | 是 | 掉落表唯一 ID |
| `display_name` | String | 否 | 掉落表显示名 |
| `enabled` | bool | 否 | 是否启用 |
| `tags` | Array[String] | 否 | 用于统计与筛选 |
| `entries` | Array | 是 | 掉落条目列表 |

### 4.3 掉落条目字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `type` | String | 是 | 条目类型，例如 `exp_orb`、`currency`、`weapon_token` |
| `chance_percent` | int/float | 是 | 触发概率，0~100 |
| `amount` | int | 否 | 固定数量，MVP 阶段优先使用 |
| `spawn_offset` | Vector2/Dictionary | 否 | 掉落相对位置偏移 |
| `tags` | Array[String] | 否 | 统计与扩展标签 |

### 4.4 波次局内快照结构

建议在每波结束时输出如下局内快照。该快照只服务于 UI 和下一波流程，不写入存档：

```json
{
  "exp_gained": 18,
  "gold_gained": 18,
  "dropped_orbs": 6,
  "collected_orbs": 6,
  "level_ups": 2,
  "offers_generated": 3
}
```

### 4.5 最终战斗结算结构

只有玩家死亡或通关时才输出最终结算结果，并交给存档模块转换为局外进度：

```json
{
  "result": "defeat",
  "camp_currency_gain": 180
}
```

MVP 不需要 `settlement_id`，也不做结算去重。

### 4.6 商店候选项结构

商店候选项建议统一为字典结构，便于 UI 直接渲染：

```json
{
  "offer_id": "weapon_upgrade:weapon_void_blade:2",
  "offer_type": "weapon_upgrade",
  "rarity": "rare",
  "target_id": "weapon_void_blade",
  "display_name": "虚空刃 升至2级",
  "icon": "res://assets/ui/icons/weapons/weapon_void_blade.png",
  "load_cost": 12,
  "from_level": 1,
  "to_level": 2,
  "effects": []
}
```

## 5. 局内掉落流程

### 5.1 敌人死亡掉落

1. 敌人死亡后向波次模块发出掉落请求。
2. 波次模块读取 `drop_table_id`。
3. 逐条滚动 `entries`，按 `chance_percent` 判断是否触发。
4. 若条目类型为 `exp_orb`，实例化经验球并加入拾取层。
5. 后续如加入金币、材料或特殊 token，也沿同一入口生成。

### 5.2 经验球结算

1. 经验球接触玩家或进入吸附范围后被收取。
2. 经验值和金币同时入账。
3. 经验与金币增量分别受到 `exp_gain_percent` 和 `currency_gain_percent` 影响。
4. 若波次结束仍有经验球未收取，则统一清场前全部吸取；血包等即时拾取物不参与波次收尾吸收。

### 5.3 波次结束结算

1. 停止当前波次刷怪。
2. 统一吸取场上所有经验球，并清理其他奖励拾取物。
3. 结算经验和局内金币。
4. 如果触发升级，则向 UI 输出升级候选并等待选择完成。
5. 结算上一波理财利息。
6. 向 UI 输出局内商店候选。
7. 商店完成后进入理财页面。
8. 玩家选择是否存入当前剩余局内金币。
9. 清空场上敌人和未使用掉落物；仅保留经验球的收尾结算口径。
10. 输出局内波次快照给战斗循环与 UI。

波次结束不写入正式存档；局内金币、理财本金、商店购买和本局武器/遗物都只保存在运行态。

### 5.4 死亡或通关结算

1. 停止战斗循环。
2. 统计本局最终可回流的局外货币。
3. 输出最终战斗结算结果。
4. 存档模块只消费最终结算结果，不读取波次过程。

## 6. 升级与奖励候选池

### 6.1 候选类型

MVP 阶段建议只保留三类：

1. 新武器。
2. 遗物。
3. 武器升级。

不再单独设置“属性升级”候选；免费领取和付费购买只是这三类内容的不同入口。

### 6.2 候选过滤规则

1. 新武器：必须未拥有，且满足解锁条件。
2. 遗物：必须未达到 `max_stack`，且满足解锁条件。
3. 武器升级：必须已装备，且未达到最大等级。
4. 同一轮武器升级选项不得重复同一把武器的同一级升级项。

### 6.3 权重规则

1. 稀有度权重受 `luck` 影响。
2. 新武器权重受剩余 `load_capacity` 影响。
3. 武器升级权重可随未刷出次数提升。
4. 若某一类无候选，则该类权重应直接置零。

### 6.4 免费奖励入口与付费商店入口

1. 免费奖励入口和付费商店入口共用同一套候选池。
2. 各入口只在“是否收费”和“是否消耗购买次数”上不同。
3. 刷新逻辑、稀有度权重和去重规则必须一致。

## 7. 与其他模块的接口

### 7.1 与敌人与波次模块

1. 敌人死亡时提供 `drop_table_id` 和死亡位置。
2. 波次结束时统一触发经验球收取。
3. 波次结算时输出局内快照，不触发存档。
4. 死亡或通关时输出最终结算结果。

### 7.2 与玩家与角色模块

1. 使用玩家的 `pickup_radius` 决定吸附范围。
2. 使用 `exp_gain_percent` 与 `currency_gain_percent` 计算最终收益。
3. 使用 `luck` 影响稀有度权重。
4. 使用 `load_capacity` 影响新武器候选权重。

### 7.3 与局内武器系统模块

1. 候选池需要读取当前已装备武器。
2. 武器升级项必须读取当前等级和最大等级。
3. 购买失败或负载不足由 UI 提示，不在本模块硬编码表现。

### 7.4 与局内遗物与羁绊模块

1. 遗物候选池需要读取已有遗物数量。
2. 达到 `max_stack` 的遗物不应再次出现在候选池中。
3. 羁绊相关奖励只在后续版本扩展。

### 7.5 与 UI 交互模块

1. UI 只接收候选池与奖励快照。
2. UI 不负责重新计算权重。
3. UI 只负责展示、选择和回调确认。
4. UI 侧奖励选项统一复用同一个 `tscn` prefab，不按“武器升级 / 新武器 / 遗物 / 商店购买”拆分不同底图。
5. 奖励选项的按钮文案由入口决定：免费升级奖励显示“选择”，商店购买显示具体花费金额。
6. UI 可直接用节点框架与文本表达分类，不要求独立卡底 PNG。

### 7.6 奖励选项 prefab 约定

奖励选项建议统一成一个可复用 `tscn` prefab，内部节点结构可按下列顺序组织：

1. 顶部边框线：用稀有度颜色区分的长方形外框线。
2. 标题：`武器升级`、`新武器` 或 `遗物`。
3. 图标：内容图标或武器/遗物图标。
4. 名称：奖励名称。
5. 属性描述：效果说明、属性变更或遗物文本。
6. 底部边框线：与顶部一致的框线或分割线。
7. 按钮：免费入口显示“选择”，商店入口显示具体花费金额。

稀有度只影响边框、标题强调色和少量装饰，不影响 prefab 的主体结构。

### 7.7 与局外营地与存档模块

1. 只有死亡或通关后的最终结算奖励回流营地。
2. 波次结束、升级、商店和理财都不触发存档。
3. 营地建筑和存档只消费最终奖励结果，不直接介入掉落计算。

## 8. 场景与脚本建议

### 8.1 当前可复用的实现

1. `scenes/pickups/exp_orb.tscn`：经验球拾取实体。
2. `scenes/pickups/health_pack.tscn`：血包拾取实体。
3. `scripts/pickups/exp_orb.gd`：经验球吸附与收取逻辑。
4. `scripts/pickups/health_pack.gd`：血包吸附、治疗与收取逻辑。
5. `scripts/rewards/drop_reward_system.gd`：掉落表解释、概率处理与奖励生成。
6. `scripts/rewards/reward_snapshot.gd`：奖励结算快照。
7. `scripts/waves/wave_manager.gd`：波次结算、奖励收取与汇总。
8. `scripts/ui/shop_offer_generator.gd`：商店候选池与权重生成器。
9. `scenes/ui/rewards/reward_option.tscn`：奖励 / 商店候选项共用 UI prefab。

### 8.2 后续可选拆分

1. `scripts/rewards/drop_reward_system.gd`：统一掉落表解释器。
2. `scripts/rewards/reward_snapshot.gd`：奖励快照结构化对象。
3. `scripts/rewards/reward_pool_generator.gd`：升级/商店候选池生成器。

## 9. MVP 验收标准

1. 敌人死亡后能按掉落表生成经验球。
2. 经验球能被玩家吸附并结算经验与金币。
3. 波次结束后能统一吸取场上所有经验球。
4. 经验和金币能正确受到玩家百分比加成影响。
5. 升级时能生成新武器、遗物、武器升级三类候选。
6. 候选池能正确过滤已拥有武器和达到上限的遗物。
7. 稀有度与类型权重能根据 `luck`、`load_capacity` 和拥有状态变化。
8. 战斗循环和 UI 能拿到完整局内波次快照。
9. 死亡或通关时能输出最终局外货币结算。

## 10. 结论

本模块优先解决“局内奖励从哪里来、怎么收、怎么选”的问题。等这层稳定后，再继续展开局内战斗循环、区域驻守收割、召唤物和更复杂的奖励类型，会顺很多。
