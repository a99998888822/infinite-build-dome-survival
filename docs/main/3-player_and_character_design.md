# 玩家与角色模块详细设计方案

本文档定义玩家实体、角色基础属性、受击/死亡、拾取范围、角色被动、开局配置与局外解锁的接入方式。它只负责“谁在场上行动、拥有多少基础能力、如何接入数值系统”，不负责武器自动攻击、敌人 AI、掉落表和营地成长规则。

## 1. 模块目标

1. 建立稳定的玩家实体根节点与脚本结构。
2. 统一角色基础属性、被动 modifier 和开局武器配置的读取方式。
3. 统一玩家移动、碰撞、受击、死亡和拾取范围的实现方式。
4. 为后续武器、掉落、召唤物、营地成长模块提供明确接口。
5. 保持玩家逻辑可扩展，支持未来多角色切换与特化构筑。

## 2. 模块边界

### 包含内容

1. 玩家实体场景与脚本。
2. 角色静态配置读取。
3. 玩家基础属性初始化。
4. 移动控制、面向、速度计算。
5. 受击、无敌帧、死亡。
6. 拾取范围与经验球吸附判定。
7. 角色被动转换为 `Modifier`。

### 不包含内容

1. 武器自动攻击与索敌。
2. 敌人 AI 与受击反馈。
3. 掉落生成与概率规则。
4. 羁绊、遗物、营地建筑的具体效果。
5. UI 弹窗和营地界面交互。

## 3. 角色数据结构

角色数据来自 `data_config/characters.json`，当前只保留最小可用字段。

### 推荐字段

```json
{
  "id": "character_void_hunter",
  "display_name": "虚空猎者",
  "description": "默认测试角色。",
  "enabled": true,
  "tags": ["character", "starter"],
  "base_stats": {
    "max_hp": 100,
    "hp_regen": 0,
    "shield": 0,
    "armor": 0,
    "move_speed": 180,
    "load_capacity": 100,
    "pickup_radius": 80,
    "humanity": 100,
    "divinity": 0
  },
  "start_weapons": ["weapon_void_blade"],
  "passive_modifiers": []
}
```

### 字段说明

1. `base_stats`：角色初始基础属性。
2. `start_weapons`：开局携带武器 ID 列表。
3. `passive_modifiers`：角色被动效果，直接写标准 `Modifier` 或由轻量配置展开。

## 4. 玩家实体结构

### 场景建议

```text
player_root.tscn
├─ PlayerRoot (CharacterBody2D)
├─ CollisionShape2D
├─ Sprite2D / AnimatedSprite2D
├─ Hurtbox / PickupArea
└─ VisualAnchor
```

### 节点职责

1. `PlayerRoot`：处理移动、生命、受击、死亡。
2. `CollisionShape2D`：实体碰撞。
3. `Sprite2D`：基础表现。
4. `PickupArea`：经验球、掉落物吸附判定。
5. `VisualAnchor`：后续挂武器、特效、召唤物偏移点。

### 动画方向约定

1. MVP 阶段玩家只制作向右动画。
2. 向左动画由向右动画在 Godot 中水平翻转得到。
3. 暂不制作向上、向下动画，移动时仍使用左右朝向表现。
4. Ludo.ai 生产流程采用“先生成向右单帧精灵，再基于该精灵生成向右多帧动画”。
5. 人物像素精度使用中高精度，不做低像素块状角色。

## 5. 脚本职责

建议脚本：`scripts/player/player_controller.gd`

### 核心职责

1. 读取角色配置并初始化属性。
2. 处理输入移动。
3. 应用 `ModifierStack` 后的最终属性。
4. 处理受击、死亡和复活边界。
5. 向武器、掉落、UI 发送状态变化信号。

### 不建议承担的职责

1. 武器开火逻辑。
2. 掉落概率生成。
3. 敌人索敌判定。
4. 营地成长逻辑。

## 6. 基础属性接入

玩家基础属性分两层：

1. **角色基础值**：来自 `characters.json` 的 `base_stats`。
2. **运行时修正值**：来自角色被动、遗物、羁绊、营地建筑和临时效果。

### 处理顺序

1. 载入角色配置。
2. 创建玩家自己的 `ModifierStack`。
3. 写入 `base_stats`。
4. 叠加角色被动 `Modifier`。
5. 叠加局内来源 `Modifier`。
6. 每次属性变化后刷新当前值。

### 角色当前值建议

1. `current_max_hp`
2. `current_hp`
3. `current_shield`
4. `current_armor`
5. `current_move_speed`
6. `current_pickup_radius`
7. `current_load_capacity`

## 7. 移动与碰撞

### 移动规则

1. 使用二维移动。
2. 默认由输入方向驱动。
3. 速度由 `move_speed` 控制。
4. 移动不包含战斗锁定逻辑，后续可扩展为“受击轻微硬直”。

### 碰撞规则

1. 玩家实体需要和敌人、障碍、掉落物进行区分。
2. 玩家本体只负责实体碰撞。
3. 拾取判定独立由 `PickupArea` 处理。

## 8. 受击与死亡

### 受击输入

玩家受击应接收一个统一伤害包，至少包含：

1. 伤害数值。
2. 伤害类型。
3. 标签信息。
4. 来源实体。

### 受击处理顺序

1. 先扣护盾。
2. 再扣生命。
3. 根据护甲换算最终承伤比例。
4. 可选触发短暂无敌帧。
5. 生命归零后进入死亡流程。

### 死亡流程

1. 标记玩家死亡。
2. 停止移动与输入响应。
3. 通知战斗循环模块进入结算或失败流程。
4. 后续可由 UI 显示死亡结算界面。

## 9. 拾取范围

1. `pickup_radius` 是玩家自动吸附经验球和基础掉落的范围。
2. 该值可由角色基础属性、营地升级、遗物、羁绊共同修正。
3. 拾取逻辑只负责“判定与吸附”，不负责掉落生成。

## 10. 角色被动与开局配置

### 被动规则

1. 角色被动写入 `passive_modifiers`。
2. 被动优先作为 `Modifier` 叠加，不直接改实体字段。
3. 若被动是特殊效果，再通过扩展效果注册表处理，不污染基础属性表。

### 开局配置

1. `start_weapons` 由角色数据直接指定。
2. 后续若有开局遗物、开局召唤物或特殊资源，也应在角色配置中按独立字段扩展。
3. 开局配置只负责“初始携带”，不负责局外永久解锁。

## 11. 与其他模块的接口

### 与基础数值与数据配置模块

1. 通过 `DataRegistry` 读取角色配置。
2. 通过 `ModifierStack` 计算最终属性。
3. 通过 `StatDefinitions` 校验属性键合法性。

### 与局内武器模块

1. 玩家提供 `VisualAnchor` 和负载上限。
2. 武器模块读取玩家当前属性与开局武器。
3. 武器发射、换装、升级都只读玩家状态，不反向改角色配置。

### 与掉落与奖励模块

1. 玩家拾取范围决定经验球吸附。
2. 经验与金币结算由掉落模块负责，玩家只提供拾取接口。

### 与局外营地模块

1. 营地建筑升级可改变玩家基础属性。
2. 局外永久成长应在存档层记录，不回写角色 JSON。

## 12. 角色流程约定

推荐流程：`角色选择页面 -> 营地 -> 开始战斗`。

### 属性加载顺序

1. 角色选择后读取 `base_stats`。
2. 叠加局外养成/升级属性。
3. 开战后叠加局内遗物属性。

### 开局武器

1. 开始战斗时写入初始武器 ID 列表。
2. 该列表来源于角色配置和局外解锁结果。
3. 战斗开始后，武器模块只读取这份列表，不回写角色配置。

### 角色被动预留

1. 当前角色被动可为空。
2. 预留 `passive_modifiers` 作为扩展入口。
3. 后续若需要更复杂的角色特性，再补独立字段，不影响现有流程。

## 13. MVP范围

当前 MVP 只实现：

1. 1 名默认角色。
2. 基础属性读取。
3. 移动。
4. 受击。
5. 死亡。
6. 拾取范围。
7. 开局武器配置。
8. 向右动画与向左镜像表现。

暂不实现：

1. 多角色选择界面。
2. 角色天赋树。
3. 角色切换。
4. 复杂被动效果。
5. 角色专属动画分层。
6. 向上、向下独立动画。

## 14. 场景与脚本建议

### 文件建议

1. `scenes/player/player_root.tscn`
2. `scripts/player/player_controller.gd`
3. `scripts/player/player_state.gd`（后续可选）

### 推荐职责划分

1. `player_controller.gd`：运行时控制。
2. `player_state.gd`：角色状态和属性快照。
3. 后续如出现角色切换，再拆出 `player_selector.gd`。

## 15. 验收标准

1. 能从 `characters.json` 正确读取默认角色。
2. 玩家能按 `move_speed` 移动。
3. 玩家能正确扣除护盾和生命。
4. 玩家死亡后能通知战斗循环。
5. `pickup_radius` 能影响吸附范围。
6. 开局武器能正确加载。
7. 玩家属性能由 `ModifierStack` 正确计算。
8. 角色选择、营地、战斗三段流程的数据传递清晰。
