# 战斗进入与首次攻击卡顿修复

点击角色页的进入按钮后，立即显示纯黑加载页，右下角为“正在进入地下城...”和依次轻跳的三个点。先等待加载页实际绘制，再创建战斗。准备完成后用 0.35 秒淡出黑幕；玩家、攻击和波次计时在黑幕消失前保持暂停。首次新手引导保留自身的暂停状态。

## 改动

- 将角色初始化和开始首波拆开，保留原来同步确认接口的默认行为。
- 地形各层初始化完成后只生成一次初始布局；加载期间按每帧约 4 毫秒的预算逐块创建，单个地块不可拆分。等待所有初始地块完成才揭开黑幕。
- 提前缓存所有角色动作帧的实际脚底边界，避免首次攻击或移动时执行纹理回读和逐帧透明区域扫描。
- 装备武器时加载并持有弹体贴图，避免每次发射重复查询、加载，或贴图引用释放后再次加载。
- 在黑幕下实际绘制角色、弹体、粒子和雷电材质，准备首次渲染所需的着色器。样本没有碰撞体、不造成伤害、不消耗冷却，揭开黑幕前释放。
- 加载页拦截输入及 Android 返回；重复点击不会重复建场景，流程重置可取消加载，初始化失败返回菜单。
- 依赖菜单确认的现有测试改为等待加载完成信号。

## 验证

- `battle_loading_test.tscn`：18 项通过，覆盖即时黑幕、暂停计时、重复点击、取消、失败恢复、资源准备、新手引导和恢复战斗。无界面及后台 GPU 运行均通过。
- `cavern_sunlight_test.tscn`：97 项通过，包括实际动作脚底排序、地形完整性、障碍碰撞、移动、自动攻击和二次进入。
- `player_action_animator_test.tscn`：92 项通过。
- 编辑器无界面导入完成；提示 Android build-tools 目录未配置。
- 后台 GPU 辅助程序确认实际引擎窗口运行在私有桌面，`foreground_samples=0`。

本机 GPU 性能探测使用真实菜单、木质弓箭及默认雷电附魔：

| 指标 | 修改前观测 | 修改后观测 |
| --- | ---: | ---: |
| 确认按钮回调耗时 | 325.786 ms | 0.564 ms |
| 进入过程最长帧 | 2176.547 ms | 396.400 ms（黑幕期间） |
| 首次攻击调用耗时 | 9.869 ms | 2.052 ms |
| 首次攻击观察窗口最长帧 | 198.402 ms | 34.378 ms |

这些是单次本机观测，不是跨硬件保证。首次启动的资源初始化仍在主线程，加载页覆盖这段等待，初始地形通过分帧创建减轻阻塞。修改后探测将目标生命提高以避免死亡、奖励弹窗干扰，并确认两次施放都成功；修改前第二次施放未成功，其数据不用于比较。

最终版本再次运行探测，两次施放及实际命中检查通过：按钮回调 0.346 ms，首次攻击调用 1.273 ms，首次攻击观察窗口最长帧 41.598 ms，第二次为 46.438 ms。两次修改后运行的首次攻击最长帧为约 34–42 ms。

原始日志、指标和私有桌面验证记录：`artifacts/reports/battle_entry_before*`、`artifacts/reports/battle_entry_after*`、`artifacts/reports/battle_entry_final*`、`artifacts/reports/battle_loading_visual*`。画面：`artifacts/previews/battle_loading_20261019/`。

## 移动中首次自动攻击的补充验证

前述性能探测没有覆盖移动中首次自动攻击，不能仅凭耗时改善宣称“瞬移”已验证解决。新增 `first_attack_motion_test.tscn` 后，使用真实右键移动输入、真实自动弓箭和默认雷电附魔，记录每个物理步及每个 GPU 完成帧的玩家坐标、相机坐标、角色屏幕位置。测量过程中不读取截图，避免读回本身制造卡顿；敌人固定位置并提高生命，避免奖励弹窗干扰。

对照入口绕过当前版本的加载与预热，新入口使用真实角色确认按钮。对照不是完整历史版本，也没有人为添加延迟或修改玩家位置。

| 指标 | 未预热对照，两次运行 | 正式加载入口 |
| --- | ---: | ---: |
| 首次自动攻击后最长画面帧 | 110.329 / 76.839 ms | 39.674 ms |
| 首次自动攻击后最大帧间世界位移 | 14.000 / 11.667 px | 4.667 px |
| 最大单个物理步位移 | 2.333 px | 2.333 px |
| 最大角色屏幕位置步长 | 0.667 px | 0.667 px |
| 瞬移事件、越过正常移动速度的物理步 | 0 | 0 |

原始轨迹中可见，长帧后同一画面帧容纳了多个正常物理步；相机跟随玩家一次跨过较长的世界距离，产生视觉跳段。正式加载入口未再出现对照中的同等跳段。此结论覆盖上述复现场景，不能等同于排除了所有来源的位移异常。

三次后台 GPU 运行均退出成功且 `foreground_samples=0`。日志及轨迹：`artifacts/reports/first_attack_motion_cold*`、`artifacts/reports/first_attack_motion_loaded*`。首次对照的摘要保存在 `.log` 中；带 `_trace_metrics.json` 的第二次对照和 `_loaded_metrics.json` 保存完整逐帧轨迹。
