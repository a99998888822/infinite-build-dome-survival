# 存档与本地进度模块详细设计方案

本文档定义本项目的本地存档规则。当前存档只保存局外进度：局外货币、营地建筑等级、营地升级选项等级和音量设置；不保存任何战斗中的过程状态。

## 1. 已确认游戏主流程

### 1.1 局内战斗流程

```text
启动页面
→ 选择角色
→ 进入战斗第一波
→ 战斗过程中升级时立即弹出升级页面
→ 波次倒计时结束
→ 吸收所有经验球
→ 如果吸收经验后升级，则继续弹出升级页面
→ 结算上一波理财利息
→ 弹出商店页面
→ 完成购买后弹出理财页面
→ 玩家决定是否把当前剩余局内金币存入理财
→ 开始下一波战斗
→ 循环直到死亡或通关
```

这整条流程属于“单局运行态”，不允许中途写入正式存档。

### 1.2 局外营地流程

```text
启动页面
→ 选择购买天赋 / 营地成长
→ 进入营地页面
→ 购买营地建筑或升级选项
→ 已购买升级选项全游戏生效
```

这里的“天赋”在当前工程中等价于营地建筑提供的局外升级选项。

## 2. 模块目标

1. 保存一个默认本地存档槽。
2. 保存局外货币 `camp_currency`。
3. 保存营地建筑等级和营地升级选项等级。
4. 保存音量设置。
5. 禁止保存战斗中的游戏进程。
6. 支持旧存档字段补全、基础校验和安全回退。

## 3. 模块边界

### 3.1 本模块负责

1. 本地 JSON 存档文件读写。
2. 默认存档结构生成。
3. 存档字段补全和类型校验。
4. 死亡或通关后的局外奖励写入。
5. 营地已完成升级项写入。
6. 音量设置保存。

### 3.2 本模块不负责

1. 战斗中的波次进度保存。
2. 局内金币、局内遗物、局内武器等级保存。
3. 理财本金、当前波次、商店候选项保存。
4. 经验球、敌人、投射物、血包等场上实体保存。
5. 结算去重。
6. 多存档槽、云同步和中途继续本局。

## 4. 已确认规则

1. 当前只有一个存档槽：`profile_01`。
2. 不需要 `void_shards`。
3. 保存音量设置：`master_volume`、`bgm_volume`、`sfx_volume`。
4. 不做“中途退出继续本局”。
5. 不需要 `settlement_id` 或结算去重。
6. 存档只在局外安全点写入，不在战斗流程中写入。

## 5. 存档路径

Godot 用户数据目录下使用：

```text
user://saves/profile_01.json
user://saves/profile_01.backup.json
user://saves/profile_01.tmp.json
```

MVP 只实现 `profile_01`。后续如果需要多存档槽，再扩展 UI 和路径管理。

## 6. 存档结构

```json
{
  "schema_version": 1,
  "profile_id": "profile_01",
  "currencies": {
    "camp_currency": 0
  },
  "building_levels": {
    "camp_armory_workshop": 1,
    "camp_relic_archive": 1
  },
  "upgrade_levels": {},
  "settings": {
    "master_volume": 100,
    "bgm_volume": 80,
    "sfx_volume": 90
  }
}
```

### 6.1 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | int | 存档结构版本 |
| `profile_id` | String | 固定为 `profile_01` |
| `currencies.camp_currency` | int | 局外营地货币 |
| `building_levels` | Dictionary | 建筑 ID 到已完成等级 |
| `upgrade_levels` | Dictionary | 营地升级选项 ID 到已购买等级 |
| `settings` | Dictionary | 本地音量设置 |

### 6.2 不再保存的字段

当前 MVP 不保存：

1. `void_shards`。
2. 解锁 ID 列表；可解锁内容由建筑等级和升级项等级派生。
3. 最近选择角色和初始武器；每次从启动页面重新选择角色并进入战斗。
4. 胜负纪录、最高波次和击杀数；后续如果需要成就或统计，再单独扩展。
5. `processed_settlement_ids` 或任何结算去重字段。

## 7. 保存时机

### 7.1 允许保存

1. 游戏启动后首次创建默认存档。
2. 玩家在营地页面成功购买建筑等级或升级选项后。
3. 玩家死亡后完成战斗结算时。
4. 玩家通关后完成战斗结算时。
5. 玩家修改音量设置后。

### 7.2 禁止保存

1. 战斗进行中。
2. 波次倒计时结束后但本局尚未死亡或通关时。
3. 吸收经验球时。
4. 弹出升级页面时。
5. 收到理财利息时。
6. 局内商店购买时。
7. 理财页面存入金币时。
8. 进入下一波战斗前。

这些状态都属于单局临时状态，只能存在于内存中。

## 8. 加载流程

```text
启动游戏
→ 加载 profile_01
→ 无存档则创建默认状态
→ 有存档则解析 JSON
→ 补全缺失字段
→ 校验字段类型和数值范围
→ 提交给营地与设置模块读取
```

损坏存档处理：

1. 正式存档无法解析时尝试读取 `.backup.json`。
2. 备份也无法解析时创建默认存档。
3. 输出警告，不阻止玩家进入游戏。

## 9. 保存流程

```text
获取局外进度
→ 移除临时字段
→ 补全默认字段
→ 校验字段
→ 写入 .tmp.json
→ 读回临时文件确认可解析
→ 当前正式存档复制为 .backup.json
→ .tmp.json 替换正式存档
```

保存失败时保留旧正式存档和备份，不强行覆盖。

## 10. 战斗结算回流

战斗只在死亡或通关后回流局外结果：

```text
死亡 / 通关
→ 奖励模块输出本局最终结算
→ 存档模块增加 camp_currency
→ 保存 profile_01
→ 返回启动页面或营地页面
```

不保存本局过程中的金币、理财、商店购买、局内武器等级和局内遗物。它们只影响这局战斗，最终通过死亡或通关结算转换成局外货币。

## 11. 营地升级回流

玩家在营地页面购买建筑或升级选项后，立即更新：

1. `currencies.camp_currency`。
2. `building_levels`。
3. `upgrade_levels`。

这些是局外安全点，可以保存；这不属于战斗过程存档。

## 12. 校验规则

### 12.1 强校验

1. 根对象必须是 Dictionary。
2. `schema_version` 必须是整数。
3. `camp_currency` 不允许为负数。
4. 建筑等级和升级项等级不允许为负数。
5. `settings` 中的音量必须是 0~100 的整数。

### 12.2 自动修复

1. 缺少 `settings` 时补默认音量。
2. 缺少 `currencies` 时补 `camp_currency = 0`。
3. 缺少初始建筑等级时按 `camp_buildings.json` 的初始状态补全。
4. 建筑等级超过配置最大等级时截断到上限。
5. 升级项等级超过 `max_level` 时截断到上限。

## 13. 临时会话

Bootstrap 自测和编辑器预览不能污染正式存档。

临时会话规则：

1. 进入临时会话后复制一份默认局外状态。
2. 临时会话内所有保存请求都直接返回成功，但不写磁盘。
3. 退出临时会话时恢复原始状态。

现有 `CampProgression.begin_transient_session()` / `end_transient_session()` 继续保留。

## 14. MVP 实施范围

1. 继续保留一个默认存档槽。
2. 去掉 `void_shards` 和结算去重设计。
3. 只保存 `camp_currency`、`building_levels`、`upgrade_levels` 和 `settings`。
4. 禁止战斗中保存。
5. 支持死亡 / 通关后的结算回流保存。
6. 支持营地购买升级后的保存。
7. 支持损坏存档回退备份。

暂不实现：

1. 多存档槽。
2. 云同步。
3. 战斗中断续关。
4. 成就纪录持久化。
5. 解锁 ID 列表持久化。

## 15. 验收标准

1. 无存档时能创建默认存档。
2. 重启后能恢复局外货币、建筑等级、升级项等级和音量设置。
3. 战斗过程中不会写入正式存档。
4. 死亡或通关结算后才会把局外货币写入存档。
5. 营地升级购买后能保存已完成升级项。
6. 损坏正式存档时能尝试恢复备份。
7. Bootstrap 临时会话不会污染正式存档。
