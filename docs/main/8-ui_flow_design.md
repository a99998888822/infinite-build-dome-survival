# UI 交互模块详细设计方案

本文档定义本项目所有核心 UI 流程、弹窗、HUD、输入切换、营地界面和数据绑定方式。它只负责“界面如何展示、如何切换、如何读取状态”，不负责战斗规则、成长规则或掉落规则本身。

## 1. 模块目标

1. 统一战斗内与局外界面的组织方式。
2. 为 HUD、升级弹窗、营地界面、结算界面提供一致的状态入口。
3. 保证 UI 只读业务状态，不直接改写核心规则。
4. 为后续新增界面、弹窗和按钮状态保留扩展口。

## 2. 模块边界

### 2.1 本模块负责

1. 战斗 HUD 显示与刷新。
2. 升级三选一弹窗。
3. 武器负载不足、升级失败、购买失败等提示弹窗。
4. 战斗暂停、继续、结算、进入营地的界面流转。
5. 局外营地界面与建筑入口。
6. 角色选择页、模式选择页、图鉴页的界面跳转。

### 2.2 本模块不负责

1. 玩家属性计算。
2. 武器伤害计算。
3. 敌人 AI。
4. 掉落结算。
5. 存档结构定义。
6. 营地成长规则本身。

## 3. UI 核心原则

1. UI 只读状态，不直接改规则。
2. 核心规则通过信号和数据快照驱动 UI。
3. 弹窗之间互斥，避免多层模态叠加。
4. 战斗态和营地态使用不同 UI 层。
5. 新增 UI 优先加节点和绑定，不优先改业务逻辑。

## 4. UI 分层

### 4.1 战斗层

用于战斗中的实时信息展示。

建议包含：

1. 血条。
2. 护盾条。
3. 经验条。
4. 波次时间。
5. 金币。
6. 负载显示。
7. 当前武器信息。
8. 羁绊提示。

### 4.2 弹窗层

用于暂停、升级、购买和结算类交互。

建议包含：

1. 升级三选一弹窗。
2. 免费商店购买提示。
3. 武器购买失败提示。
4. 结算结果弹窗。
5. 资源领取弹窗。

### 4.3 局外层

用于角色选择、营地、图鉴、模式选择等。

建议包含：

1. 角色选择页。
2. 营地主界面。
3. 营地建筑详情面板。
4. 图鉴页。
5. 模式选择页。

## 5. 界面流程

### 5.1 角色选择到战斗

`角色选择页面 -> 营地 -> 开始战斗`

1. 先选角色。
2. 再回到营地查看局外成长。
3. 点击开始战斗后，UI 组装出战参数。
4. 进入战斗场景后切换到战斗 HUD。

### 5.2 战斗中升级流程

1. 达到升级条件。
2. 弹出升级三选一。
3. 玩家选择后立即生效。
4. 若触发免费商店，则连带显示一次免费购买流程。

### 5.3 战斗结束流程

1. 结算界面展示本局数据。
2. 回收局内掉落和升级结果。
3. 切回营地。

## 6. UI 数据绑定

### 6.1 绑定原则

1. UI 通过信号刷新，不做轮询。
2. HUD 只接收当前帧快照，不缓存复杂战斗逻辑。
3. 弹窗通过单次打开参数渲染内容。

### 6.2 推荐绑定来源

| UI 组件 | 绑定来源 |
| ---- | ---- |
| 血条 / 护盾条 | 玩家当前 HP、Shield、Max HP |
| 经验条 | 当前经验、升级阈值、等级 |
| 负载显示 | 武器总负载、负载上限 |
| 波次时间 | 当前波次剩余时间 |
| 金币 | 当前局内金币 |
| 羁绊提示 | 当前武器标签 + 遗物标签统计 |
| 营地建筑列表 | `CampProgression` 的建筑等级与解锁状态 |

## 7. 关键弹窗

### 7.1 升级三选一弹窗

作用：玩家升级时从三项中选一项。

规则：

1. 弹窗打开时锁定其它主交互。
2. 选择后立即关闭。
3. 若没有可用项，允许显示保底项或自动跳过。

### 7.2 武器购买失败弹窗

作用：提示负载不足或配置无效。

规则：

1. 文案区分失败原因。
2. 只显示一层提示，不叠加多重错误框。

### 7.3 结算弹窗

作用：展示本局战斗结果、资源变化、解锁变化。

规则：

1. 结算后先显示结果，再回营地。
2. 结果页面只展示汇总，不做复杂动画依赖。

### 7.4 局内商店选项规则

商店只提供三类选项：`new_weapon` 新武器、`relic` 遗物、`weapon_upgrade` 已装备武器的下一等级升级项；不提供单独购买基础属性。免费商店和付费商店共用同一套候选池、稀有度权重、类型权重和去重规则，区别只在于选择后是否扣除局内货币。

遗物、新武器和武器升级共用六档稀有度：`common` 普通白、`uncommon` 优良绿、`rare` 稀有蓝、`epic` 珍贵紫、`mythic` 罕见橙、`legendary` 传说红。新武器使用武器本体 `rarity`；武器升级使用升级项自身 `rarity`，两者不混用。

1. 新武器不可重复获得；已拥有武器不再进入新武器候选池。
2. 新武器即使当前负载不足也可以刷新，但购买/装备时必须通过负载强校验；剩余负载越低，新武器类型权重越低。
3. 遗物只从已解锁且未达到 `max_stack` 的列表构建；`max_stack = 0` 表示不限制。
4. 武器升级只从已装备且未达到 `max_level` 的武器构建，并只生成当前等级的下一等级升级项。
5. 同一轮商店中，同一把武器的同一级升级项最多出现一次。

稀有度权重函数：

```text
get_shop_rarity_weights(luck: int) -> Dictionary
common    = max(20, 100 - floor(luck * 0.30))
uncommon  = max(25,  55 - floor(luck * 0.10))
rare      = 25 + floor(luck * 0.20)
epic      = 10 + floor(luck * 0.12)
mythic    =  4 + floor(luck * 0.06)
legendary =  1 + floor(luck * 0.03)
```

权重示例：

| 幸运 | 白 | 绿 | 蓝 | 紫 | 橙 | 红 |
|---:|---:|---:|---:|---:|---:|---:|
| 0 | 100 | 55 | 25 | 10 | 4 | 1 |
| 50 | 85 | 50 | 35 | 16 | 7 | 2 |
| 100 | 70 | 45 | 45 | 22 | 10 | 4 |
| 200 | 40 | 35 | 65 | 34 | 16 | 7 |
| 300 | 20 | 25 | 85 | 46 | 22 | 10 |

幸运只影响稀有度，不直接指定具体条目。类型权重默认是 `new_weapon = 25`、`relic = 50`、`weapon_upgrade = 25`。剩余负载比例对应新武器权重倍率为：50%以上 1.00、30%~49% 0.70、15%~29% 0.45、1%~14% 0.25、0% 0.15。

武器升级使用轻量保底：连续刷新未出现升级时，`weapon_upgrade_weight = min(100, 25 + upgrade_miss_count * 15)`；出现至少一个升级后清零；没有可升级武器时不累积。

建议接口：`build_shop_candidate_pool(context)`、`get_shop_rarity_weights(luck)`、`get_shop_type_weights(context)`、`roll_shop_offers(rarity_weights, type_weights, candidate_pool, refresh_count)`。刷新时按稀有度、类型、具体条目的顺序抽取，候选桶为空时回退，避免空槽位。

## 8. 营地 UI

### 8.1 营地主界面

营地主界面用于展示：

1. 当前角色。
2. 当前建筑状态。
3. 局外货币。
4. 可购买升级项。
5. 进入战斗按钮。

### 8.2 建筑面板

点击建筑后显示：

1. 建筑名称。
2. 建筑说明。
3. 当前等级。
4. 下一等级效果或升级项列表。

### 8.3 解锁显示

1. 未解锁建筑显示废墟。
2. 已解锁建筑显示正式素材。
3. 初始自带建筑直接显示正式素材。

## 9. 输入与暂停

### 9.1 输入优先级

1. 弹窗优先于主界面。
2. 暂停优先于战斗控制。
3. 营地页面优先于普通装饰点击。

### 9.2 暂停规则

1. 战斗中可按暂停键打开暂停菜单。
2. 暂停时停止战斗逻辑，但保留 UI 响应。
3. 弹窗打开时默认阻断底层输入。

## 10. 场景建议

### 10.1 战斗 UI 场景

建议由以下部分组成：

1. `CanvasLayer`。
2. `HUDRoot`。
3. `PopupLayer`。
4. `FadeLayer`。

### 10.2 局外 UI 场景

建议由以下部分组成：

1. `CanvasLayer`。
2. `CampRoot`。
3. `PanelLayer`。
4. `PopupLayer`。

## 11. MVP 范围

MVP 阶段只做：

1. 战斗 HUD。
2. 升级三选一弹窗。
3. 结算弹窗。
4. 营地主界面。
5. 建筑详情面板。
6. 简单暂停菜单。

暂不做：

1. 动画化转场。
2. 多语言系统。
3. 复杂图鉴分页。
4. 高级拖拽编辑器。
5. 多主题皮肤。

## 12. 结项判断

本模块可视为完成的条件是：

1. 战斗、营地、结算三类 UI 能正常切换。
2. HUD 能实时展示关键数值。
3. 弹窗能正确响应升级和购买事件。
4. UI 不直接改写核心规则。
