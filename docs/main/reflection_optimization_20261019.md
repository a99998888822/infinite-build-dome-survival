# 第一项优化：大量反射效果（2026-10-19）

已完成首轮优化：降低大量反射同时生成、扫描和更新时的重复开销，保留每束反射的独立伤害、命中记录和执行顺序。极端组合仍有长帧，本轮没有把整个主战斗场景判定为性能达标。

## 优化方向与实际改动

| 原有开销 | 已实施方案 |
|---|---|
| 每次生成反射都遍历全部像素特效，实例越多，后续生成越慢 | 达到最低视觉等级的判断阈值后立即结束扫描；已被现有视觉预算隐藏的反射直接注册分组，无须再次扫描 |
| 同一位置、半径、朝向的反射重复做范围、距离、方向和角度计算 | 同帧共享几何结果，再按各自扫描角度共享候选筛选结果 |
| 隐藏反射仍每帧请求重绘 | 跳过视觉等级为隐藏时的重绘请求，保留伤害和生命周期更新 |
| 缓存可能在移动、死亡、增删目标或伤害回调后失效 | 跟踪帧号、怪物注册版本、空间版本和祖先变换；回调改变几何条件时，立即按原注册顺序继续实时扫描 |

实现位置：`scripts/effects/light_reflection_effect.gd`、`scripts/effects/reflection_query_cache.gd`、`scripts/effects/pixel_effect_draw.gd`。

清单最初提出“按施法批次集中管理”。本轮先共享计算，继续保留原来的节点处理顺序，避免集中调度改变反射与其他效果之间的状态消耗和死亡回调顺序。缓存不保存最终伤害、存活状态或各束反射的已命中记录；角度和缓存键保留双精度，避免边界接触时间发生变化。每帧最多缓存 512 组几何结果，超过后正常计算。

## 优化前后：相同工作量的 GPU 对照

测试使用真实 GameRoot、战斗背景、怪物受击与 HUD，1920×1080，Godot 4.7.2，Compatibility / ANGLE；关闭垂直同步和帧率上限。运行器在独立 Windows 桌面执行，实际桌面校验一致，`foreground_samples=0`。

- 96 只高生命值静止怪物；固定 32 个反射起点、相同朝向和半径。
- 在第 0、6、12、18 步各生成 320 束反射，共 1,280 束；每步推进 1/60 秒，共 60 步，模拟时间为 1 秒。
- 反射与视觉预算时钟手动固定，关闭打击停顿；保留正常伤害、跳字、受击和可见反射绘制。其它表现仍随实际帧推进。
- 优化前使用冻结的旧实现，优化后使用正式实现；每边跑两轮，共 120 个完成绘制的帧间隔。
- 此测试衡量密集反射负载，不代表普通游玩平均帧率，也不等同于驱动缓存被清空后的首次攻击测试。

| 指标 | 优化前 | 优化后 | 降低 |
|---|---:|---:|---:|
| 平均帧耗时 | 142.738 ms | 48.745 ms | 65.85% |
| P95 帧耗时 | 321.488 ms | 74.662 ms | 76.78% |
| P99 帧耗时 | 537.953 ms | 117.127 ms | 78.23% |
| 最大帧耗时 | 709.606 ms | 415.167 ms | 41.49% |
| 超过 100 ms 的帧数 / 120 帧 | 73 | 3 | 95.89% |
| 每轮生成反射累计 CPU 耗时 | 747.331 ms | 30.787 ms | 95.88% |
| 单步生成反射 CPU 峰值 | 366.023 ms | 9.624 ms | 97.37% |
| 每轮反射更新累计 CPU 耗时 | 6,668.756 ms | 1,915.866 ms | 71.27% |
| 单步反射更新 CPU 峰值 | 335.038 ms | 71.045 ms | 78.79% |

帧指标由两轮原始样本合并计算；CPU 累计值为两轮平均，峰值取两轮最大。反射更新耗时包含真实伤害和内部回调，不能解释成纯范围查询成本。

优化前两轮平均帧耗时分别为 136.734 / 148.741 ms，优化后为 46.352 / 51.137 ms。优化后第二轮第 34 步仍出现 415.167 ms 长帧，该步反射更新计时为 56.171 ms，且第一批反射在这一阶段到期；本轮没有单独分解延迟释放、渲染和系统调度，不能把整帧余下时间归因于某一项。表格保留该峰值，没有剔除异常帧。

四次运行均完成 **76,800 次伤害事件、2,688,000 点伤害**，逐步累计命中数和活动反射数一致；按步骤、反射、目标、伤害顺序计算的校验值均为 **1426651616**，96 个目标的最终生命值逐个一致。视觉等级数量均为 **16 / 32 / 48 / 1,184**，因此收益没有来自新增视觉压缩或减少反射伤害。

## 真实组合复测与剩余瓶颈

另外使用原测量场景运行 4 级电浆炮＋水＋冰＋光，保留怪物移动、真实施法和打击停顿，各跑约 12 秒。

| 指标 | 复测 1 | 复测 2 |
|---|---:|---:|
| 全程伤害事件数 | 117,065 | 170,745 |
| 采样到的反射实例峰值 | 4,152 | 6,016 |
| 稳态 P95 | 52.725 ms | 53.466 ms |
| 稳态最大帧耗时 | 306.652 ms | 559.091 ms |

这些运行的伤害事件数、反射数量和暂停比例与旧测量不同，不能把旧峰值 1,171.611 ms 与这里的峰值直接相除，声称同负载收益。相同工作量的百分比以上面的固定负载对照为准。

剩余问题是数千个逻辑节点的生命周期、调度、独立命中记录和大量真实伤害回调；共享计算没有限制反射生成。即使固定负载的长帧已明显缩短，仍未达到稳定 60 FPS。下一步应在保留处理顺序的前提下验证实例复用和节点调度优化；雷火集中结算、法阵绘制和地形补块仍按原清单分别处理。

## 验证与已有失败

**后续复核更新：**下列 5 项历史失败已查清并修正测试；元素反应 69 项、附魔叠加 285 项全部通过。新增分阶段复测发现一次 485 ms 绘制阶段尖峰，已补充加载期间的反射绘制预热，原 415 ms 峰值仍不宣称完全消除。详见[长帧与测试失败复核](reflection_long_frame_followup_20261019.md)。以下保留首轮当时的验证记录。

- 反射专项新增测试：278 项检查通过，比较旧/新完整有序伤害轨迹、来源、数值、生命值、光状态、单束命中记录和可见视觉等级；覆盖密集/稀疏目标、移动目标及父节点、移动反射、同帧增删目标、修改扫描范围、不同伤害来源、存活状态变化、浮点边界、暂停和结束。
- 战斗反应音效测试：33 项检查通过。
- Godot headless editor 无解析/编译错误，主场景通过 120 帧 headless 启动检查；环境仍提示 Android build-tools 目录不可用。
- 元素反应测试有 4 项失败，附魔叠加测试有 1 项失败。用隔离项目恢复本轮优化前的两个正式脚本重跑，失败项与优化后完全一致，未修改这些测试或相关战斗规则来掩盖失败。
- 既有失败具体为：冰面椭圆外目标判定、初始外圈冰面目标、致死电火花引爆邻近燃烧、火焰初始外圈目标、领域对风刃宽度的参数断言。
