# 大量遗物时的战斗与界面性能优化

2026-10-07。针对约 50～60 件遗物时战斗、ESC、商店购买卡顿，尤其点击购买按钮时的停顿，调整重复计算和界面资源复用。未调整遗物数值、结息规则或商品价格。

## 原因与修改

- 战斗 HUD 每帧更新关闭的属性抽屉，并为本金标签生成包含遗物效果的完整理财快照。现在只在抽屉打开或动画期间更新属性行，本金直接读取余额；羁绊栏在效果版本变化时刷新。
- 玩家及购买预览未启用已有的属性缓存。现在启用缓存，新增、移除、到期、替换基础属性等操作继续通过原有接口使缓存失效；护甲关联的减伤一起刷新。
- 添加正向属性时反复复制并遍历全部遗物运行效果。现在按遗物效果版本缓存触发器列表和属性增长限制索引。对外返回独立副本，防止预览或调用方改坏缓存。
- 遗物重建时每加一条修正都重新排序全部修正。现在向有序数组二分插入；刷新持续时间且可能改变优先级时仍重新排序。
- 理财计算反复扫描遗物配置。现在复用效果定义与叠层数；本金、收益和随机事件结果仍按当前状态计算。动态属性刷新只提取需要的旧数值，避免复制所有修正对象。
- ESC 遗物数量未变时不再重建图标节点；相同稀有度共用辉光纹理，隐藏时暂停呼吸动画；商店与 ESC 共用图标纹理缓存。保留现有图标尺寸、灰框、辉光和介绍。

## 后台实机对照

Godot 4.7.2，1152×648，关闭垂直同步和帧率上限，同一设备、固定随机种子。分别测试 0 件与 60 件遗物，使用真实 GameRoot、ESC、理财界面和购买事务。遗物集来自配置顺序，购买同一件止血布，购买前有 102 条属性修正。测试使用临时进度，不保存测试背包。

对照工程保存在 `D:/project/useless/review-archives/relic-performance-20261007/control`，使用本轮修改前源码快照。GPU 运行均通过 `scripts/tools/run_godot_background.py` 的独立 Windows 桌面，实际引擎桌面匹配，`foreground_samples=0`。

每个画面预热 30 帧后采样 120 帧。为隔离遗物与 UI 开销，暂停玩家物理更新和刷怪、移除敌人，因此这些数值不是大量敌人交战时的 FPS 保证。原始 JSON 也记录了 0 件遗物对照。

首次集中冷加载 60 件遗物图标仍有约 339 ms 开销。直接授予遗物的测试会集中遇到这项成本；正常流程中商店已显示的图标可以复用缓存。本轮主要改善持续计算、购买和重复打开界面，未消除所有首次资源加载停顿。

此前 headless 对照购买耗时为 102.825 → 29.886 ms；上表采用最终 GPU 对照，避免混用两种运行条件的数据。

- `relic_balance_regression_test`：88 项通过。
