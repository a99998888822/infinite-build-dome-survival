# 本金消费服务：战斗专精

日期：2026-10-11。状态：用户审阅界面后已接入正式理财页面。战斗专精价格、效果和最新文案按确认内容实现，出现规则采用本文方案。

## 范围

保留当前完整计息机制。新增本金消费服务仅包含战斗专精，不实施此前提议的分段利息、资产加怪、定向升级、定向附魔或冒险存款。现有遗物、商店和哥布林交易不在本次调整范围。

## 战斗专精：用户指定内容

将用户给出的分号分组解释为六组候选，每次购买一组，同组全部效果同时获得。价格随本局战斗专精的成功购买总次数增长，六组共用计数，而不是每组独立计数。

| 本局第几次成功购买 | 本金价格 |
| --- | ---: |
| 1 | 300 |
| 2 | 600 |
| 3 | 1200 |
| 4 | 2000 |
| 5 | 3600 |
| 6 | 5600 |

六次总成本 13300 本金，购买六次后本局不再出现。价格按用户给定的固定本金金额解释，不额外施加普通商店波数、购买次数、折扣或理智修正。

| 组别（暂名） | 每次购买获得的效果 | 波数条件 |
| --- | --- | --- |
| 生存专精 | 最大生命 +5；护甲 +15 | 无额外波数门槛 |
| 伤害专精 | 近战伤害 +5；远程伤害 +5；元素伤害 +5 | 无额外波数门槛 |
| 攻击专精 | 攻击距离 +12；伤害范围 +12；攻击速度属性 +12 | 无额外波数门槛 |
| 成长专精 | 金币获取 +12 个百分点；经验获取 +12 个百分点；拾取范围 +12 | 无额外波数门槛 |
| 投射专精 | 投射物数量 +1 | 即将开始的波数 ≥4 |
| 复活专精 | 复活次数 +1 | 即将开始的波数 ≥4 |

每次属性提升持续本局。最大生命增加不附赠治疗；复活提供一次本局可用的次数，消耗后不因属性重算而恢复。攻击距离、伤害范围和拾取范围按现有对应属性增加 12，不改现有换算规则。

## 战斗专精：正式出现规则

以下规则配置于 `data_config/battle_specializations.json`：

- 进入有下一波的准备阶段后，满足 `本金 ≥ max(3000, 本次专精价格)` 时获得当次出现资格。
- 每个准备阶段独立以 50% 概率出现一次。首次满足资格时抽取并保存结果，反复存取款或开关面板不重新抽取。
- 出现后从当前波数允许的组别中等概率抽取三组，玩家选购一组；同一报价内不重复组别。未来准备阶段可以再次出现以前购买过的组别。
- 每个准备阶段最多购买一次。放弃、未购买或支付失败均不推进价格；成功购买才将全局次数加一。
- 从本金直接支付，不要求先手动取款，因此资本家也能使用。若实际支付后本金将耗尽，沿用此前已确认的破产重组顺序。
- 服务独立抽取，不改变已有哥布林交易的候选权重或出现概率。没有可进行的下一波时不出现。

选择三组再选一，可以保留随机性并减少抽到完全不适合构筑的服务。若进入准备阶段时本金不足，存款达到门槛时可获得当波唯一一次抽取机会；未抽中后再次存取款不会重抽。

## 理财页面正式布局

- 在右侧工作区的“购买 / 附魔”页签行，追加“战斗专精 · 可选”；小屏缩写为“专精 · 可选”。上方保留金币、本金和利率摘要。
- 只有本波抽中时才显示专精入口。打开理财页仍默认查看商店，不自动切换、不弹窗。
- 点击专精入口后，使用原右侧工作区显示三张选择卡。左侧存取款、哥布林交易位置和底部下一波按钮维持既有布局。
- 顶部仅展示“战斗专精”标题，三张卡完整列出各组属性；移除“三选一 · 本局永久…”副标题。
- 点击卡片只选择，不付款。下方实时显示本金的前后变化，最后由独立的“确认购买 · 300 本金”按钮提交，金额随购买次数变化。预览页移除预计利息文本，计息规则保持原样。
- 购买后保留获得结果，入口改为“已购”，其余选择禁用，本次不能重复付款。
- 若报价生成后玩家取出本金，导致余额不足，保留报价并显示差额、禁用确认。没有抽中时不展示灰色占位入口。

正式入口位于 `scripts/ui/finance_popup.gd`，专精面板为 `scripts/ui/battle_specialization_panel.gd`。使用已有理财美术，点击确认后扣除实际本金、授予本局属性，并同步银行摘要、顶部 HUD 和角色属性栏。极矮窗口遇到贷款栏时允许专精区滚动。

## 实现与核对

- 已核对现有属性：攻速、金币获取、经验获取、暴击等使用对应百分比属性；伤害、生命、护甲、移速、拾取和投射物数量使用对应数值属性。攻击距离与范围继续使用项目现有属性换算。

- `BattleSpecializationSystem` 在局内保存专精次数、当波报价和购买记录；开新局清空。重复打开页面、切换页签、查看 Esc 面板和刷新属性不会重抽、重付或重复授予复活。
