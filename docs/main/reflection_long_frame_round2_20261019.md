# 反射长帧第二轮优化（2026-10-19）

本轮继续减少已命中目标的重复检查，并合并同帧重复的受击视觉提交。相对上轮已完成几何共享、隐藏反射免重绘和加载预热的版本，固定压力对照的平均帧耗时降低 **27.6%**，P95 降低 **31.2%**。

**真实连锁组合仍出现 675.099 ms 长帧，尚未解决全部战斗卡顿，也未达到稳定 60 FPS。** 下文分别记录固定工作量对照和真实组合，不能混用两者的提升百分比。

## 实际改动

| 热点 | 本轮优化 | 保留的行为 |
|---|---|---|
| 每束反射在每帧重复遍历已经命中的目标 | 为每束反射建立命中位集，相同几何和相同排除集合共享筛选结果；每帧最多缓存 2,048 个筛选结果，达到上限后正常计算 | 每束反射仍有独立的实例 ID 命中账本，伤害数值、结算顺序、首次命中时间、光状态消费和存活状态实时读取 |
| 同一怪物在同一帧被反复命中 | 相同受击姿态只提交一次偏移、材质和闪白参数，后续相同视觉状态直接复用 | 血量、伤害信号、元素效果、随机数和死亡照常逐次处理；动画偏移、世界变换、材质、闪白模式改变，或重置、跨帧命中时重新同步 |

怪物登记表改变时，位集从原命中账本重建；伤害回调移动、增加、移除目标或改变当前反射参数时，保留原有的实时遍历回退。缓存不把死亡等同于已命中，未被命中过的复活目标仍能正常受到伤害。

代码：`scripts/effects/light_reflection_effect.gd`、`scripts/effects/reflection_query_cache.gd`、`scripts/effects/enemy_hit_visual.gd`。

## 优化前后实测

环境为 Godot 4.7.2、1920×1080、Compatibility/ANGLE D3D11、Intel Arc Graphics。所有真渲染运行均在独立 Windows 桌面完成，验证引擎桌面一致、退出码为 0、`foreground_samples=0`，没有打开前台游戏窗口。

固定工作量：96 只静止的真实怪物，32 个反射起点，4 批共 1,280 束反射，60 个固定 1/60 秒模拟步骤；伤害和视觉路径正常执行，关闭打击停顿。背景、跳字和受击视觉仍按实际帧间隔运行。每次正式采样前都走当前地下城加载流程，未打开诊断场景的额外预热。

优化前版本冻结在测试夹具中，包括反射查询和受击视觉。两个进程分别交替执行“前、后、后、前”和“后、前、前、后”，合计每版 4 轮、240 帧；交换启动顺序以减少首次运行偏差。没有删除尖峰帧。

## 长帧还发生在哪里

固定负载对照组再次捕捉到两种数百毫秒尖峰：

- **470.877 ms，第 34 步**：绘制前 69.122 ms，绘制开始到完成 401.552 ms；当帧退出 320 束反射，退出信号跨度仅 3.898 ms。可以定位到绘制阶段，不能把全部耗时算作 GPU 运算或节点释放。
- **394.807 ms，第 44 步**：绘制前 385.410 ms，反射更新仅 33.613 ms，绘制阶段 9.192 ms，当帧没有反射退出。仍有未覆盖的更新/等待开销；不能把全部差额归因于反射扫描、草簇或怪物逻辑。
- 优化后的固定负载最高帧为 **90.836 ms**：绘制前 83.309 ms，绘制阶段 7.313 ms，其中伤害回调 12.016 ms。本轮主要改善的是持续 CPU 工作量，仍有明显的长帧。

真实“等离子炮＋水／冰／光剑”运行保留移动怪物、武器物理更新、自动连锁和打击停顿，12 秒采样中：

- 2 次释放，93,573 次伤害，采样到的反射数量峰值为 **4,681**；此数量是定期快照，可能低于真实瞬时峰值。
- 511 个绘制帧中有 18 帧超过 100 ms；最高帧 **675.099 ms**，该帧结算 **21,804 次伤害**，伤害回调累计 **216.477 ms**，背景更新 **2.425 ms**。
- 伤害回调只能解释其中一部分耗时。这次真实组合采样没有完整绘制阶段拆分，也没有逐个反射计时，`reflection_ms=0` 表示未启用该项插桩，不表示反射没有成本。
- 363 / 511 个采样帧处于打击停顿。平均绘制帧时间会被大量暂停帧拉低，不能据此宣称真实战斗已经流畅。

这说明数千个反射和单帧数万次真实伤害仍是后续重点；两次释放次数少也不能解释为伤害工作量少。本次真实组合用于运行验证和暴露剩余问题，没有优化前同工作量对照，因此不计算其提升百分比。

## 后续优先方向

1. **反射调度与实例数量成本**：研究复用节点和集中更新，先量清批量创建、调度、释放各自成本，保持原来的结算顺序与命中时间。
2. **单帧数万次伤害的固定成本**：继续分析属性解析、状态查询、伤害事件构造和跳字准入，复用状态未变时的结果；单纯把伤害推迟到以后几帧会改变战斗时序，不能当作等价优化。
3. **未覆盖的数百毫秒等待**：补充真实组合的完整阶段时间线，进一步区分引擎提交、资源回收、驱动同步与脚本回调；保留所有尖峰样本。
4. 地形补块、法阵绘制仍按根目录清单另行优化。当前反射峰值帧中背景只有约 2.4 ms，没有证据把该次卡顿归因于草簇。
