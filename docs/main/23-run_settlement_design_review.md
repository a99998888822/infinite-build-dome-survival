## 改动前的问题

- `MainFlowCoordinator.present_battle_result()` 目前把 `summary.gold` 直接交给 `CampProgression.apply_final_settlement()`；调用方传入结束时钱包余额。
- 当前 `BattleResultPanel` 只展示胜负和阵亡波次，没有完整收益明细。
- `RewardSnapshot` 每波重置；`EconomyJournal` 最多保留 300 条。因此最终统计需要独立的整局累积数据，不能从最后一波快照或日志文字倒推。
- 已有 `WaveManager._on_enemy_died()`、战斗金币入账、`interest_settled`、交易接受 / 取消、挑战选择等事件，可以提供统计入口。
- 正式怪物目前有「天外幼体」与「钢甲骑士」，首版使用现有素材显示击杀记录。

按剩余金币结算会让买装备、存本金的玩家损失营地币，尤其与已经实现的全额存款挑战冲突。本方案改用累计贡献，消费不会抹掉已挣得的贡献。

## 界面设计

主标题统一为「冒险结束」。标题下方小字：死亡显示「第x波 阵亡」，通关显示「通关！」。死亡波次使用本局结束时的实际当前波次，与右侧已完成波次数分开记录。

左侧展示「击杀记录」：怪物原图、名称、击杀数量。两类原型各占一格，合计等于右侧总杀敌数；将来种类增加时，按击杀数排序，并允许横向滚动查看完整记录。死亡与通关均展示实际击败的敌人，清场消失的敌人不计入。

右侧按顺序展示：

| 指标 | 主数值 | 右侧贡献 |
| --- | --- | --- |
| 总杀敌数 | 1,800 只 | +180 营地币 |
| 赚取金币 | 2,500 金币 | +125 营地币 |
| 度过波次 | 8 波 | +160 营地币 |
| 赚取利息 | 1,600 金币 | +32 营地币 |

右侧下方是最大的「本次获得营地币 +497」。四个分项相加必须与总数完全一致。鼠标 / 长按分项可显示折算规则。利息贡献到上限时显示小型「贡献已达上限」标签，实际利息金额照常显示。

哥布林位于左侧下方，复用银行人物与柜台风格；对白气泡放在其头顶。底部只保留「返回主界面」按钮。

小窗口：640×360 使用紧凑两栏，怪物记录横向滚动，哥布林缩小但不隐藏。窄屏使用上下排列的滚动区，操作按钮固定。已进行 1152×768、640×360、360×640 的运行截图与控件检查。

## 统计口径

| 数据 | 纳入 | 不纳入 |
| --- | --- | --- |
| 总杀敌数 / 怪物明细 | 本局真实死亡事件，包括精英、附魔、持续伤害击杀 | 波末清场、强制移除、重复死亡回调 |
| 赚取金币 | 战斗与掉落实收金币，包含金币获取加成及击杀掉落类遗物的收益 | 利息、取款、出售返还、初始钱包、哥布林送金币、本金赠送 |
| 度过波次 | 完整存活并完成结算的波次 | 进入但未完成的波次；第 9 波阵亡记为 8 波 |
| 赚取利息 | 本局成功实际到账的整数利息，包含额外、周期与手动结息 | 理智折损前的名义利息、未兑现的小数、预估利息、存取本金 |

花掉 / 存入的金币仍属于已挣得的金币，取款不再重复计算。利息自动转存后仍记在利息总额；随后取款也不新增金币贡献。本金本身不直接兑换营地币，它通过战斗能力与已实现的利息体现收益。

死亡时，已击杀的怪物照常计数；尚未拾取的地面金币不算已赚取金币。未完成波次不补发正常波末利息。正常通关先执行最后一波全部结息和已接受的挑战奖励，再冻结统计与显示最终结果。

## 营地币公式

首版将四项分别向下取整后相加：

```text
杀敌贡献 = floor(总杀敌数 / 10)
金币贡献 = floor(赚取金币 / 20)
波次贡献 = 度过波次 × 20
利息贡献 = min(floor(赚取利息 / 50), 波次贡献)

本次营地币 = 杀敌贡献 + 金币贡献 + 波次贡献 + 利息贡献
```

利息贡献最多等于波次贡献，防止复利收益在营地成长上无限放大。这个上限只作用于局外营地币折算，实际利息完整到账、完整展示；界面提供明确提示。全额本金和哥布林赠款不会直接制造额外营地币。

同样四项统计，无论死亡 / 通关、听从 / 拒绝建议，都得到同样的营地币。通关自然得到全部 20 波贡献；首版不额外按失败打折，也不根据「听话程度」奖惩玩家。

| 示例，非实测均值 | 击杀 | 战斗金币 | 已过波次 | 已赚利息 | 四项贡献 | 营地币 |
| --- | ---: | ---: | ---: | ---: | --- | ---: |
| 前期阵亡 | 360 | 400 | 3 | 120 | 36 + 20 + 60 + 2 | 118 |
| 中期阵亡，演出样例 | 1,800 | 2,500 | 8 | 1,600 | 180 + 125 + 160 + 32 | 497 |
| 高利息但中期阵亡 | 1,100 | 1,600 | 8 | 40,000 | 110 + 80 + 160 + 160 | 510 |
| 均衡通关 | 6,800 | 9,000 | 20 | 10,000 | 680 + 450 + 400 + 200 | 1,730 |
| 高利息通关 | 5,600 | 7,000 | 20 | 50,000 | 560 + 350 + 400 + 400 | 1,710 |

当前营地不少基础训练起价在 100–500 币，以上方案使前期失败仍可积累一次基础提升，中期失败约提供数次低级成长，通关获得更明显的回报。这是待确认的起始参数，需在接入后采集不同构筑的真实整局数据校准。

## 哥布林反应

银行「交易」与「下一波挑战」统一计为哥布林建议；每次实际展示的一项建议最多计一次。此口径已实现。

- 接受且成功生效：记为接受；失败点击不计。
- 明确拒绝、选择正常开战、或购物 / 存取 / 刷新使已显示交易取消：记为未接受。
- 返回银行、打开设置、重复展示同一挑战：仍是同一项待决定建议。
- 没有符合条件的建议、初始第一波、直接开战交易跳过的挑战：不计作拒绝。
- 接受数大于未接受数：使用「听从」对白；小于：使用「不太听从」对白。
- 恰好各半：参考最后一次有效决定选择反应。尚未遇到任何建议时，仅让哥布林清点硬币，不播放指责玩家听不听话的台词。

| 情形 | 台词，严格沿用用户原文 | 表情 / 动作 |
| --- | --- | --- |
| 听从多数建议，提前死亡 | 哥布林包赚，但不包活哈哈哈！ | 眯眼奸笑，露齿，肩部轻抖 |
| 未接受多数建议，提前死亡 | 嘬嘬嘬，不听哥布林，吃亏在眼前！ | 挑眉、微微前倾，带责怪意味 |
| 听从多数建议，通关 | 再来，再来！ | 露笑、招手，想留下玩家 |
| 未接受多数建议，通关 | 啧，稳妥点当然好，就是赚的少了些。 | 撇嘴，勉强认账 |

最后一句是哥布林的偏见，不能据此减少玩家实际营地币。四组相同统计的试算值保持一致。
