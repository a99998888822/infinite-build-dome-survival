# 局内遗物与羁绊模块详细设计方案

本文档定义局内遗物、羁绊计数、羁绊效果结算、遗物重复获取与数量上限、以及与玩家数值系统的接入方式。它只负责“遗物如何进入局内、如何堆叠、如何触发羁绊、如何提交属性变化”，不负责掉落池权重、UI弹窗样式、营地图鉴解锁和特殊效果的具体执行。

## 1. 模块目标

1. 建立稳定的局内遗物数据模型。
2. 支持局内重复获得同名遗物，并通过最大持有数限制刷出。
3. 支持遗物属性直接叠加到玩家 `ModifierStack`。
4. 支持“武器 + 遗物”共同统计羁绊层数。
5. 支持羁绊阈值效果自动生效。
6. 为后续特殊效果、羁绊界面和图鉴系统预留扩展口。

## 2. 模块边界

### 2.1 本模块负责

1. 遗物静态配置读取。
2. 局内遗物实例管理。
3. 遗物数量上限判断。
4. 羁绊层数统计。
5. 羁绊效果转换为 modifier。
6. 遗物/羁绊变更通知玩家刷新最终属性。

### 2.2 本模块不负责

1. 掉落概率与掉落表权重。
2. 具体掉落物生成逻辑。
3. 遗物选择 UI 的视觉表现。
4. 特殊效果的执行器。
5. 营地图鉴解锁、结算和存档展示。

## 3. 设计原则

1. 数据驱动：遗物与羁绊都必须由 `data_config/relics.json` 和 `data_config/bonds.json` 驱动。
2. 统一入口：属性变化只通过 `ModifierStack` 叠加，不在角色脚本里直接改写最终数值。
3. 允许重复：同名遗物可以重复获得，但要受单遗物最大数量限制。
4. 只做生效：局内只要凑够层数就立即生效，不做额外解锁、装填或互斥机制。
5. 特殊效果延迟：当前只记录特殊效果配置，不执行具体逻辑。

## 4. 数据结构

### 4.1 relics.json 最小字段

```json
{
  "id": "relic_finance_manager",
  "display_name": "理财经理",
  "rarity": "uncommon",
  "bond_id": "bond_chosen",
  "tags": ["relic", "finance", "manager"],
  "max_stack": 0,
  "effects": [
    {
      "id": "mod_relic_finance_manager_interest_rate",
      "source_type": "relic",
      "source_id": "relic_finance_manager",
      "target_scope": "player",
      "stat": "interest_rate",
      "operation": "add_flat",
      "value": 1,
      "duration": -1,
      "stack_rule": "unique"
    }
  ]
}
```

### 4.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | String | 是 | 遗物唯一 ID |
| `display_name` | String | 是 | 遗物显示名 |
| `rarity` | String | 是 | 稀有度 |
| `bond_id` | String | 否 | 该遗物主要归属羁绊，便于图鉴和权重引用 |
| `tags` | Array[String] | 是 | 遗物标签；用于羁绊统计 |
| `max_stack` | int | 否 | 单局最大持有数量；`0` 表示不限制，`1` 以上表示最多持有对应数量 |
| `effects` | Array | 是 | 遗物带来的 modifier 列表 |
| `special_effects` | Array | 否 | 特殊效果记录字段，当前不执行 |

### 4.3 bonds.json 最小字段

```json
{
  "id": "bond_mighty",
  "name": "大力",
  "bond_tag": "melee",
  "thresholds": {
    "2": [{ "stat": "melee_damage", "value": 2 }],
    "4": [{ "stat": "melee_damage", "value": 4 }]
  }
}
```

### 4.4 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | String | 是 | 羁绊唯一 ID |
| `name` | String | 是 | 羁绊显示名 |
| `bond_tag` | String | 是 | 计数标签 |
| `thresholds` | Dictionary | 是 | 各层级生效效果 |

## 5. 羁绊归属与统计规则

1. 只有高稀有度（史诗/`epic`、罕见/`mythic`、传说/`legendary`）的武器与遗物才会配置 `bond_id`；普通/优良/稀有不携带羁绊。
2. 羁绊统计来源为**已持有且配置了 `bond_id` 的武器与遗物**，每件按 `bond_id` 计 1 层，不再按标签统计。
3. 同一羁绊由多件物品共同累计层数。
4. 羁绊层数按阈值判定：达到 2、4、6、7 层时依次生效对应效果。
5. 局内只要凑够阈值，效果立即生效，不需要额外确认。
6. `data_validator` 会校验：`bond_id` 只能出现在 epic/mythic/legendary 稀有度上，且必须引用 bonds 表中的 id。

### 5.1 羁绊展示

1. 武器条、遗物清单、升级奖励/商店卡片 hover 时，若该物品配置了 `bond_id`，在提示中追加一行“羁绊：xxx（当前 N 层）”；无 `bond_id` 则不展示。
2. 战斗 HUD 右上角（属性栏左侧）展示一个羁绊图标：仅当存在任一已激活羁绊时出现，取配置表中第一个持有数大于 0 的羁绊。
3. hover 图标弹出层级小窗：标题为“羁绊名（当前 N）”，每个阈值一行；已解锁层白色、未解锁层灰色，内容为该层的具体属性效果。

## 6. 遗物重复与上限

1. 同名遗物允许重复获得。
2. 每个遗物可通过 `max_stack` 控制最大持有数。
3. 若当前持有数量已达到 `max_stack`，则该遗物在后续刷新池中不再出现。
4. `max_stack = 0` 表示不限制数量。
5. 若未配置 `max_stack`，默认按 `0` 处理，表示不限制。

### 6.1 商店候选规则

1. 遗物商店候选只包含已解锁且当前持有数量未达到 `max_stack` 的遗物。
2. 遗物使用自身 `rarity` 参与商店稀有度抽取。
3. 遗物与武器本体、武器升级共用六档稀有度：普通、优良、稀有、珍贵、罕见、传说。
4. 免费奖励入口和付费商店入口共用同一套遗物候选池和刷新规则。
5. 商店不提供单独属性购买；遗物效果通过获得遗物后应用。

### 6.1 逻辑建议

- 掉落池先检查玩家已有数量。
- 若已满，则从候选池移除该遗物。
- 若所有候选都已满，则回退到普通奖励或其他遗物。

## 7. 效果结算顺序

推荐顺序如下：

1. 读取遗物静态配置。
2. 创建遗物实例并加入当前局内持有列表。
3. 将遗物 `effects` 转换为 `ModifierStack`。
4. 统计武器 + 遗物标签。
5. 计算当前羁绊层数。
6. 将羁绊阈值效果转换为 `ModifierStack`。
7. 通知玩家重新计算最终属性。

## 8. 特殊效果预留

1. `special_effects` 只记录配置，不执行。
2. 每条特殊效果应保留 `effect_id`、`trigger`、`params` 等基础结构。
3. 未来若新增条件触发、击杀触发、波次触发等逻辑，可直接在该字段扩展。

## 8.1 effects 字段说明

```json
{
  "id": "mod_relic_finance_manager_interest_rate",
  "source_type": "relic",
  "source_id": "relic_finance_manager",
  "target_scope": "player",
  "stat": "interest_rate",
  "operation": "add_flat",
  "value": 1,
  "duration": -1,
  "stack_rule": "unique"
}
```

| 字段 | 含义 |
|---|---|
| `id` | 这条效果自身的唯一 ID，便于调试、去重和日志定位。 |
| `source_type` | 来源类型，通常写 `relic`，表示它来自遗物。 |
| `source_id` | 来源对象 ID，表示这条效果属于哪件遗物。 |
| `target_scope` | 作用范围，通常写 `player`，表示加给玩家自身。 |
| `stat` | 要修改的属性 ID，例如 `melee_damage`。 |
| `operation` | 修改方式，例如 `add_flat` 表示固定值加成，`add_percent` 表示百分比加成。 |
| `value` | 具体数值。 |
| `duration` | 持续时间；`-1` 表示常驻到本局结束。 |
| `stack_rule` | 同类效果堆叠规则，例如 `unique` 表示同源只保留一份。 |

## 9. 与玩家模块的接口

### 9.1 输入

1. 玩家当前武器标签列表。
2. 玩家当前遗物列表。
3. 当前 `ModifierStack`。

### 9.2 输出

1. 更新后的最终属性。
2. 当前激活羁绊层数。
3. 当前遗物计数与最大数量状态。

## 10. MVP 实现范围

1. 遗物加载与实例化。
2. 遗物重复获取与 `max_stack` 判断。
3. 羁绊层数统计。
4. 羁绊阈值属性生效。
5. 启动自测打印。

暂不实现：

1. 遗物选择 UI。
2. 特殊效果执行器。
3. 图鉴界面。
4. 稀有度权重系统。

## 11. 结项判断

本模块可视为完成的条件：

1. Godot 启动后能读取 `relics.json` 与 `bonds.json`。
2. 能正确统计武器 + 遗物标签。
3. 能正确激活 2/4/6/7 层羁绊效果。
4. 能正确限制同名遗物的最大持有数。
5. 特殊效果字段可被读取但不执行。

## 11. 理财遗物扩展设计

### 11.1 机制目标

理财机制为局内金币增加“延迟收益”选择：第一波开始前不打开理财页；第 2 波起，玩家可在每波开始前进行一次本金操作，选择存入、取出或跳过；波次结束后，系统会按当前本金和利率自动结算利息，并把收益加入本金。

### 11.2 核心规则

1. 本金与局内金币分离：存入会扣除当前金币并增加本金，取出会减少本金并返还金币。
2. 每次弹窗只执行一种操作：存入、取出或跳过。
3. 快捷操作包括：全部存入、存入一半、全部取出、取出一半。
4. 自定义输入必须为非负整数；不可存入超过当前金币的数量，不可取出超过本金的数量，最终由理财系统统一校验。
5. 利息公式：`ceil(principal * interest_rate / 100)`。
6. 波末默认进行一次全额利息结算，收益加入本金。
7. 部分遗物可以触发额外结算、战斗中小额结算或永久提高利率。

### 11.3 运行状态字段

| 字段 | 说明 |
|---|---|
| `principal` | 当前理财本金 |
| `interest_rate` | 当前有效利率，基础利率 + modifier + 永久成长加成 |
| `interest_rate_bonus` | 由复利类遗物产生的局内永久利率成长 |
| `current_wave_number` | 当前理财操作对应波次 |
| `last_deposit_wave_number` | 最近一次存入本金的波次 |
| `has_deposited_before_current_wave` | 本波开战前是否发生过存入，用于高利契约 |
| `finance_stage_prepared` | 主流程是否已提前打开下一波理财页 |

### 11.4 流程接入

1. 波结束：`WaveManager.finish_current_wave()` 先吸收经验球和清场，再调用金融系统结算利息。
2. 结算展示：主流程进入 `interest_settlement`，可以读取 `finance_state.last_settlement_result` 展示收益。
3. 商店阶段：保留现有 `shop_popup` 状态。
4. 理财阶段：主流程在下一波开始前进入 `finance_popup`，调用 `prepare_finance_for_wave(next_wave_number)`，应用“每波开始”类遗物并构建弹窗 payload。
5. 玩家确认后：`submit_finance_operation(action, amount)` 校验并执行，关闭弹窗后进入区域选择或回到战斗准备。
6. 下一波开始：如果理财阶段已提前准备过该波，`WaveManager.start_next_wave()` 不重复应用每波开始类遗物。

### 11.5 遗物数据字段

静态属性仍写入 `effects`，事件型效果写入 `runtime_effects`：

```json
{
  "id": "relic_piggy_bank",
  "display_name": "猪猪存钱罐",
  "rarity": "common",
  "max_stack": 0,
  "tags": [],
  "effects": [],
  "runtime_effects": [
    { "trigger": "wave_start", "effect": "add_principal_flat", "value": 15, "free_principal": true }
  ]
}
```

支持的触发点：`on_acquire`、`wave_start`、`deposit`、`wave_end`、`interest_settle`、`interest_success`、`principal_zero`、`derived`、`enemy_kill`。

### 11.7 实现备注

- `effects` 只处理 modifier；`runtime_effects` 只作为事件型配置和校验记录。
- 金融执行器按“触发点 + effect 类型”通用分发，不再按遗物 ID 特判；遗物仅通过 JSON 声明 runtime_effects，新增效果只需扩展对应 effect 分支。
- 利率支持小数，便于 0.2% 和 0.3% 成长。
- “免费本金”不扣除当前金币，但仍计入本金和后续收益。
- 高利契约的存入门槛 由 `runtime_effects` 的 `minimum_deposit` 配置（默认P），仅统计本波开始前的玩家手动存入金额。
