# 战斗特效像素对齐检查与雷火尖角候选（2026-10-17）

## 本轮结论与修改范围

雷火审阅版已改为直边尖角、连片黄白色块：金黄色窄外缘、浅黄色中层、象牙白主体。沿用原有伤害、范围、密度预算与持续时间。改动位于 `shaders/reviews/reaction_blocks.gdshader` 的 `blast()`；组合反应候选总开关仍默认关闭，没有把尚待确认的整组候选安装到正式玩法。

本轮对结霜及其他视觉进行分析，没有批量修改正式特效。审查覆盖 14 种武器的视觉入口、9 种有独立视觉的附魔、11 类组合反应（包括无独立动画的光暗抵消）、4 类敌人的状态/技能，以及受击、屏幕震动、复活、阴影、战斗文字等公共层。机制类附魔如分裂、弹射、多投复用对应武器，不算独立美术。

**结霜的主要问题是旧霜纹被非整数放大，并以半透明色块叠在怪物上方；不是 1920×1080 把整幅战斗画面滤糊了。** 另有小窗口降采样、旋转/缩放后的网格不均、抗锯齿小图标等独立问题。

## 1. 分辨率管线：1080p 正常，小窗口会丢细节

实际运行值：

| 项目 | 1920×1080 窗口 | 1152×648 窗口 |
| --- | --- | --- |
| 世界 SubViewport | 1920×1080 | 1920×1080 |
| UI 设计画布 | 1152×648 | 1152×648 |
| 世界容器比例 | 0.6 | 0.6 |
| 窗口最终变换 | 1.666667 | 1.0 |
| 世界到显示画面的有效比例 | **1.0** | **0.6** |
| 世界和容器采样 | 最近邻 | 最近邻 |
| Camera2D.zoom | (1, 1) | (1, 1) |

`GameRoot` 把世界容器缩到 UI 的逻辑尺寸，窗口最终变换再映射到物理画面；这两个几何变换不是两次中间图片采样。实测在 1080p 下，战斗局部 500×300 的 **150,000 个像素**，世界原始纹理和最终窗口图像完全相同。没有经过 1152 的中间低清图片。

1152 窗口则确实把世界压到 60%。最近邻不会产生平滑过渡，但 1px 细线可能消失，2px/3px 色块可能显示为不等宽的格子。1440p、其他非整数显示比例也可能出现宽度不均。这是输出比例问题，不能靠把每个素材统一乘 1.667 来修正。

查验 `assets/effects`、`assets/sprites/weapons`、`assets/sprites/enemies` 下 92 份 PNG 导入配置，均未启用 mipmap、导入尺寸限制或有损压缩模式。不能因此说所有视觉都已对齐：后续的绘制变换和源图透明度同样会影响效果。

代码依据：`scripts/core/game_root.gd`、`project.godot`、`scripts/tests/effect_pixel_alignment_review.gd`。

## 2. 结霜：体型来源、源图密度和覆盖层都没有协调

`EnemyStatusVisual._get_body_radius()` 只识别圆形碰撞体。虫、冲锋者、冥狼已经使用胶囊体，因此函数回退到“动画帧画布尺寸 × 精灵比例 ÷ 2”，包含透明留白，不是真正的身体半径；圆形分支又没有计算碰撞节点自身的缩放。

旧 `slowed` 图集一帧是 64×40，但实际有颜色的区域仅 **32×20**。绘制比例为 `body_radius × 0.88 / 16`。基础体型实测如下：

| 敌人 | 碰撞体半径 | 被状态代码采用的半径 | 旧霜纹缩放 | 有色区域约占世界像素 |
| --- | ---: | ---: | ---: | ---: |
| 虫怪 | 22，胶囊 | 64 | **3.52×** | 113×70 |
| 回声蝙蝠 | 16，圆形 | 16 | **0.88×** | 28×18 |
| 冲锋小 Boss | 32，胶囊 | 128 | **7.04×** | 225×141 |
| 冥狼小 Boss（当前姿态） | 36.8，胶囊 | 104.8576 | **5.767×** | 185×115 |

这里的有色区域与整帧画布不同：例如虫怪整帧绘制矩形是 225.28×140.8，约一半是透明留白。冥狼的精灵比例会随注册后的动画姿态变化，回退算法也会把姿态变化带入状态尺寸；这不适合作为稳定的状态锚点。

源图还有 19 档非零透明度。放大后，大块浅蓝、半透明交叠和不均匀像素边同时出现。状态层 `z_index=25`，统一偏移 `(0,12)`，覆盖在怪物上方，造成截图里“身体被打了蓝色马赛克”的感觉。

已在真实弓箭附冰命中后暂停同一个场景，分别保存“显示状态层”和“仅隐藏状态层”的截图。后者的身体轮廓恢复清楚，冰场、人物、怪物素材保持原样。这张对照只用于定位问题，**不是取消结霜的修改方案**。

同一半径函数还负责湿润/光/暗图标位置、冻结冰壳尺寸选择和燃烧火舌布局。冻结冰壳采用固定尺寸帧、没有相同的 3.52× 放大，但也会因为半径错误而选到最大尺寸。需要一起统一锚点，不能只改一行霜纹 scale。

此外，眩晕星点的 `lightning_status_visual.gd` 也只识别圆形体；胶囊体落到默认半径 10，可能把头顶星点放得过低。它与霜纹的错误方向相反，同属旧体型接口未更新。

建议修正顺序：为每种怪物定义稳定的身体/脚底/头顶视觉锚点，处理挑战体型倍率；霜纹按目标显示尺寸重新绘制或生成硬边像素块，不把 32×20 有效旧图直接放大；地面霜与身体冰壳分层。保留用户确认的怪物大小。

## 4. 武器：保持批准的大小，修正渲染方式

最近邻保证不会把相邻颜色平滑混合；它不保证任意缩放/旋转后每格仍是同样宽度。下表中的“变换风险”不等同于当前造型需要回退，也不代表每个方向都肉眼模糊。

| 武器 | 现行路径 | 对齐情况 |
| --- | --- | --- |
| 木质弓箭 | 投射物精灵，随方向旋转和范围参数缩放 | 基础最近邻；旋转与尺寸增益存在网格不均风险。 |
| 电浆炮 | 24×24 球体贴图拉到 `2×core_radius`；基础半径 12，电弧为像素几何 | 基础球体 1:1；范围增益后可能非整数缩放。 |
| 铸铁榴弹炮 | 128×128 爆炸图集拉到实际爆炸直径，地面爆炸有椭圆投影 | 范围变化和投影会改变每格宽高；需要目标尺寸绘制方案。 |
| 坤舆秘仪书 | 命中图集 96×128 按原尺寸；领域层按实际范围缩放，内部符文旋转 | 命中主体正常；领域的网格仍可能不均。旧 0.5× 指纹辅助函数已不走当前绘制入口，不列为现行问题。 |
| 食利者钱包 | 钱币 16×16；分裂币缩到 12×12；命中用原尺寸图集 | 普通命中主体正常；分裂币 0.75× 和范围增益有细节损失风险。 |
| 赤铜炉灯 | 2px 屏幕方向网格内计算火焰和地面投影，节点不随瞄准旋转 | **对齐较好，可作为方向型特效的实现参考。** |
| 异化触手 | 160×128 图集随距离/半径分别缩放，再旋转；分支额外 0.65× | 基础尺寸时较好；斜向、升级、分支的格子宽高不完全统一。 |

| 营地短刀 | 刀花图集按攻击距离连续缩放，再做地面方向投影 | 造型已获认可；仍有变换造成的像素宽度不均。 |

| 流星摆锤 | 轨迹图集跟随锤头位置缩放、镜像、旋转、地面投影 | 变换叠加较多，斜向轨迹像素一致性是后续重点。 |

| 巨型手持火炮 | 炮口喷火采用 3px 网格内的方向/投影计算；弹丸、分裂弹和后坐烟另走图集 | **喷火主体正常**；弹丸大小、后坐烟旋转属于次级风险。 |

## 6. 其他公共层与敌人技能

- **屏幕震动的单位仍按 UI 画布换算。** `_set_screen_offset()` 把偏移除以容器父 viewport 的 1152×648，随后去采样 1920×1080 世界纹理。水平输入 1/2/6 对应世界纹理位移约 1.667/3.333/10 像素，再由最近邻落到整像素。已暂停同一实机画面调用这条表现接口，逐图比对得到实际平移 **2/3/10px**。如果目标是“1080p 下的 1/2/6 像素”，这处没有统一单位；它影响力度与步进，不会产生双线性模糊。建议统一以世界渲染像素定义，再转换 UI 附属层。
- **怪物受击变白和自身震动**：白色 shader 只改颜色；震动偏移先按世界像素取整，再转回精灵局部坐标。这条路径没有新增纹理滤波，也没有把已删除的通用旧命中特效重新启用。
- **湿润、光、暗状态图标**：共同受体型/锚点问题影响。太阳线和暗眼斜线还使用 `draw_line(..., true)` 抗锯齿，部分顶点是分数坐标；这是明确的软边来源，适合改硬边小色块。
- **霸体/伤害/反应文字**：霸体文字 18px 字号后再缩到 0.7；伤害数字入场从 0.84/0.92 动画缩到 1；反应名使用 12px 像素字体的 14px 字号。需要区分有意的弹出动画和稳定字形的清晰度，不能把所有字体缩放都归因于世界分辨率。
- **光晕照明层**：共享粒子灯是四层半透明圆盘，闪电命中光晕也包含低透明度层。它们本来就是柔和照明，不是主体贴图被模糊；若要求连光晕也严格色块化，应单独审阅其美术变化。
- **敌人阴影**：尺寸先落到整像素，再生成对应大小的阶梯色块纹理，位置取整；不复用一张小图任意拉伸。当前路径已对齐。
- **回声蝙蝠技能**：蓄力图 0.52×、声波 0.625× 后旋转、命中图 0.75×；预警按范围伸缩。属于明显的缩小/旋转细节风险。
- **冲锋小 Boss 预警**：旋转细线、透明填色和小方点，非固定屏幕像素网格。硬边为主，但细线在小窗口更容易断。
- **冥狼技能**：鬼火仿炉灯在 2px 网格内计算方向，主体对齐较好；身体动画使用每姿态注册比例，相关状态锚点应独立于姿态比例。
- **虫怪**：没有另一套独立技能贴图，主要问题是上述公共状态层。
- **复活羽翼**：2px 程序化网格、18fps 离散姿态，未发现同类旧图放大问题。

场景地面、草、远景雾不是本清单中的武器/状态特效；本轮没有改动这些场景美术。

## 7. 建议优先级

1. 先处理结霜的体型依据、原生像素密度和分层，同时统一所有敌人状态锚点；统一屏幕震动的像素单位。
2. 保留已批准的造型和大尺寸，将风刃方向、枪芒生长、锤风/裂地、摆锤轨迹、范围增益中的绘制落到最终网格。固定目标大小的资源可重制成目标像素尺寸；动态范围优先在网格上重新绘制，避免把整张小图连续拉伸。
3. 再处理抗锯齿状态图标、蝙蝠小图缩放、战斗文字和光晕；黑洞细线保留为用户批准的风格例外。
4. 单独决定小窗口策略：固定 1080p 世界仍可用，但 1152 窗口无法无损保留每个世界像素。若必须兼容小窗口清晰细线，需要响应式像素绘制或不同世界渲染规格，不能只调素材 scale。
