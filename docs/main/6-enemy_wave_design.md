# 敌人与波次模块详细设计方案

本文档定义敌人实体、波次推进、刷怪调度、敌人受击/死亡、以及和掉落表、玩家战斗循环之间的接口。它只负责“敌人如何出现、如何移动、如何受击、何时死亡、波次如何推进”，不负责武器自动攻击、玩家 UI、营地成长和遗物羁绊。

## 1. 模块目标

1. 建立统一的敌人实体根节点与脚本结构。
2. 支持波次时间轴驱动的刷怪。
3. 支持敌人追踪玩家并进入战斗。
4. 支持敌人受击、死亡、掉落表引用。
5. 支持波次结束与下一波开始的切换。
6. 为后续精英怪、BOSS、阶段事件和特殊词缀预留扩展口。

## 2. 模块边界

### 2.1 本模块负责

1. 敌人静态配置读取。
2. 敌人场景实例化。
3. 刷怪调度与波次时间推进。
4. 敌人基础 AI。
5. 敌人血量、护甲、移动、受击和死亡。
6. 敌人死亡后向掉落模块发出掉落请求。

### 2.2 本模块不负责

1. 武器自动攻击与索敌。
2. 经验球、金币、遗物的具体生成表现。
3. 玩家局外成长。
4. 营地建筑升级效果。
5. 复杂 Boss 机制与阶段技细节。

## 3. 设计原则

1. 配置驱动：敌人与波次都必须由 `data_config/enemies.json` 和 `data_config/waves.json` 驱动。
2. 实体独立：每个敌人都是独立 Node 实例，便于后续碰撞、动画、受击与死亡表现。
3. 波次解耦：波次只负责“什么时候刷什么”，不直接关心敌人 AI 细节。
4. 强校验：所有 `enemy_id`、`drop_table_id`、`spawn_groups` 引用都必须可校验。
5. 简单优先：MVP 先做普通怪，后续再加精英/BOSS 与词缀。

## 4. 数据结构

### 4.1 enemies.json 最小字段

```json
{
  "id": "enemy_mutated_grub",
  "display_name": "天外幼体",
  "description": "最基础的近战追踪小怪示例。",
  "enabled": true,
  "tags": ["enemy", "normal", "melee", "void"],
  "enemy_type": "normal",
  "base_stats": {
    "max_hp": 20,
    "armor": 0,
    "move_speed": 100,
    "melee_damage": 8
  },
  "ai_type": "chase_player",
  "scene": "res://scenes/enemy/mutated_grub.tscn",
  "drop_table_id": "drop_basic_enemy"
}
```

### 4.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | String | 是 | 敌人唯一 ID |
| `display_name` | String | 是 | 敌人显示名 |
| `description` | String | 否 | 描述文本 |
| `enabled` | bool | 否 | 是否启用 |
| `tags` | Array[String] | 是 | 敌人标签，用于筛选与统计 |
| `enemy_type` | String | 是 | 敌人类型，例如 `normal`、`elite`、`boss` |
| `base_stats` | Dictionary | 是 | 敌人基础属性 |
| `ai_type` | String | 是 | AI 类型，例如 `chase_player` |
| `scene` | String | 是 | 敌人场景路径 |
| `drop_table_id` | String | 是 | 死亡后引用的掉落表 ID |

### 4.3 waves.json 最小字段

```json
{
  "id": "wave_stage_01",
  "duration_seconds": 20,
  "spawn_groups": [
    {
      "enemy_id": "enemy_mutated_grub",
      "spawn_interval_ms": 1200,
      "count_per_spawn": 3
    }
  ]
}
```

### 4.4 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | String | 是 | 波次唯一 ID |
| `duration_seconds` | int | 是 | 单波持续时间，单位秒 |
| `spawn_groups` | Array | 是 | 该波次的刷怪组列表 |

### 4.5 spawn_groups 子结构

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `enemy_id` | String | 是 | 引用 `enemies.json` 的敌人 ID |
| `spawn_interval_ms` | int | 是 | 每次刷怪间隔，单位毫秒 |
| `count_per_spawn` | int | 是 | 每次生成数量 |

## 5. 波次时间规则

1. 不使用 `time_start/time_end` 区间式配置。
2. 每波单独计时，配置字段为 `duration_seconds`。
3. 波次时长使用 `min(15 + 5 * wave_index, 50)`。
4. 第 1 波为 20 秒，第 2 波为 25 秒，最高 50 秒。
5. 波次结束时，先停刷怪，再统一吸取场上所有经验球并结算经验、金币与升级，再清理其他奖励拾取物并清空场上敌人，最后进入下一波休整。

## 6. 敌人实体设计

### 6.1 敌人节点建议结构

1. `EnemyRoot`：敌人根节点，负责整体逻辑。
2. `CollisionShape2D`：实体碰撞。
3. `Sprite2D` 或 `AnimatedSprite2D`：敌人表现。
4. `HurtBox`：受击区域。
5. `HitBox`：敌人与玩家发生接触时的判定区域。

### 6.2 敌人运行状态

1. `enemy_id`
2. `enemy_data`
3. `current_hp`
4. `alive`
5. `target_player`
6. `move_speed`
7. `contact_damage`
8. `knockback_velocity`
9. `has_contact_damaged`：当前接触段是否已造成伤害；敌人与玩家拉开到重置半径后恢复为 false。

## 7. 基础 AI 规则

### 7.1 MVP AI

当前只实现 `chase_player`：

1. 寻找最近玩家。
2. 朝玩家位置移动。
3. 与玩家碰撞时立刻造成一次接触伤害。
4. 接触伤害读取敌人 `melee_damage`。
5. 一次碰撞只造成一次伤害。
6. 造成碰撞伤害后，敌人立刻被弹开；拉开到重置半径后允许下一次独立碰撞伤害。
7. 弹开结束后，敌人重新进入追逐玩家状态。

### 7.2 后续可扩展 AI

1. 停顿射击。
2. 突进。
3. 远程弹幕。
4. 圈地巡逻。
5. Boss 分阶段 AI。

## 8. 伤害与死亡规则

1. 敌人受击时读取最终伤害值。
2. 敌人护甲按基础数值模块的护甲曲线参与减伤。
3. 敌人血量降到 0 时死亡。
4. 敌人死亡后掉落经验球。
5. 玩家拾取经验球时获得经验和等额基础金币。
6. 波次结束后统一吸取并结算场上所有经验球。

## 9. 掉落表接口

### 9.1 敌人到掉落表

敌人配置中的 `drop_table_id` 指向 `drop_tables.json`，敌人死亡时读取该表并生成对应经验球或概率奖励请求。

### 9.2 掉落表建议职责

1. 决定基础经验值。
2. 根据基础经验值同步产生等额基础局内金币。
3. 决定血包、遗物、其他奖励的概率。
4. 死亡时生成经验球，经验球被拾取后结算经验与金币。
5. 波次结束后只统一吸取场上所有未拾取经验球；血包等即时奖励不参与收尾吸收。

## 9.3 角色升级与共享奖励/商店页

1. 玩家获得经验后，若达到升级条件，立即触发一次共享奖励/商店页的免费领取机会。
2. 免费领取不消耗局内金币。
3. 免费领取仍需遵守武器负载上限、遗物 `max_stack`、配置池过滤等规则。
4. 若一次经验结算连续升多级，则按升级次数依次触发多次免费领取机会。
5. 共享奖励/商店页具体 UI 和选项池由后续“掉落与奖励/商店模块”实现，本模块只负责发出升级触发事件。

## 10. 刷怪调度

### 10.1 调度原则

1. 波次系统按当前战斗时间推进。
2. 在 `duration_seconds` 内按 `spawn_groups` 刷怪。
3. 同一波内可存在多个刷怪组。
4. 刷怪点在玩家周围随机生成。
5. 刷怪距离玩家最小 1000、最大 1500。
6. 若随机点超出战斗边界，由敌人生成器重新采样或钳制到边界内。

### 10.2 MVP 刷怪逻辑

1. 读取当前波次。
2. 按组定时生成敌人。
3. 每次刷出 `count_per_spawn` 个敌人。
4. 每个敌人生成在玩家周围 1000~1500 距离环内。
5. 波次结束后停止本波刷怪，统一吸取场上经验球，并清空场上敌人。
6. 波次结束经验结算后处理升级与共享奖励/商店页触发。

## 11. MVP 实现范围

1. 读取敌人和波次配置。
2. 生成普通敌人。
3. 支持 `chase_player`。
4. 支持敌人碰撞伤害。
5. 支持受击与死亡。
6. 支持死亡后引用掉落表并掉落经验球。
7. 支持波次时间推进与刷怪节奏。
8. 支持波次结束统一吸取场上经验球并清场。
9. 支持经验达标后触发共享奖励/商店页事件。

暂不实现：

1. 精英怪特殊词缀。
2. Boss 阶段技。
3. 路径寻路。
4. 群体 AI 协同。
5. 敌人技能树。

## 12. 结项判断

本模块可视为完成的条件：

1. Godot 启动后能读取 `enemies.json` 与 `waves.json`。
2. 能按 `duration_seconds` 持续刷出敌人。
3. 敌人能在玩家周围 1000~1500 范围内生成。
4. 敌人能朝玩家移动、造成碰撞伤害并受击死亡。
5. 敌人碰撞玩家后能造成一次伤害、立刻弹开；拉开到重置半径后重新追逐并允许下一次独立碰撞伤害。
6. 波次结束后能统一吸取场上经验球、清理其他奖励拾取物并清空场上敌人。
7. 敌人死亡后能正确关联 `drop_table_id` 并掉落经验球。
8. 波次结束经验结算后，升级能触发共享奖励/商店页事件。
9. 配置校验能拦截错误的 `enemy_id` 与 `drop_table_id` 引用。
