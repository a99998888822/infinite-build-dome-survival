# 敌人与波次模块详细设计方案

本文档定义敌人实体、波次推进、刷怪调度、敌人受击/死亡、以及和掉落表、玩家战斗循环之间的接口。它只负责“敌人如何出现、如何移动、如何受击、何时死亡、波次如何推进”，不负责武器自动攻击、玩家 UI、营地成长和遗物羁绊。

## 当前难度规则

`BattleDifficulty` 统一定义选择卡片和战斗参数，角色确认时由 `MainFlowCoordinator` 传给 `WaveManager.initialize`，整局固定。难度以字符串数字 `1`、`2`、`3` 标识，每次新开局默认1。旧 `beginner`／`standard` 映射为1，`hard`／`nightmare` 映射为3，未知值回退1。下列规则优先于后文早期示例。

| 参数 | 1－标准难度 | 2－属性加强20% | 3－属性加强30%，精英更频繁 |
| --- | --- | --- | --- |
| 生命、伤害、护甲、移速相对标准倍率 | 1.0 | 1.2 | 1.3 |
| 首波普通怪生命 / 实际接触伤害 / 移速（取整后） | 24 / 4 / 85 | 29 / 5 / 102 | 31 / 5 / 111 |
| 配置刷怪数量倍率（向上取整） | 0.15 | 0.22 | 0.30 |
| 最终批次数量倍率（属性加成取整后） | 1 | 1 | 1 |
| 基础刷新间隔倍率 | 2.70 | 2.40 | 2.10 |
| 首批延迟（秒；各组再错开0.6秒） | 2.0 | 2.0 | 2.0 |
| 同屏普通调度敌人上限 | 48 | 72 | 96 |
| 普通怪每波增加生命（取整前，不计侵蚀） | 200/19 ≈ 10.53 | 240/19 ≈ 12.63 | 260/19 ≈ 13.68 |
| 小 Boss 每波生命乘数 | 1.24 | 1.24 | 1.24 |
| 每波伤害 / 移速增幅（百分点） | 1.5 / 0.5 | 1.5 / 0.5 | 1.5 / 0.5 |
| 每波基础增加护甲（再乘难度倍率） | 0.5 | 0.5 | 0.5 |
| 每波刷怪数量 / 刷新频率增幅（百分点） | 6 / 2.5 | 6 / 2.5 | 6 / 2.5 |
| 最早出现小Boss（此后每波至少1只） | 第2波 | 第2波 | 第2波 |
| 小Boss原始期望数量倍率 | 1.0 | 1.15 | 1.3 |

标准档单怪属性倍率：敌人配置生命×0.8、伤害×0.45、移速×0.85，护甲×1.0。普通怪配置基础生命为30、伤害为9；标准生命采用 `round(24 + 200 × (波次 - 1) / 19)`。2、3档在取整前分别统一乘1.2、1.3。钢甲骑士基础生命600、近战伤害12，幽焰冥狼基础生命720；两种小 Boss 的生命均保留24%复利波次成长，同样接受难度和侵蚀修正。2026-10-09基础生命已提高至原来的3倍，详见 [获取与生命调整](reward_access_balance.md)。

侵蚀继续独立叠加，常规小 Boss 配额上限为每波3只，挑战可另追加2只。第1波不生成，第2波起期望为 `min(3, max(1, 波次/8) × 难度倍率 × (1 + clamp(侵蚀/100, 0, 1)))`，按相邻整数抽样，因此每波至少1只；波初固定配额，仅前半波生成。三档通过组内数量、刷新间隔和在场上限区分密度；普通怪基础奖励为4经验＋4金币，小 Boss为8经验＋8金币。初心者基础生命30；近战、远程、元素基础伤害每波增加1.5个百分点。

2026-10-09 增加强化曲线：基础间隔再除以 `BattleDifficulty.SPAWN_DENSITY_CURVE`。第1—5波为2.15倍，第10波约1.78倍，第15波约1.50倍，第20波1.20倍；逐波配置避开批次数量取整台阶，三个难度的理论供给速度均不倒退。首批仍在2秒、2.6秒出现，最短间隔仍为300毫秒，哥布林永久频率加成继续叠加。上限扩容用于容纳新增供给，并不承诺同场存活数量恰好等比例增长。

整波调度对比见 [2026-10-09 曲线与数据](../../artifacts/reviews/spawn_density_20261009/README.md)。`spawn_density_test.tscn` 检查全部60组整波供给、前5波小怪至少翻倍、第20波约增加20%、第2—5波不击杀时小Boss仍然出现以及在场上限。

所有敌人均在玩家当前位置周围400—500世界单位刷新。同次调度的各刷怪组及挑战追加小 Boss共用首个刷新方向，后续落点集中在其±8°扇区内；每个候选位置尝试避开其他敌人32单位，拥挤时优先保留距离与聚集约束。每批重新选方向，不保证位于屏幕外。

以下为2026-10-09强化前的20秒刷怪调度历史基线（持续移除敌人以排除同屏上限干扰；无侵蚀加成）：

| 波次 | 难度1：数量 / 血量 | 难度2：数量 / 血量 | 难度3：数量 / 血量 |
|---|---|---|---|
| 1 | 10 / 24 | 19 / 29 | 26 / 31 |
| 5 | 19 / 66 | 26 / 79 | 39 / 86 |
| 10 | 34 / 119 | 54 / 142 | 71 / 154 |
| 15 | 42 / 171 | 76 / 206 | 104 / 223 |
| 20 | 68 / 224 | 101 / 269 | 158 / 291 |

所有60组“难度×波次”检查覆盖线性血量、供给成长及密度差异；普通怪接触伤害取整后为4–7点。数量表示累计生成，并非在场数量。对应回归为 `wave_pressure_test.tscn`，另覆盖成群刷新、拥挤回退及小 Boss独立生命。主动战斗数值见 [正式接入记录](active_combat_implementation.md)；旧实机对比保留原录制数值。

## 2026-10-07 侵蚀与秒怪生命强化（已启用）

侵蚀 `E = max(波初侵蚀, 0)`。生命倍率为 `1 + 0.018E + 0.018max(E−30,0) + 0.018max(E−60,0)`；近战、远程、元素伤害倍率为 `1 + 0.009E + 0.003max(E−30,0) + 0.003max(E−60,0)`。护甲保留 `1 + 0.0135E`，移速、刷新数量、Boss配额不因本次修改额外增加。30、60处连续，无数值跳变，60以上按最终斜率继续增长，不封顶。配置在 `erosion_pressure_rules.json`。

| 侵蚀 | 生命倍率 | 伤害倍率 | 护甲倍率 |
|---|---:|---:|---:|
| 0 | 1.00 | 1.00 | 1.00 |
| 30 | 1.54 | 1.27 | 1.405 |
| 50 | 2.26 | 1.51 | 1.675 |
| 60 | 2.62 | 1.63 | 1.81 |
| 100 | 4.78 | 2.23 | 2.35 |
| 200 | 10.18 | 3.73 | 3.70 |

秒怪强化由 `enemy_adaptation_rules.json` 配置，`EnemyWavePressure` 持有本局状态。首次有效受伤至死亡不超过1秒计为秒怪；小怪至少20个有效样本，小Boss至少1个，分别统计。上一波战斗观察至少15秒、秒怪比例至少80%且未明显吃力时，下一波小怪额外生命加10个百分点，上限60%；小Boss加5个百分点，上限30%。最早第4波生效。加成按档位相加，不逐波复利。

已有战斗压力判定为吃力时回退一档；否则，同类样本充足且连续两波秒怪比例低于50%时回退一档。中间区间或样本不足保持档位并清零连续慢杀计数。吃力沿用现有规则：近期平均残敌达到 `max(15, ceil(同屏上限×30%))`、本波三次从半血以上掉到半血以下，或累计低于半血至少5秒。回退不低于0，不降低基础波次强度。

已受伤且存活超过1秒的敌人按未秒杀计入；未交战、观察不足1秒的残敌、召唤物及奖励进度排除对象不计入。范围、持续伤害与致死首击正常统计；暂停不推进时钟，不接受伤害样本。常规战斗及最多10秒清剿共用战斗时钟；波末先决策再清场，清场不当作击杀。新开局清零，已有与本波后续敌人共用固定生命档位。

最终生命在取整前叠加 `原有波次/难度生命 × 侵蚀倍率 × (1 + 本类秒怪加成)`，只额外修改生命。界面侵蚀说明显示按当前侵蚀计算的倍率，波次面板显示强化标记及本波两类生命加成。未接入本金压力，也未恢复任何玩家属性全局上限。

## 1. 模块目标

当前小 Boss 造型为钢甲骑士，沿用 `enemy_elite_rusher` ID。玩家进入 240 距离且冷却结束后才开始 0.8 秒预警；随后在 0.16 秒内冲刺并挥锤，收招 0.5 秒、冷却 6 秒。预警保持直角矩形，内部不透明度 12%，强化两侧红色边缘与方粒。数量、属性与掉落沿用上方现行难度规则；资源与判定细节见 [接入说明](../asset/iron_knight_integration.md)。

1. 建立统一的敌人实体根节点与脚本结构。
2. 支持波次时间轴驱动的刷怪。
3. 支持敌人追踪玩家并进入战斗。
4. 支持敌人受击、死亡、掉落表引用。
5. 支持波次结束与下一波开始的切换。
6. 为后续精英怪、BOSS、阶段事件和特殊词缀预留扩展口。

## 2. 模块边界

### 2.1 本模块负责

1. 敌人静态配置读取。
2. 敌人场景实例化。
3. 刷怪调度与波次时间推进。
4. 敌人基础 AI。
5. 敌人血量、护甲、移动、受击和死亡。
6. 敌人死亡后向掉落模块发出掉落请求。

### 2.2 本模块不负责

1. 武器自动攻击与索敌。
2. 经验球、金币、遗物的具体生成表现。
3. 玩家局外成长。
4. 营地建筑升级效果。
5. 复杂 Boss 机制与阶段技细节。

## 3. 设计原则

1. 配置驱动：敌人与波次都必须由 `data_config/enemies.json` 和 `data_config/waves.json` 驱动。
2. 实体独立：每个敌人都是独立 Node 实例，便于后续碰撞、动画、受击与死亡表现。
3. 波次解耦：波次只负责“什么时候刷什么”，不直接关心敌人 AI 细节。
4. 强校验：所有 `enemy_id`、`drop_table_id`、`spawn_groups` 引用都必须可校验。
5. 简单优先：MVP 先做普通怪，后续再加精英/BOSS 与词缀。

## 4. 数据结构

### 4.1 enemies.json 最小字段

```json
{
  "id": "enemy_mutated_grub",
  "display_name": "天外幼体",
  "description": "最基础的近战追踪小怪示例。",
  "enabled": true,
  "tags": ["enemy", "normal", "melee", "void"],
  "enemy_type": "normal",
  "base_stats": {
    "max_hp": 20,
    "armor": 0,
    "move_speed": 100,
    "melee_damage": 8
  },
  "ai_type": "chase_player",
  "scene": "res://scenes/enemy/mutated_grub.tscn",
  "drop_table_id": "drop_basic_enemy"
}
```

### 4.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | String | 是 | 敌人唯一 ID |
| `display_name` | String | 是 | 敌人显示名 |
| `description` | String | 否 | 描述文本 |
| `enabled` | bool | 否 | 是否启用 |
| `tags` | Array[String] | 是 | 敌人标签，用于筛选与统计 |
| `enemy_type` | String | 是 | 敌人类型，例如 `normal`、`elite`、`boss` |
| `base_stats` | Dictionary | 是 | 敌人基础属性 |
| `ai_type` | String | 是 | AI 类型，例如 `chase_player` |
| `scene` | String | 是 | 敌人场景路径 |
| `drop_table_id` | String | 是 | 死亡后引用的掉落表 ID |

### 4.3 waves.json 最小字段

```json
{
  "id": "wave_stage_01",
  "duration_seconds": 20,
  "spawn_groups": [
    {
      "enemy_id": "enemy_mutated_grub",
      "spawn_interval_ms": 1200,
      "count_per_spawn": 3
    }
  ]
}
```

### 4.4 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | String | 是 | 波次唯一 ID |
| `duration_seconds` | int | 是 | 单波持续时间，单位秒 |
| `spawn_groups` | Array | 是 | 该波次的刷怪组列表 |

### 4.5 spawn_groups 子结构

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `enemy_id` | String | 是 | 引用 `enemies.json` 的敌人 ID |
| `spawn_interval_ms` | int | 是 | 每次刷怪间隔，单位毫秒 |
| `count_per_spawn` | int | 是 | 每次生成数量 |

## 5. 波次时间规则

1. 不使用 `time_start/time_end` 区间式配置。
2. 每波单独计时，配置字段为 `duration_seconds`。
3. 波次时长使用 `min(15 + 5 * wave_index, 50)`。
4. 第 1 波为 20 秒，第 2 波为 25 秒，最高 50 秒。
5. 波次结束时，先停刷怪，再统一吸取场上所有经验球并结算经验、金币与升级，再清理其他奖励拾取物并清空场上敌人，最后进入下一波休整。

## 6. 敌人实体设计

### 6.1 敌人节点建议结构

1. `EnemyRoot`：敌人根节点，负责整体逻辑。
2. `CollisionShape2D`：实体碰撞。
3. `Sprite2D` 或 `AnimatedSprite2D`：敌人表现。
4. `HurtBox`：受击区域。
5. `HitBox`：敌人与玩家发生接触时的判定区域。

### 6.2 敌人运行状态

1. `enemy_id`
2. `enemy_data`
3. `current_hp`
4. `alive`
5. `target_player`
6. `move_speed`
7. `contact_damage`
8. `knockback_velocity`
9. `has_contact_damaged`：当前接触段是否已造成伤害；敌人与玩家拉开到重置半径后恢复为 false。

## 7. 基础 AI 规则

### 7.1 MVP AI

当前只实现 `chase_player`：

1. 寻找最近玩家。
2. 朝玩家位置移动。
3. 与玩家碰撞时立刻造成一次接触伤害。
4. 接触伤害读取敌人 `melee_damage`。
5. 一次碰撞只造成一次伤害。
6. 造成碰撞伤害后，敌人立刻被弹开；拉开到重置半径后允许下一次独立碰撞伤害。
7. 弹开结束后，敌人重新进入追逐玩家状态。

### 7.2 后续可扩展 AI

1. 停顿射击。
2. 突进。
3. 远程弹幕。
4. 圈地巡逻。
5. Boss 分阶段 AI。

## 8. 伤害与死亡规则

1. 敌人受击时读取最终伤害值。
2. 敌人护甲按基础数值模块的护甲曲线参与减伤。
3. 敌人血量降到 0 时死亡。
4. 敌人死亡后，玩家按 `on_kill_heal` 恢复固定生命值。
5. 敌人死亡后掉落经验球。
6. 玩家拾取经验球时获得经验和等额基础金币。
7. 波次结束后统一吸取并结算场上所有经验球。

## 9. 掉落表接口

### 9.1 敌人到掉落表

敌人配置中的 `drop_table_id` 指向 `drop_tables.json`，敌人死亡时读取该表并生成对应经验球或概率奖励请求。

### 9.2 掉落表建议职责

1. 决定基础经验值。
2. 根据基础经验值同步产生等额基础局内金币。
3. 决定血包、遗物、其他奖励的概率。
4. 死亡时生成经验球，经验球被拾取后结算经验与金币。
5. 波次结束后只统一吸取场上所有未拾取经验球；血包等即时奖励不参与收尾吸收。

## 9.3 角色升级与共享奖励/商店页

1. 玩家获得经验后，若达到升级条件，立即触发一次共享奖励/商店页的免费领取机会。
2. 免费领取不消耗局内金币。
3. 免费领取仍需遵守武器负载上限、遗物 `max_stack`、配置池过滤等规则。
4. 若一次经验结算连续升多级，则按升级次数依次触发多次免费领取机会。
5. 共享奖励/商店页具体 UI 和选项池由后续“掉落与奖励/商店模块”实现，本模块只负责发出升级触发事件。

## 10. 刷怪调度

### 10.1 调度原则

1. 波次系统按当前战斗时间推进。
2. 在 `duration_seconds` 内按 `spawn_groups` 刷怪。
3. 同一波内可存在多个刷怪组。
4. 刷怪点在玩家周围随机生成。
5. 刷怪距离玩家最小 1000、最大 1500。
6. 若随机点超出战斗边界，由敌人生成器重新采样或钳制到边界内。

### 10.2 MVP 刷怪逻辑

1. 读取当前波次。
2. 按组定时生成敌人。
3. 每次刷出 `ceil(count_per_spawn * (1 + enemy_spawn_rate_percent / 100))` 个敌人。
4. 每个敌人生成在玩家周围 1000~1500 距离环内。
5. 波次结束后停止本波刷怪，统一吸取场上经验球，并清空场上敌人。
6. 波次结束经验结算后处理升级与共享奖励/商店页触发。

## 11. MVP 实现范围

1. 读取敌人和波次配置。
2. 生成普通敌人。
3. 支持 `chase_player`。
4. 支持敌人碰撞伤害。
5. 支持受击与死亡。
6. 支持死亡后引用掉落表并掉落经验球。
7. 支持波次时间推进与刷怪节奏。
8. 支持波次结束统一吸取场上经验球并清场。
9. 支持经验达标后触发共享奖励/商店页事件。

暂不实现：

1. 精英怪特殊词缀。
2. Boss 阶段技。
3. 路径寻路。
4. 群体 AI 协同。
5. 敌人技能树。

## 12. 结项判断

本模块可视为完成的条件：

1. Godot 启动后能读取 `enemies.json` 与 `waves.json`。
2. 能按 `duration_seconds` 持续刷出敌人。
3. 敌人能在玩家周围 1000~1500 范围内生成。
4. 敌人能朝玩家移动、造成碰撞伤害并受击死亡。
5. 敌人碰撞玩家后能造成一次伤害、立刻弹开；拉开到重置半径后重新追逐并允许下一次独立碰撞伤害。
