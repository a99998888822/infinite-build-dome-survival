# 外部图片 → Picxel 像素素材

本技能复用项目中已确认的哥布林处理方法：**外部原图 → 保留特征与抠图 → 限色和网格化 → AI 对照检查 → 局部像素修整 → 透明 PNG 与审阅图**。

在本项目中，“使用 Picxel”优先进入此流程；精确技能名为 `$picxel-external-images`。输入、用途、尺寸或样例已在对话／面板明确时直接沿用，不要求重复填写。只说“picxel”时准备并展示项目面板、读取设置，然后结束初始化；不要自动续跑旧任务。明确要求生图重绘或从零设计时，转入适用的美术生成技能；上游 `codex/claude/api` 只是效果图来源标签，Python 不会自动调用模型。

## 工作边界

- 转换输入是用户已经提供的 PNG/JPEG/WebP 等本地图片；已有 `.pxg` 修整沿用原任务。实际制作缺少输入时只询问来源，不要求生图工具、API key 或付费生成服务，不调用图片生成模型。
- AI 负责看图、判断保留特征、设计抠图与修整方案；代码负责像素处理。如实称为“原图像素化与局部修整”，不称为模型重新生成。轮廓、构图或解剖结构缺失时，缩图算法不能自动补全。
- 依用户指定尺寸工作；未指定的高清角色默认 128×128，简单道具可选 64×64。需要探索效果时可先做单张样例，不缩减用户已明确要求的批量范围。只导出实际要求的尺寸（32、64、128），不得将已有小图放大充作新高分辨率结果。
- 本技能的每张图最多 16 色；不使用抖色模拟连续渐变。`.pxg` 使用 A–P 色号、`.` 透明，见 [网格规格](vendor/picxel/SPEC.md)。角色、道具四角透明，最终 alpha 为 0/255。先保留原图姿势、比例、视线和表情，再考虑像素可读性。地块使用 `kind: tile` 并检查重复接缝，不能套用角色抠图规则。
- 已有用户确认的样例时，沿用其色板、尺度和清理强度，保留该文件不变，处理剩余原图。不同表情分别判断，不能复制同一张脸或硬套同一组像素坐标。
- 默认输出审阅素材。只有用户要求接入项目时，才覆盖正式资源、调整图集裁切或处理动画；沿用会话中已有授权，不重复请求确认。

## 1. 准备本地面板与输入

初始化、转换或修整任务先准备并展示面板，无需用户另说“打开面板”。从本文件所在目录解析所有相对路径；下文 `<skill>`、`<task>`、`<work>` 是路径占位符，执行前替换。Python 需要 3.10+ 与 Pillow。附带运行库在 `vendor/picxel`，无需全局安装 Picxel，也无需拉取新代码。

```powershell
python -B <skill>/vendor/picxel/scripts/start_panel.py --port 8771 --no-open
```

读取返回的 `url`、`python`、`pid`、`reused`，用宿主浏览器打开工具展示面板，核对页面或 `/api/health`；仅发链接不代替可用的打开工具。没有宿主打开工具时去掉 `--no-open`，使用系统浏览器。后续使用返回的 Python；缺少 Pillow 由启动器安装到本运行库 `.venv`。Windows 使用可显示原生文件选择框的用户桌面会话，遵循宿主执行权限。

8771 用于避免与全局版 8770 冲突。启动器核验安装根目录、复用健康服务；端口属于其他服务时报告实际错误并选择空闲端口，不关闭其他服务。面板不发起生图或上传文件；单张约 5 秒显现是成品展示，不是内部绘画过程，不为播放延迟交付。

若用户已在面板选择文件、尺寸或输出位置，先运行 `python -B <skill>/vendor/picxel/scripts/picxel.py job show` 读取并沿用，不能用默认 128 覆盖其选择。

项目任务文件位于 `vendor/picxel/.runtime/current-job.json`；全局版是 `~/.picxel/current-job.json`，不自动同步。若本次输入来自全局面板，按 [面板设置与状态](references/workflow.md#面板设置与状态) 迁移选择；不要将旧全局任务当作当前请求。已有对话输入可用项目 `panel.save_job` 填入，保留活动任务和已有产物。

仅编写技能、阅读文档、安装完成素材时，不启动面板或新任务。

创建独立任务目录，通常为 `artifacts/previews/<subject>/<revision>/`：

```text
refs/         原图副本与 <name>.anchor.json
prepared/     可选：同名 PNG，已抠图但仍保留原图尺度
work/         网格、色板、原尺寸 PNG、4 倍预览、报告和成品图
```

一次最多 20 张。同名不同扩展名先在副本中改成唯一名称，保留来源映射。原始文件不被覆盖。说明输入是否已带透明背景；不把棋盘格当成真实 alpha。

## 2. 看原图、标注、抠图

先一起看原图，再只裁剪不确定的脸部、手部、细链等细节。按 [操作参考](references/workflow.md) 为每张图写 anchor，记录保留／简化项；复杂脸必须记录原图视线。**anchor 是 AI 的检查约定，不是程序能理解的语义指令。**

透明原图直接保留 alpha。均匀背景可使用边界连通抠图；复杂背景、桌面或手臂内部空隙，依据实际原图编写局部遮罩，保存 `prepared/<name>.png`。抠图后检查耳尖、帽檐、指缝、细链，避免沿用其他图片的种子点。相关修整规则见 [操作参考](references/workflow.md)。

整批使用已确认的完整色板时，把相同的 16 色 `palette` 写入各 anchor。用户要求先看样例时先交付一张，再沿用选定色板；已有确认样例直接继续。用户已要求整批处理时按授权范围完成，不额外增加画风鉴定或审批环节。保留特征和原图对照仍必须完成。

## 3. 转换一次

```powershell
python -B <skill>/scripts/external_pixel.py build <task>/refs -o <task>/work --sizes 128 --prepared-dir <task>/prepared --background none
```

无独立抠图结果时省略 `--prepared-dir`；纯色底可改用 `--background auto`，技术底色可用 `--background key:#ff00ff`。只在确认底色不属于主体时使用 key 模式。

入口直接处理外部文件，**没有 provider、生图或模型调用选项**。它记录文件哈希、写入独立面板任务并开始计时，按顺序处理图片，生成 `batch-report.json` 和 `review-*.png`。不要在 `build` 之前调用 `job start`，因为创建任务会拒绝覆盖运行中任务。每张高清输入只解码和取色一次，多尺寸共享色板、各自计算网格，不先生成 32 再放大。多个尺寸用空格：`--sizes 128 64`。转换完成仍是底稿，不能仅凭程序通过就宣称视觉合格。

只重做部分原图时使用 `build ... --only hero potion -o <new-work>`，新目录保留旧成果；报告只代表此次子集。已有底稿的小改动直接进入修整，不重跑整批。区域预处理、大图派生小图、地块和图集按需阅读 [高级操作与项目接入](references/advanced.md)。

## 4. 检查并局部修整

打开 `review-*.png`，同时看原尺寸与最近邻放大。检查轮廓、留白、身份特征、实际表情、手指、材质色块、半透明残边和同批一致性。使用 [Picxel 检查清单](vendor/picxel/references/checklist.md)，只修观察到的问题。

- 配饰、轮廓：用 `Grid.load()` 按十六进制颜色查符号，局部改色／线条／像素，保存另一个 `.pxg`。不能假设不同文件的字母代表同一颜色。
- 眼口：阅读 [眼口修整规则](vendor/picxel/references/faces.md)，对照高清原图，使用紧密矩形 patch 和附带 `picxel.py face`。保持视线、眼睑、眉毛、鼻子及嘴形；每种表情单独定位。修眼后不再全图去噪或描边。
- 孤立像素警告可能是瞳孔、指尖或金属闪光，不按警告数量批量删除。不要为消除警告牺牲已确认效果。

先看整批总览，再裁剪不确定细节；`show` 默认只显示摘要，`show --box` 按图上实际坐标编辑，不为局部修改读取整张 128 行网格。合并相关修整后渲染一次，通过的图不重复处理。`select` 后用 `external_pixel.py review <work>` 刷新总览；只有摘要缺少必要信息才读取完整报告。

视觉检查完成后，为每张／每个尺寸登记选用版本（无须修整时选底稿）：

```powershell
python -B <skill>/scripts/external_pixel.py select <task>/work --name hero --size 128 --sheet <task>/work/hero-128-face.pxg --note "已对照原图核对视线、嘴形与轮廓"
```

登记操作校验网格／色板／透明度，保留底稿，更新面板中的最终 PNG 与 face review，不重跑整批转换。具体命令和 Python 编辑例子见 [操作参考](references/workflow.md)。

## 5. 导出与交付

```powershell
python -B <skill>/scripts/external_pixel.py finish <task>/work
```

它核验所有尺寸已被检查、原图哈希未变、最终文件匹配所选网格，然后刷新总览、导出 `work/成品图/` 并结束面板任务。打开最终图片后，用绝对路径展示，简短说明尺寸、色板、表情与实际处理方法。用户审美确认仍由用户决定，`finish` 不是自动审美批准。

必须等待用户补充信息时用项目 `picxel.py job ask --note "实际问题"`；恢复修整用 `job start`，保留原始计时。中断执行 `external_pixel.py stop <task>/work --note "实际原因"`，不能留下运行中的转圈。完成可用审阅稿后执行 `finish` 再交用户审阅；不要用底层 `job done` 绕过复核。批量多表情可做标签对照图；只有用户需要图集／HTML 时执行 `external_pixel.py sheet <work>`，它仅打包已登记版本，不混入底稿。默认不制作动画。
