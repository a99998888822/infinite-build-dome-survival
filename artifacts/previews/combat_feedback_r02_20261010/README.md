改动只控制精灵姿态、颜色、装饰爆点与来源提示。伤害与击退正常逐次执行；反馈位移不改变敌人身体或碰撞器。暴击判定和飘字沿用原逻辑，独立附魔效果与其他武器继续使用原反馈。死亡接管颜色和缩放，受击动画不与尸体淡出竞争。

新装饰使用固定 2 像素网格与约 30 Hz 分帧形状变化，一次接触由一个节点批量绘制多个块面；装饰上限 96 个节点。没有调用图像模型或图片 API。秘仪短音为本地合成，复用现有战斗混音的冷却与声部限制；GIF 不含声音，页面提供单音素材试听。

## 审阅边界

取景使用正式 GameRoot、地表、角色、敌人资源及正式武器运行时。高血量敌人固定位置，关闭自动刷怪和玩家移动，以固定 60 Hz 步长调用真实武器碰撞与伤害逻辑，按 30 FPS 捕获 GPU 画面。下方武器栏是同一画面的真实控件截图，不是另绘的示意图。

这组录像用于比较单次、连击和叠加反馈，不代表完整波次、敌人追逐与危险预警混战测试，也不作为帧率或性能结论。伤害数字仍逐次显示，可据此审阅后续飘字聚合的必要性。GIF 使用每段统一的 256 色调色板；网页逐帧画面为无损 WebP，可更准确观察浅色与暗部。

## 实现与复核

正式版共用 `scripts/effects/combat_feedback_settings.gd`，默认启用；`GameGlobal` 的 `combat_feedback_r02_enabled` 仅用于局部覆盖，审阅夹具用它切换前后版本，结束后清除。新实现位于 `scripts/effects/combat_feedback_r02.gd`、`scripts/effects/combat_impact_r02.gd` 和 `scripts/ui/weapon_pulse_r02.gd`；现有命中入口与武器栏只增加相应调用。`take_damage` 的既有签名与敌人子类覆盖保留。

`before/` 保存本轮编辑前的相关脚本；`baseline.json` 保存其散列。制作工具、正式资源及此前其他工作区改动均保留。`capture.gd`、`launch.gd` 为受控录制入口，`package_review.py` 打包动图和分段图集，`check_browser.cjs` 复核审阅页。正式代码不引用 `artifacts/` 目录。

本目录作为存档保留，后续录制应另建目录。原 GIF 内的“现行版本／R02 审阅”分别表示替换前版本与已采用 R02。`manifest.json` 的脚本散列描述获批时的实现；正式启用后的散列保存在安装记录中。
