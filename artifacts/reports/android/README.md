# Android 界面适配评估（2026-09-25）

需要进行移动端适配。项目已经具备触屏操作基础，但部分界面在手机上会缩得过小，设置页返回逻辑也有需要修正的地方。建议保留当前桌面端效果，通过移动端样式和布局分支适配。

## 验证范围

- 检查 Android 缩放、触屏输入、返回键及主要界面代码。
- 在隔离副本中启用现有移动端代码分支，用 Godot 实际运行主菜单、设置、角色、天赋、战斗、属性、理财商店、附魔和背包界面。
- 预览窗口为 960×432（20:9）。生产 Android 配置为 1280×720 逻辑画布、KEEP 比例，实际内容为 768×432；左右各有 96 像素留黑。截图仅包含内容区。
- 这是桌面模拟移动端布局，不是安卓设备截图。未构建 APK，未验证安卓输入法、系统手势、刘海屏及真实手指操作。
- 未修改生产代码或美术素材。控件测量见 `measurements.json`；原始运行日志已清理。

当前预览缩放为 0.6，因此字号 11 对应约 6.6 个预览像素、16×16 的详情图标对应约 9.6×9.6 个预览像素。这些数字不是 Android dp，也不直接代表所有手机上的物理尺寸。移动端点击区域可按约 44–48dp 的目标起步，再用真机手指操作校准。

## 已有支持，可继续沿用

- 移动端浮动摇杆，包含手指标识跟踪、UI 区域避让和失焦清理。
- 触屏拖动滚动容器。
- 附魔有选择、装备、卸下和左右调序按钮，已有不依赖拖拽的操作路径。
- 金额输入配置数字键盘，有四分之一、二分之一、全部等快捷金额按钮。
- 战斗内设置已经针对移动端禁用分辨率 / 全屏操作。
- 多数游戏状态已有安卓返回键分支，需要补齐弹窗层级处理。

## 屏幕比例选择

当前保持 16:9，在 20:9 手机屏幕上会有合计约 20% 宽度的左右黑边。初次测试 APK 可以保留这种布局。正式移动版本可利用额外宽度扩展背景、安排操作区，但应同时检查摄像机范围和所有弹窗布局，不宜只切换一个 stretch 参数。

## 建议实施顺序

1. 补齐点击查看详情和设置页返回逻辑，建立移动端字号与触控尺寸配置。
2. 调整理财 / 商店 / 附魔布局，再检查属性栏、背包、角色和天赋页面。
3. 构建测试 APK，在不同屏幕比例的手机上验证安全区、键盘、多指操作和前后台恢复。
