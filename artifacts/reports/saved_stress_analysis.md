# 电浆炮压力测试：初步性能分析

读取用户保存的同名方案，通过 RecordingSession 创建正式战斗，玩家静止且测试时无敌。CPU 对照每组模拟 900 帧，固定 60Hz；GPU 复测为 900 个实际画面帧，关闭垂直同步、上限 120 FPS。用户原测试仍在运行，因此结果包含机器竞争，不能当作独占机器的帧率基准。

## 配置

第10波；侵蚀200；怪物数量增幅200%；攻速100；投射物数量3；攻击距离100；伤害范围200。电浆炮、木弓、钱袋均满级，均有多投与分裂，分别附加雷、火、水。侵蚀和怪物增幅共同扩大刷怪量；本次观测敌人峰值48。

## 结果

第二轮无头 CPU 对照，单位毫秒：

| 配置 | 平均帧间隔 | P95 |
| --- | ---: | ---: |
| 完整 | 8.26 | 16.60 |
| 去掉雷 | 8.18 | 14.09 |
| 去掉火 | 8.57 | 18.87 |
| 去掉水 | 8.82 | 19.12 |
| 去掉分裂 | 6.88 | 11.11 |
| 去掉多投 | 8.27 | 15.27 |

完整配置后台图形复测：平均17.56ms，P95 36.79ms，最大67.91ms；900帧中354帧超过16.67ms。私有桌面验证完成，foreground_samples=0。

每30帧统计仍存活的新节点，完整配置观察到416个闪电效果，去掉分裂后233个。此计数会漏掉两次采样间出生并销毁的节点，不是完整生成总数。去掉火或水后闪电数量反而增加，说明击杀、控制与元素反应会改变后续负载，单次删附魔不能理解为独立函数耗时。

## 判断

分裂带来的命中与附魔扩散是最稳定的放大源，两轮对照都降低P95约三分之一；雷链路值得优先进一步分析。代码中电浆每目标最多触发5次附魔，分裂子弹也可触发，雷链又包含目标查询、命中、元素反应、闪电几何和粒子。现有每帧8条路径限额限制的是部分几何构建，不能限制整条逻辑链成本。

外部监测发现单线程接近满核，GPU整体利用率不高，支持CPU主线程/提交侧压力的方向；不能据此排除渲染成本。图形运行存在数百次 draw call，实际帧间隔明显高于无头测试，应继续拆分几何构建、渲染提交和逻辑耗时。

未获得函数级 profiler 数据，不能把以上判断当作具体函数耗时排名。测试退出有4个ObjectDB实例、2个资源仍在使用的提示；尚未确认来源，不能据此判断实战持续泄漏。外部采样的内存增长也需要重复同一波次观察回落后再判断。

本次仅增加诊断文件，未调整游戏平衡或性能实现。
